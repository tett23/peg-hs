# ADR 0098: PR #86 の言語サーバーの応答時間を CI で判定する

ステータス: 採択

## 文脈

[ADR 0094](0094-fixes-of-recovered-labels-duplicate-alternatives-and-incremental-quotes.md) は、言語サーバーの編集応答時間を修正の前後で測り、結果を PR に記録すると定めた。
PR #86 では、手元の負荷が高く、変更後の同じバイナリでも Golem の編集と semantic tokens の処理に 13.5 ms から 30.3 ms かかった。
低負荷の手元のマシンを確保するまで保留していた判定を、GitHub Actions のランナーで行う。

## 調査した事項

既存の `peg-bench` は `PEG_BENCH_LSP_GRAMMAR` で入力を切り替えられる。
文書の先頭、中ほど、末尾について、範囲編集の診断までと、同じ編集の後に semantic tokens を返すまでを個別に測る。
[以前の計測記録](../benchmarks/2026-11-06-lsp-incremental.md) には、Memo.hpeg と比較した Golem.hpeg のパスとコミットがある。

## 実装すること

PR #86 のベースとヘッドを同じ GitHub Actions ランナーで順にビルドし、同じ GHC、最適化設定、RTS オプション（`-A64m`）で計測する。
入力には同じ Memo.hpeg と、以前の計測に使った Golem のコミット `89ae4b41` の `modules/golem-parser/grammar/Golem.hpeg` を使う。
各版について、二つの文法、三つの編集位置、二つの操作を組み合わせた 12 件の Criterion の平均時間を取得する。
編集と semantic tokens を続けて測るケースには診断も含まれる。

両版のコミット、入力の版、ランナーとツールチェーンの情報、12 件の変更前後の値を CI のジョブサマリーに出し、PR に結果を記録する。
16 ms の合否はマージするヘッドで判定し、変更前の値は比較に使う。

## 実装しないこと

この判断は PR #86 のマージ条件に限る。
他の PR に性能検査を追加することや、過去の計測記録を更新することは対象外とする。

## 不変条件

1. ベースとヘッドの各 12 件がそろい、すべての平均時間が有限の正の値で、ヘッドの各値が 0.016 秒以下のときに限って判定が成功する。比較には表示用に丸める前の秒数を使う。

| 入力（記載した項目以外は条件を満たす） | 判定 |
| --- | --- |
| ヘッドの最大値が 0.016 秒 | 成功 |
| ヘッドの一件が 0.016001 秒 | 失敗 |
| ベースにだけ 0.016 秒を超える値がある | 成功 |
| 一件が欠落、重複、計測失敗、または数値が無効 | 失敗 |

## テスト設計

不変条件 1 の番号を付けた判定テストに、表の境界例を与える。
PR #86 の実際のヘッドで CI を実行し、二つの版の結果とジョブの終了状態を照合する。

## トレードオフ

GitHub が割り当てるランナーの性能にはばらつきがある。
同じランナーで前後を測ると差を比較できるが、16 ms を超えた理由がコードにあるかどうかは、この判定だけでは決まらない。
