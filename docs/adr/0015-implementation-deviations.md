# ADR 0015: 初回の実装で生じた ADR とのずれの記録

ステータス: 採択→自己記述の文法の識別子の制限は ADR 0020

## 文脈

ADR 0001〜0014 は、ADR 0013 の順序に従って一度に実装した。
その過程で、ADR に書かれていない追加、ADR の文言からの変更、テスト設計の置き換えが生じた。
コミット済みの ADR は書き換えられないため、本 ADR にまとめて記録する。

記録の対象は二種類ある。
ADR の意図を保ったまま実装の都合で加えたものと、ADR の文言とは異なる形で実装したものである。
後者のうち、元の ADR の記述が誤っていたものは、訂正する ADR を別に起こした（タブの部分消費は ADR 0018）。

## ずれと修正

### 実装の順序（ADR 0013）

- **ずれ**：ADR 0012 の拡張（意味述語、引数付き規則、解析環境、桁の参照）を、段階 10 ではなく、記法と生成器を実装する段階 3 と 4 で実装した。記法の解析と生成の処理が一つにまとまっており、分けて実装すると二度手間になったためである
- **影響**：ADR 0011 は、拡張を使わない v1 の記法での測定を先に取ることを求めていた。拡張が先に存在したため、v1 の記法だけで書いた文法を別に用意して測った（`conformance/commonmark/v1/`）。この経緯は初回のスナップショット（`docs/conformance/commonmark/2026-10-11-v1-notation.md`）に記した

### 生成モジュールの Prelude（ADR 0014）

- **ずれ**：ADR 0014 は、生成コードが Prelude を `PegPrelude` として qualified に import すると定めた。しかし GHC は、Prelude を明示的に import したモジュールでは暗黙の Prelude の import を行わない。このままでは利用者の verbatim ブロックとアクションから Prelude の名前が見えなくなる
- **修正**：verbatim ブロックが Prelude を import していないとき、生成器は `import Prelude` も出力する。補った import が使われていないと警告になるため、入口の定義は `fst` を `Prelude.fst` として参照する。verbatim ブロックが Prelude を import しているときは何も補わず、GHC の通常の規則と同じ結果になる

### 予約名（ADR 0014）

- **追加**：生成器が導入する型 `Peg'Store` と衝突しないよう、予約する接頭辞を `peg'` に加えて `Peg'` にも広げた。verbatim ブロックの字句検査も両方を対象にする
- **追加**：生成コードの型変数を `s` ではなく `peg's` とした。規則の型注釈に利用者が型変数 `s` を書いた場合の衝突を避けるためである

### 生成コードの警告の検査（ADR 0014）

- **ずれ**：ADR 0014 のテスト設計は、生成コードを `-Wall -Werror` でコンパイルできることを求めた。Hackage は `.cabal` ファイルの `ghc-options` に `-Werror` を書いたパッケージを受け付けない（ADR 0009）
- **修正**：`-Werror` は `cabal.project` で peg-codegen に対してだけ指定した。リポジトリ内のビルドと CI では検査が働き、公開物には含まれない

### 生成コードを GHC で型検査するテスト（ADR 0014）

- **追加**：アクションの型の誤りが `.peg` の行と桁で報告されることのテストは、パッケージのデータベースを使わず、`-i../peg-runtime/src` で peg-runtime のソースを直接読ませて GHC を起動する。peg-runtime の依存はすべて GHC 付属のパッケージなので、cabal を介さずに型検査できる

### 生成の決定性のテスト（ADR 0014）

- **ずれ**：ADR 0014 は「同じ文法を異なる作業ディレクトリから同じ相対パスで生成し、出力が一致すること」を求めた。この形のテストは書いていない
- **代替**：生成は純関数であり（ADR 0002）、作業ディレクトリを参照しない。リポジトリにコミットした生成物と、テストの中でその場で生成した出力がバイト単位で一致することを、すべての生成物について検査している

### ベンチマークの対象（ADR 0007）

- **ずれ**：ADR 0007 は「自己記述の `.peg` 文法の解析」を計測対象に挙げた。自己記述のパーサーは既定の解析器になっていないため、手書きのパーサーで JSON の文法を解析する時間を計測している
- **今後**：自己記述のパーサーに切り替えた時点で、計測対象をそちらに替える

### v1 の測定での原因の割り当て（ADR 0011）

- **ずれ**：ADR 0011 は、失敗のすべてに原因の分類を割り当てることを求めた。v1 の記法での測定では失敗が 152 件あり、例ごとに調べず、規則によって割り当てた（例が参照定義を含めば前方参照、引用かリスト項目を含めば字下げの状態、など）
- **扱い**：規則はスナップショットに明記した。拡張を使う文法の失敗（3 件）は例ごとに調べ、`conformance/commonmark/failures.txt` に理由を記した

### 空の期待集合の表示（ADR 0005）

- **追加**：期待集合が空の失敗（意味述語や否定先読みだけで失敗した場合）は `行:桁: parse error` と表示する。ADR 0005 は要素が一つ以上の場合の書式だけを定めていた

### 自己記述のパーサー（仕様書の設計原則）

- **追加**：自己記述のパーサーを生成するため、peg-grammar が peg-runtime に依存するようになった。peg-runtime が他のパッケージに依存しないことは変わらない
- **現状**：自己記述のパーサーは、リポジトリ内のすべての文法について手書きのパーサーと同一の結果を返す。既定の解析器への切り替えは、すべての検査に合格した後に行う。CommonMark の全件適合（ADR 0018）もその検査に含める
- **制限**：自己記述の文法は、識別子の文字を ASCII に限っている。手書きのパーサーは Unicode の英字も受け付ける。切り替えの前に、この差をなくすか、記法の側で ASCII に限ることを決める

## 実装すること

本 ADR は記録であり、新たに実装するものはない。
仕様書のモジュール構成（peg-grammar から peg-runtime への依存）と、syntax.md の予約名と Prelude の扱いは、本 ADR の採択と同じコミットで更新する。

## 実装しないこと

- 上記のずれを元の ADR の文言に合わせて戻すことはしない。どれも元の ADR の意図を保つための変更である

## テスト設計

- 記録した追加と修正には、それぞれ既存のテストがある（`import Prelude ()` を含む文法の生成と、Prelude の名前を使わない文法の `-Werror` でのコンパイル、予約名の検査、生成物の一致の検査）。本 ADR で新たに加えるテストはない

## トレードオフ

- 補った `import Prelude` を使わせるために入口の定義の形を変えたことは、生成コードの読みやすさを少し損なう。警告を抑えるプラグマを出力する案もあったが、利用者の書いた断片の警告まで抑えてしまうため採らなかった
