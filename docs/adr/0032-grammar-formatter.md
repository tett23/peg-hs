# ADR 0032: 文法ファイルの整形（peg-hs fmt）

ステータス: 採択

## 文脈

リポジトリの `.peg` ファイルは、選択肢の `/` を `<-` の下に揃える、規則の間に空行を一つ置く、といった書き方を手で揃えている。
文法が増え、Golem の文法も加わると、手で揃え続けるのは難しい。
書き方の揺れは差分を読みにくくし、レビューで書き方の指摘を繰り返させる。

整形の流儀を選べるようにすると、流儀ごとに書き方が分かれ、整形器を使う理由が薄れる。
gofmt のように、流儀を一つに決めて選択肢を設けない。

整形にはロスレスな構文木（[ADR 0019](0019-lossless-syntax-tree.md)）が要る。
コメントを失わずに、空白だけを書き換えるためである。
記法のパーサーは自己記述の文法から生成している（[ADR 0027](0027-switch-to-self-hosted-parser.md)）ので、同じ文法から構文木を返すパーサーを生成できる。

## 実装すること

### コマンド

- `peg-hs fmt [FILE...]` は、各ファイルを整形して上書きする
- `peg-hs fmt --check [FILE...]` は、ファイルを書き換えず、整形の結果が元と異なるファイルがあれば、その名前を表示して失敗する。CI で使う
- ファイルを指定しない場合は、現在のディレクトリから再帰的にたどった、拡張子が `.peg` のすべてのファイルを対象にする。名前が `.` で始まるディレクトリと `dist-newstyle` はたどらない。対象のファイルはパスの順に処理する
- 整形の流儀を変える設定、オプション、文法中の指示は設けない。整形を部分的に止める指示も設けない
- 構文の誤りのあるファイルは整形せず、誤りを報告して失敗する。ほかのファイルの整形は続ける

### 構文木

- 自己記述の文法（`grammar/Peg.peg`）に `%syntax`、`%token`、`%trivia` を加えた変種から、構文木を返すパーサーを生成する。変種は再生成のスクリプトが自己記述の文法から導く（[ADR 0017](0017-nomemo-implementation.md) の JSON の変種と同じ方法）
- 既定の記法のパーサー（`parseGrammar`）は変種を使わない。構文木の入口は型付きの値の入口より遅い（[ADR 0019](0019-lossless-syntax-tree.md) の計測で約 65%）ためである

### 流儀

空白と改行だけを書き換える。
字句の並び、コメントの文言、Haskell の断片（verbatim ブロック、型注釈、アクション、意味述語、引数）の中身は変えない。
要素の順序（ディレクティブ、規則、選択肢）も変えない。

- **ファイル**：改行は LF とする。行末の空白を除く。ファイルの終わりに改行を一つ置き、末尾の空行を除く。連続する空行は一つにまとめる
- **ディレクティブ**：`%` の後に名前、空白一つ、引数とする。引数の中の空白は変えない
- **verbatim ブロック**：`%{` と `}%` をそれぞれ単独の行に置く。中身は変えない
- **規則**：型注釈の行の直後に定義を置き、間に空行を置かない。規則と規則の間には空行を一つ置く。コメントは直後の規則に付くものとして、規則との間に空行を置かない
- **選択肢**：一つめの選択肢を `<-` と同じ行に置き、二つめ以降は行を改め、`/` を `<-` の `<` と同じ桁に揃える
- **式**：逐次の要素の間は空白一つとする。接頭辞（`&`、`!`、`$`）と接尾辞（`*`、`+`、`?`）は式に付け、束縛 `x:` も式に付ける。括弧の内側に空白を置かない。グループの選択肢の `/` の前後は空白一つとする。失敗ラベルは式の後に空白一つを置いて `^label` とする
- **アクション**：選択肢の要素の後に空白一つを置いて `{` を書く。一行のアクションは `{ code }` とし、中身の前後の空白を一つにする。複数行のアクションは中身を変えない
- **コメント**：行のコメントは前後の要素の字下げに合わせる。行末のコメントは、直前の要素との間を空白一つにする
- **行の長さ**：長い行を折り返さない。折り返しの位置を選ぶ規則は、流儀の議論を呼びやすく、決定的な結果を得にくいため

### 保証

- **意味の保存**：整形の前後で、文法の AST（位置を除く）が一致する。整形器は整形の結果を解析し直して比べ、一致しなければ書き込まずに内部の誤りとして失敗する
- **冪等性**：整形した結果をもう一度整形しても変わらない
- **ロスレス性**：コメントと、Haskell の断片の中身が、すべて残る

## 実装しないこと

- 流儀の設定、整形を止める指示、部分的な整形（範囲の指定）
- 長い行の折り返しと、選択肢を一行にまとめること（作者が書いた改行の位置は、選択肢の区切り以外では保つ）
- Haskell の断片の整形（ormolu などへの委譲を含む）
- ファイルを指定しない場合の `.gitignore` の解釈。たどらないディレクトリは上に挙げたものに限る
- エディタとの連携（LSP の整形の要求への応答）。LSP を扱う ADR で検討する

## テスト設計

- **golden**：流儀の各項目を含む入力と、整形の結果の golden ファイル
- **冪等性と意味の保存**：リポジトリのすべての文法について、整形の結果を整形しても変わらず、整形の前後で AST（位置を除く）が一致すること
- **無作為な空白**：リポジトリの文法の字句の間の空白と改行を無作為に増減させた入力（意味が変わらない範囲）を整形すると、元の文法を整形した結果と一致すること（プロパティテスト）
- **コメント**：あらゆる位置のコメントが残ること
- **リポジトリの整形**：リポジトリのすべての `.peg` ファイルを整形した状態でコミットし、CI で `peg-hs fmt --check` を実行する
- **`--check`**：整形済みのファイルで成功し、未整形のファイルで失敗してその名前を表示すること
- **ファイルの探索**：ファイルを指定しない場合に、入れ子のディレクトリの `.peg` ファイルをすべて対象にし、`.` で始まるディレクトリと `dist-newstyle` の中のファイルを対象にしないこと。`fmt` と `fmt --check` の両方で確かめる

## 実装の段階

[ADR 0031](0031-rule-templates.md) の後に行う。
雛形（[ADR 0031](0031-rule-templates.md)）の記法も整形の対象に含めるためである。

## トレードオフ

- 流儀を一つに固定するので、利用者は流儀を選べない。代わりに、どの文法も同じ書き方になり、書き方の議論がなくなる
- 長い行を折り返さないので、長い選択肢は長いまま残る。折り返しは作者に任せ、作者の改行は保つ
- 構文木の変種を自己記述の文法から導くので、記法を変えるたびに変種も再生成する必要がある。再生成のスクリプトと生成物の一致の検査がこれを保証する
