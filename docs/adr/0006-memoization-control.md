# ADR 0006: v1 は全規則メモ化とし、%nomemo は予約のみ

ステータス: 採択

## 文脈

パックラットの線形時間保証は全規則のメモ化から来るが、メモ表のメモリは最悪で入力長と規則数の積に比例する。
最初の利用者である Golem の入力は書籍一冊分の原稿であり、この量は無視できない可能性がある。
一方、実務の PEG 処理系では「メモ化が効く規則は少数」という経験則も知られており、規則単位の opt-out には実利の見込みがある。

ただし、いま opt-out を実装する根拠になる性能データがない。
推測でメモリ最適化を作り込むかわりに、記法に席だけ確保して実測を待つ（[ADR 0005](0005-error-reporting.md) の `^label` と同じパターン）。
なお、左再帰に関与する規則は成長ループがメモ表の上で動くため（[ADR 0001](0001-bounded-left-recursion.md)）、メモ化を外す対象になりえない。

## 実装すること

- v1 の生成コードは全規則をメモ化し、非左再帰の文法に対して入力長に線形の評価回数を保証する
- `%nomemo Name` ディレクティブを記法に予約する。peg-grammar は受理して文法 AST に保持し、peg-codegen は遭遇したら未実装のエラーで停止する
- 将来 `%nomemo` を実装する際の制約を先に固定する：左再帰に関与する規則への指定は静的検査でエラーとし、メモ化の有無は解析結果を変えてはならない

## 実装しないこと

- 既定を非メモ化とする opt-in 方式（`%memo`）は将来も採らない。線形時間保証が既定で消え、パックラットとしての性質を失うためである
- メモ表のサイズ上限や LRU 破棄などの動的制御は検討しない。決定性の観点から、メモリ都合で解析挙動が変わる仕組みは持たない（メモ化の有無が結果を変えない設計なら破棄は無害だが、性能の再現性が失われる）

## テスト設計

- **予約の検証**：`%nomemo` を含む文法が peg-grammar を通過し、peg-codegen が未実装エラーで停止すること
- **線形性の検証**：評価回数を数えるテスト用フック（[ADR 0003](0003-typed-semantic-actions.md)）で、非左再帰の文法において規則本体の評価が位置×規則あたり高々一回であること
- **メモリの実測**：性能ベンチマーク（後続 ADR）の項目としてメモ表の常駐量を計測し、`%nomemo` 実装の判断材料にする

## トレードオフ

- v1 のメモリ消費は最悪で入力長×規則数に比例し、利用者に制御手段がない。書籍規模の入力で問題化した場合は `%nomemo` の実装で応える
- 「実測してから実装」の方針は、Golem 側の開発が peg-hs の性能改善を待つ場面を作りうる。ベンチマークを開発順序の早い段階に置くことで待ち時間を短くする
