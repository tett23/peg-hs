# ADR 0023: TOML 1.1.0 の文法で構文の後の検査と回復を検証する

ステータス: 採択→回復の規則と複数行の文字列の読み方は ADR 0025

## 文脈

これまでの適合性テストは、二つの性質を検査していない。

一つは、構文の後の検査との分担である。
JSON（ADR 0010）は、構文が正しければ値が決まる。
CommonMark（ADR 0011）は、どの入力も受理する。
TOML は違う。
キーの重複、表の再定義、インラインの表への追加、静的な配列への `[[ ]]` での追加は、どれも文法の上では正しい。
これらは文書全体を見て初めて誤りとわかる。
PEG で書いた文法と、その後に走らせる検査とで、どちらが何を拒否するかを決めて記録する必要がある。

もう一つは、エラーからの回復（ADR 0021）である。
回復は、ラベルを付けた JSON の文法の派生版でしか検査していない。
TOML は行が単位の言語であり、壊れた行を ERROR の節にして次の行から解析を再開する、という回復の典型に当てはまる。
実在の言語で、公開のテストスイートの拒否すべき入力を使って、回復の全域性と回復後の木の形を確かめられる。

Golem にとっても意味がある。
Golem は設定を `manifest.toml` と `style.toml` に置く。
LSP で設定ファイルの誤りを報告するには、回復する TOML のパーサーが要る。
本 ADR の文法は、その下敷きになりうる。
ただし、Golem が本 ADR の文法を使うかどうかは Golem の側の ADR で決める。

テストデータには toml-test を使う。
v2.2.0（2026-04-30、MIT）は、TOML の版ごとに対象のファイルの一覧を持つ。
TOML 1.1.0 の一覧は、受理すべき入力（`valid/`）214 件と、拒否すべき入力（`invalid/`）467 件からなる。
受理すべき入力には、期待する値が型の付いた JSON として添えてある（`{"type": "integer", "value": "1"}` の形）。

版は TOML 1.1.0 とする。
1.1.0 は 2025-12-24 に公開された最新の版である。
1.0.0 からの差は、インラインの表の中の改行と末尾のカンマ、`\xHH` と `\e` のエスケープ、時刻の秒の省略などである。
新しく書く設定ファイルの文法として、古い版を選ぶ理由はない。

## 前提

- ロスレスな構文木（ADR 0019）とエラーからの回復（ADR 0021）が実装済みであること

## 実装すること

### 配置とテストデータ

- `conformance/toml/` に文法と生成物を置き、`peg-conformance` に入れる
- toml-test v2.2.0 の `tests/` から、`files-toml-1.1.0` に載っているファイルと、受理すべき入力に対応する `.json` を `conformance/data/toml-test/` に取り込む。取り込んだタグ、コミットのハッシュ、LICENSE を同じディレクトリに置く
- 入力はバイト列として読み、UTF-8 として厳格に復号する。復号の失敗は拒否として数える（ADR 0010 と同じ）

### 文法

- TOML 1.1.0 の ABNF（toml.abnf）を写した文法を書く。文法は `%syntax` を付けて書き、型付きの値と構文木の両方の入口を生成する
- 字句の範囲の検査は文法で行う。月が 01〜12、日が 01〜31、時が 00〜23、分が 00〜59、秒が 00〜60 であることや、数の `_` の位置、先頭の 0 の禁止、文字列の中の制御文字の禁止は、文法で拒否する
- 文法の値は「行の列」とする。各行は、キーと値の組、表の見出し（`[a.b]`）、配列の表の見出し（`[[a.b]]`）、空行とコメントのいずれかである。キーはドットで区切った部分の列として、引用の有無を問わず復号した文字列で保持する

### 構文の後の検査

文法の値（行の列）から文書の値（入れ子の表）を組み立てる関数を、`peg-conformance` に置く。
組み立ての中で、次の誤りを検出して拒否する。

- キーの重複（同じ表の中の同じキー、ドット付きのキーで暗黙に作った表との衝突を含む）
- 表の再定義（同じ見出しの二度目の出現、ドット付きのキーで定義した表の見出しによる再定義）
- インラインの表と、静的な配列（`[ ]` の値）への、後からの追加
- 暦の上で存在しない日付（`2021-02-30` など）。月ごとの日数とうるう年の判定は文法では書かない
- 64 ビットの符号付き整数の範囲を超える整数

日付と整数の範囲の検査を文法から外すのは、規則が算術を要し、文法で書くと読めなくなるためである。
組み立ての誤りは、原因になった行の範囲（`_span`）を持つ。

### 判定と分担の記録

- 受理すべき入力は、文法と組み立ての両方を通り、組み立てた文書の値が期待する JSON と一致すること。比較は toml-test の比較の規則に従う。整数は値で比べ、浮動小数点数は値で比べて `nan` どうしを等しいとみなし、日時は構成要素ごとに比べる（`T` と空白の区切り、`Z` の大文字と小文字、秒の省略の違いを吸収する）
- 拒否すべき入力は、復号、文法、組み立てのいずれかで拒否されること
- 拒否すべき入力のそれぞれについて、どの段階で拒否したかをファイルに記録してコミットする。段階が変わったらテストを失敗させる。文法の変更で拒否が組み立てに漏れた場合（またはその逆）を検出するためである

### 回復

- 行の単位でラベルを付ける。キーと値の組、表の見出し、配列の表の見出しの各規則で、行の始まりを確定した後の要素にラベルを付ける（ADR 0021 の、正しい入力を拒否しない位置の原則に従う）
- 回復の規則は、次の改行（文字列の中の改行ではなく、行の終わりの改行）までを読み飛ばす。複数行の文字列と、複数行のインラインの表（1.1.0 の機能）の中で壊れた場合は、その値の閉じまでを読み飛ばす規則を別に置く
- 回復の入口（`parseRecover`、`parseSyntaxRecover`）は、組み立ての検査を行わない。組み立ての誤りは構文エラーではないため、別の関数で文書の値を組み立てるときに報告する

## 実装しないこと

- TOML の文書の生成（直列化）と、toml-test の encoder 側のテスト
- TOML 1.0.0 の一覧による検証。1.0.0 と 1.1.0 とで受理と拒否が逆になる入力があり、版の切り替えは本 ADR の目的ではない
- 浮動小数点数の字句から値への変換の独自実装。字句の検査を文法で済ませ、`_` を取り除いてから base の `read` で `Double` にする。`inf` と `nan` は文法の値の段階で区別する
- 組み立ての誤りの回復。組み立ての誤りは最初の一件で止める
- Golem の設定ファイルのスキーマの検査

## テスト設計

- **受理**：受理すべき入力 214 件のすべてで、文書の値が期待する JSON と一致すること
- **拒否**：拒否すべき入力 467 件のすべてを拒否し、拒否した段階が記録と一致すること
- **回復の全域性とロスレス性**：受理すべき入力と拒否すべき入力の全件で、`parseSyntaxRecover` が終了し、構文木のテキストが入力と一致すること
- **回復の局所性**：受理すべき入力の各行を一つずつ壊した入力（行の中の `=` の削除、値の削除、見出しの `]` の削除）で、ERROR の節が壊した行の範囲に収まり、それ以外の行がそれぞれ本来の種類の節として残ること（プロパティテスト）
- **回復の報告**：拒否すべき入力のうち文法で拒否するものについて、構文エラーの件数が 1 以上であり、最初の構文エラーの範囲が、通常の入口の最遠位置の失敗（ADR 0005）を含む行にあること
- **決定性**：生成物の再生成がコミット済みのものとバイト単位で一致すること

## 完了条件

- 上記のテスト設計のすべてが通ること
- 拒否の段階の記録の集計（復号、文法、組み立ての各件数）を `docs/conformance/toml/` にスナップショットとして置くこと

## 実装の段階

ADR 0021 の実装の後に行う。
ADR 0022 とは独立であり、どちらを先に行ってもよい。
自己記述のパーサーへの切り替え（ADR 0015）の条件である「すべての検査」に、本 ADR の検査も含める。

## トレードオフ

- 構文の後の検査を `peg-conformance` に手で書くため、検査の正しさは peg-hs の検証の対象ではなく、テストの側の実装の正しさに依存する。本 ADR が検証するのは、文法と組み立ての分担が記録どおりであることと、文法が担う部分の正しさである
- 日付の暦の検査を組み立てに回すため、`2021-02-30` のような値は通常の入口でも回復の入口でも構文エラーにならない。LSP で報告するには、組み立ての誤りの位置を使う。組み立ての誤りは最初の一件で止まるため、文書に複数あっても報告は一件になる
- 回復の規則が行を単位とするため、一行に複数の誤りがあっても報告は一件になる。設定ファイルの行は短く、実用上の不足は小さいと見込む
