# ADR 0084: 記法の解説の英語版を置く

ステータス: 採択

## 文脈

`.hpeg` 記法の利用者向けの解説は、`docs/syntax.md` にある。
日本語だけで書かれていて、英語の README は `docs/syntax.md` を「in Japanese」と断ってリンクしている。
README と CONTRIBUTING は英語版と日本語版があるが、記法の解説はない。
英語の読者が記法を学ぶには、README の短い説明か、日本語の ADR を読むしかない。

作業者の指示で、記法の解説の英語版を作る。

英語版は、日本語版と同じ内容を保たなければならない。
`docs/syntax.md` は、記法に関わる ADR を採択するたびに、同じコミットで更新している（CONTRIBUTING）。
英語版が遅れると、英語の読者は古い記法を読むことになる。

## 実装すること

### ファイル

- 英語版を `docs/syntax.en.md` に置く。
- 日本語版は `docs/syntax.md` のまま変えない。

README は `README.md` を英語、`README.ja.md` を日本語としている。
記法の解説を同じ形にそろえるなら、`docs/syntax.md` を英語にして、日本語版を `docs/syntax.ja.md` に移すことになる。
しかし、コミットした 13 の ADR が `docs/syntax.md` にリンクしていて、ADR は書きかえられない。
名前を移すと、それらのリンクが英語版を指すようになる。
ADR は日本語で書かれ、日本語版の節を指して書かれているので、日本語版の名前を残す。

### 内容

- 英語版は、日本語版の翻訳とする。節の構成、例、誤りの表、冒頭の「反映している ADR」の一覧を同じにする。
- 誤りの文言、コード、出力は、日本語版と同じものを使う。peg-hs の誤りの文言は、もともと英語である。
- コードブロックの中のコメント（`#` と `--` から行末まで）は英語に訳す。
- 記法の形を示すための日本語の語（`Name :: 型`、`Name <- 選択肢 / 選択肢 / ...`）は、英語の語に置き換える。
- Unicode の識別子の例（`数式`、`左`、`右`、`数`）は、そのまま残す。識別子に日本語を使えることを示す例だからである。
- 各ファイルの冒頭に、もう一方の言語の版へのリンクを置く。

### 同期の規則

- 記法に関わる ADR を採択したときは、同じコミットで `docs/syntax.md` と `docs/syntax.en.md` の両方を更新し、両方の「反映している ADR」の一覧を更新する。
- この規則を CONTRIBUTING（英語と日本語）と、リポジトリの `CLAUDE.md` に書く。

### ほかの文書

- `README.md` の二か所のリンクを `docs/syntax.en.md` に向け、「in Japanese」の断りを外す。
- `README.ja.md` のリンクは `docs/syntax.md` のまま変えない。
- `docs/specifications.md` の記法の項に、英語版へのリンクを足す。
- CONTRIBUTING の「記法の解説は日本語で書く」の項を、日本語版と英語版の両方を置く、と書きかえる。`CLAUDE.md` の言語の項も同じく書きかえる。

## 実装しないこと

- ADR と仕様書の英語版。ADR は変えられない文書であり、日本語で書く方針（CONTRIBUTING）を変えない。
- `docs/syntax.md` の名前の変更。上の「ファイル」の理由による。
- 翻訳の自動化と、訳の正しさの自動検査。訳の内容は人間がレビューする。

## テスト設計

先に書いて失敗させてから、英語版を書く。

- `packages/peg-grammar/test/Main.hs` の、文書の完全な文法のテスト（[ADR 0046](0046-docs-cli-and-ci-before-v0-1-0.md)）
  - 対象に `docs/syntax.en.md` を足す。英語版の `%module` で始まるコードブロックが、すべて解析と検査を通る。ファイルがない間は落ちる。
- 同じファイルに、二つの版の対応のテストを足す。英語版がない間は落ちる。
  - 二つの版のコードブロックの数が等しい。
  - `%module` で始まるコードブロックを順に並べると、各行の最初の `#` から行末を除いて行末の空白を落としたものが、二つの版で等しい。コメントだけが訳され、文法そのものは同じであることを確かめる。
  - 冒頭の「反映している ADR」の一覧から取り出した ADR の番号の集合が、二つの版で等しい。
- テストは、日本語版を変えて英語版を変えないと落ちることを、一度確かめる（一覧に ADR を一つ足す、`%module` のコードブロックの規則を一つ変える）。壊した変更はコミットしない。

## トレードオフ

- 記法の ADR を採択するたびに、二つの文書を更新する手間が増える。上のテストが、コードと ADR の一覧の食い違いを見つける。地の文の食い違いは見つけられないので、レビューで確かめる。
- 英語版の名前は、README の形（英語が拡張子なし）とそろわない。ADR のリンクを保つために受け入れる。
