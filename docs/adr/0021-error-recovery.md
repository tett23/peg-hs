# ADR 0021: ラベル付きの失敗による構文エラーからの回復

ステータス: 採択

## 文脈

仕様書は、解析に失敗したら失敗を報告して停止し、部分的な構文木を返すモードは作らないと定めている。
[ADR 0005](0005-error-reporting.md) は失敗のラベル `^label` を記法に予約したが、その意味論は実装経験を得てから決めるとした。
[ADR 0019](0019-lossless-syntax-tree.md) は構文木に誤りの種類（`ERROR`）の席だけを予約し、エラー回復を後続の ADR に委ねた。

Golem の LSP の実装で、構文エラーを含む原稿からも構文木を得る必要が生まれた。
Golem の側の要件は、Golem の ADR に次のように書かれている。

- パーサーの型は `parse :: FileId -> Text -> (Node, [Diagnostic])` であり、読み込みの検査を通過した任意のテキストに対して必ず終了し、木を返す（golem-parser [ADR 0002](0002-standalone-code-generator.md) の全域性）
- 木のテキストは、エラーを含む入力でも入力と一致する（同 ADR のロスレス性）
- 構文エラーを見つけても解析を止めず、エラーの範囲を誤りのノード（`NErrorNode`）にまとめ、次のブロックの境界（空行）から再開する
- 括弧の対応が崩れた場合は、段落の終わりで閉じたものとみなし、エラーを段落の外に広げない
- エラーごとに Golem の診断（`G01xx` の診断コードと日本語のメッセージ）を返す（golem-syntax [ADR 0001](0001-bounded-left-recursion.md)）

Golem は AST を peg-hs の型付きの値からではなく、構文木（CST）から自分で導出する（golem-parser [ADR 0001](0001-bounded-left-recursion.md)）。
したがって Golem に必要なのは、誤りの範囲を誤りのノードとして含む構文木を必ず返すことである。
型付きの値の回復は、構文木を使わない利用者のための機能として同時に定める。

回復の方法は、ラベル付きの失敗による回復（Medeiros and Mascarenhas 2018）を採る。
文法の作者が、そこで失敗したら構文エラーである位置に `e ^label` を書き、ラベルごとに回復の規則を与える。
回復の規則は、入力を同期の位置（Golem なら次の空行）まで読み飛ばす普通の PEG の規則である。
回復の方針が文法の中に書けるので、Golem の「空行で再開する」「段落の終わりで閉じたとみなす」は、Golem の文法の規則としてそのまま表せる。
PEG の回復の方式には、ほかに自動で同期の位置を探す方式もあるが、どこで再開するかを文法の作者が制御できず、Golem の局所性の要件を保証できないため採らない。

## 実装すること

### 記法

- `e ^label`（[ADR 0005](0005-error-reporting.md) で予約）の意味論を定める。予約のための未実装のエラーはなくす
- `%recover label Name`：ラベル `label` の回復の規則を規則 `Name` とする。一つのラベルに回復の規則は一つまでとする
- ラベルの名前は識別子とする。peg-hs はラベルにメッセージを付けない。ラベルから利用者向けのメッセージや診断コードへの対応は、利用者の責任とする（Golem では `G01xx` の対応表を Golem 側に持つ）

### 失敗の意味論

ラベル付きの失敗（Maidl et al. 2016）に従う。

- `e ^l` は、`e` が通常の失敗をしたとき、ラベル `l` を送出する。送出の位置は `e` を試みた位置とする
- 送出は通常の失敗と区別される。順序付き選択 `/` は、通常の失敗のときだけ次の選択肢を試し、送出はそのまま外に伝える。逐次と繰り返しも送出をそのまま伝える
- 先読み（`&e`、`!e`）の中の送出は、通常の失敗として扱う。先読みは入力を読むかどうかの判断であり、構文エラーを確定させる場所ではないためである
- 回復の規則の中の送出は、回復の失敗として扱う。回復が入れ子になって止まらなくなるのを防ぐためである
- 送出もメモ表に記録する。同じ規則を同じ位置で評価すれば、同じラベルが送出される

### 二つのモード

解析には、回復しないモードと回復するモードがある。どちらを使うかは入口で決まる。

**回復しないモード**（既存の入口 `parse` と `parseSyntax`）

- 送出されたラベルは回復せず、解析は失敗する
- 失敗の `ParseError` は、これまでどおり最遠の位置と期待集合を持ち、[ADR 0005](0005-error-reporting.md) で予約した `parseErrorLabel` に送出されたラベルが入る

**回復するモード**（新しい入口）

- ラベル `l` が送出され、`l` に回復の規則があれば、送出の位置から回復の規則を評価する。回復の規則が成功したら、`e ^l` はその値と終わりの位置で成功したものとして解析を続け、構文エラーを一つ記録する
- 回復の規則がない、または回復の規則が失敗したときは、送出はさらに外に伝わる
- 記録した構文エラーは、解析の結果の一部として扱う。後戻りで捨てた試行の中で記録されたエラーは、その試行とともに捨てる。メモ表の項目もエラーを含めて記録し、メモ表から結果を返すときにはエラーも返す
- 開始規則が成功した後に入力が残った場合、残りの全体を一つの構文エラーとする
- 開始規則が失敗した場合（回復されないラベルか、通常の失敗）は、入力の全体を一つの構文エラーとする。これで回復するモードの入口は、どの入力に対しても結果を返す

### 構文エラーの値

```haskell
data SyntaxError = SyntaxError
  { syntaxErrorLabel :: Maybe Text     -- 送出されたラベル。入力の残りと全体の失敗では Nothing
  , syntaxErrorRange :: (Int, Int)     -- 回復の規則が読み飛ばした範囲（バイトオフセット）
  , syntaxErrorPos :: Pos              -- 範囲の始まりの位置
  , syntaxErrorExpected :: Set Expected -- 送出の時点の最遠の失敗の期待集合
  }
```

- 範囲は空でもよい。回復の規則が入力を消費しない場合（Golem の「段落の終わりで閉じたとみなす」のような挿入の回復）である
- エラーの列は、範囲の始まりの位置の順に並べる

### 入口

- `parseRecover :: Text -> (Maybe a, [SyntaxError])`：型付きの値の回復。回復の規則のアクションが、回復した部分の値（利用者の AST の誤りを表す構成子など）を返す。開始規則が回復できなかった場合だけ値は `Nothing` になる
- `parseSyntaxRecover :: Text -> (SyntaxNode, [SyntaxError])`：`%syntax` の文法でだけ生成する。全域であり、どの入力に対しても木を返す
- `%entry` と `%env` の扱いは、[ADR 0014](0014-generated-module-api.md) と [ADR 0019](0019-lossless-syntax-tree.md) の入口と同じ規則に従う（`parseRecover規則名` など）

### 構文木

- 回復した範囲は、種類が `ERROR`（[ADR 0019](0019-lossless-syntax-tree.md) で予約した `errorKind`）のノードになる。子は回復の規則が作った子であり、回復の規則自身のノードは作らない（回復の規則は `%inline` のように展開する）
- 入力を消費しない回復は、幅が 0 の `ERROR` ノードになる
- 入力の残りと全体の失敗は、それぞれの範囲のテキストを一つの無名のトークンとして持つ `ERROR` ノードになる
- これらによって、ロスレス性（構文木のテキストが入力と一致すること）は、エラーを含む入力でも成り立つ

### 静的検査

- `%recover` の規則が存在しない、または同じラベルに二つある場合はエラーとする
- `%recover` で名付けたラベルが文法のどこにも現れない場合はエラーとする
- 回復の規則は引数を取れない。回復の規則の型は、ラベルを付けた式の値の型と一致しなければならない（生成コードの型検査で GHC が確かめ、エラーは `.peg` の行で報告される）
- ラベルを付けた式が値を持たない場合、回復の規則の値は使われない

### Golem の回復の方針との対応

Golem の [ADR 0002](0002-standalone-code-generator.md) の方針は、たとえば次のように書ける（記法の例であり、Golem の文法そのものではない）。

```
%recover block SkipBlock
%recover close CloseAtParagraphEnd

Block :: Block
Block <- (Heading / List / Paragraph / BlockCommand) ^block

# 次の空行まで読み飛ばす
SkipBlock :: Block
SkipBlock <- (!BlankLine .)* { ErrorBlock }

Command :: Inline
Command <- '[' name:Ident args:Args (']' ^close) { Command name args }

# 何も読まない。段落の終わりで閉じたとみなす
CloseAtParagraphEnd :: ()
CloseAtParagraphEnd <- &(BlankLine / !.) { () }
```

診断コードは、Golem がラベルの名前（`block`、`close`）から `G01xx` に写す。

## 実装しないこと

- ラベルの自動挿入（Medeiros et al. 2020 の、文法を解析して安全な位置にラベルを付ける方式）。v1 ではラベルを文法の作者が書く
- ラベルの付け方が安全か（ラベルの送出によって、正しい入力が受理されなくなる場合がないか）の静的な検査。条件は syntax.md に書き、テストで確かめる
- メッセージの対応表と多言語化。利用者の責任とする
- 自動の同期の位置の探索（パニックモードのように、決まった区切りまで読み飛ばす方式を生成器が組み込むこと）
- インクリメンタルな再解析（仕様書）
- 回復するモードでの左再帰の成長ループの中の回復の特別な扱い。左再帰の規則の本体の中の回復は、通常の規則と同じに扱う。成長の各反復は、回復を含めて一つの成功として扱い、一致が伸びる限り成長を続ける

## テスト設計

- **全域性とロスレス性**：ラベルと回復の規則を付けた JSON の文法の派生版で、無作為な Unicode のテキストに対して `parseSyntaxRecover` が必ず終了し、構文木のテキストが入力と一致すること（プロパティテスト）
- **言語の不変**：ラベルを付けた JSON の文法が、回復しないモードで、JSONTestSuite の受理すべき全件を受理し、拒否すべき全件を拒否すること。ラベルの付け方が安全であることの確認である
- **回復の局所性**：Golem の段落の構造（空行で区切ったブロックと、角括弧のコマンド）を持つ fixture を用意し、正しい段落の間に壊れた段落を一つ挟んだ入力で、壊れた段落だけが `ERROR` ノードになり、前後の段落が正しく解析されること（golem-parser [ADR 0002](0002-standalone-code-generator.md) のテスト設計と同じ形）
- **挿入の回復**：閉じていない角括弧を段落の終わりで閉じたとみなし、幅が 0 の `ERROR` ノードと構文エラーが一つ記録され、後続の段落が正しく解析されること
- **後戻りとエラー**：回復を含む選択肢が後戻りで捨てられる文法で、捨てた試行の中のエラーが報告されないこと
- **選択と送出**：送出されたラベルで順序付き選択が次の選択肢を試さないこと。先読みの中の送出が通常の失敗になること
- **回復しないモード**：送出されたラベルが `parseErrorLabel` に入ること
- **メモ化との整合**：メモ化を無効にした評価器と、回復するモードの木とエラーの列が一致すること
- **左再帰**：左再帰の規則の中のラベルと回復で、左結合の木が保たれること
- **型付きの値**：回復の規則のアクションが返した値が、利用者の AST の該当の位置に入ること
- **静的検査**：上記の静的検査のそれぞれ

## [ADR 0005](0005-error-reporting.md)、[ADR 0019](0019-lossless-syntax-tree.md)、仕様書との関係

- [ADR 0005](0005-error-reporting.md) が予約した `^label` の意味論を本 ADR で定める。採択のとき、[ADR 0005](0005-error-reporting.md) のステータスの行を「採択→ラベルの意味論は ADR 0021」に変える
- [ADR 0019](0019-lossless-syntax-tree.md) の「エラー回復と、誤りを含む入力に対する部分的な構文木は作らない」を本 ADR で改める。採択のとき、[ADR 0019](0019-lossless-syntax-tree.md) のステータスの行を「採択→エラー回復（実装しないこと）は ADR 0021」に変える
- 仕様書の「意図的に採用しなかったもの」のエラー回復の項と、未決事項のラベルの意味論とエラー回復の項を改める

## 実装の段階

[ADR 0020](0020-unicode-identifiers-self-hosted.md) の後に置く。
Golem の golem-parser [ADR 0002](0002-standalone-code-generator.md)（peg-hs によるパーサー本体）の前提になる。
Golem の側は、本 ADR の API に合わせて golem-parser [ADR 0002](0002-standalone-code-generator.md) の「回復の方針」を具体化する。

## トレードオフ

- ラベルの送出は順序付き選択の後戻りを止めるので、ラベルを付けると、回復しないモードでも受理される言語が変わりうる。ラベルは、その位置で失敗したらどの選択肢でも成功しえない場所にだけ付ける必要がある。この条件を検査する仕組みは v1 にはなく、作者の注意と適合性テストに頼る
- ラベルと回復の規則を手で書くのは手間がかかる。その代わり、回復の位置を文法の作者が決められ、Golem の局所性の要件（エラーを段落の外に広げない）を文法の規則として保証できる
- 回復するモードは、エラーの列を結果とともに受け渡すため、回復しないモードより遅い。LSP のように回復が要る用途でだけ使い、コンパイルは回復しないモードで行う使い分けを想定する
- 開始規則が回復できなかった場合に入力の全体を一つのエラーにする規定は、全域性を保証するための最後の手段である。実用の文法では、ブロックの単位にラベルを付けて、この規定に頼らないようにする
