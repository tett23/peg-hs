# ADR 0028: ラベルの安全性を静的に検査する

ステータス: 採択→安全性の定義と記法の文法の変更は [ADR 0029](0029-label-safety-implementation-deviations.md)

## 文脈

ラベル付きの失敗（[ADR 0021](0021-error-recovery.md)）の `e ^l` は、`e` が失敗したときに送出し、順序付き選択の後戻りを止める。
そのため、ラベルの位置を誤ると、受理されるはずの入力が受理されなくなる。
たとえば `A <- 'a' ('b' ^l) / 'a' 'c'` は、ラベルがなければ `ac` を受理するが、ラベルがあると一つめの選択肢の `'b'` で送出して止まる。
[ADR 0021](0021-error-recovery.md) は、ラベルを「そこで失敗したらどの選択肢でも成功しえない位置」にだけ付けることを文法の作者に求め、その検査を v1 に入れなかった。
仕様書は、この検査を未決事項としている。

ラベルを付けた文法は、すでにリポジトリに三つある（[ADR 0021](0021-error-recovery.md) の JSON、[ADR 0023](0023-toml-conformance.md) の TOML、[ADR 0027](0027-switch-to-self-hosted-parser.md) の記法の文法）。
どれも、ラベルを外した文法と受理する言語が一致することを、テストの入力の上で確かめている。
しかし、テストの入力にない形の入力で言語が変わっていないことは保証されない。
TOML の文法を書いたときには、回復の規則の不備で誤りの位置がずれる問題を、テストで初めて見つけた（[ADR 0025](0025-lua-toml-implementation-deviations.md)）。
Golem の文法はラベルを多く使う予定であり、文法を変えるたびに作者が安全性を確かめるのは難しい。

安全性の判定は、一般には決定できない。
意味述語、引数付き規則、解析環境（[ADR 0012](0012-context-sensitive-extensions.md)）は、解析の結果を Haskell の式に委ねる。
そのため、検査は近似になる。
安全と判定したラベルは本当に安全である（健全）が、安全なラベルを安全と判定できない場合がある（偽陽性）、という側に倒す。

## 実装すること

### 安全性の定義

ラベル `e ^l` が安全であるとは、`e` が失敗する入力のどれについても、ラベルがなければ解析全体が失敗することをいう。
ラベルの送出は解析を止めるので、安全なラベルは受理される言語を変えない。

### 検査の考え方

`e` の失敗は、文法の構造に沿って外側へ伝わる。
伝わる途中で、ラベルがなければ別の道を試す地点（後戻りの地点）がある。

- 順序付き選択 `a1 / ... / an` の選択肢 `ai` の中の失敗は、`ai+1` 以降を同じ位置から試す
- `x*` と `x?` の中の失敗と、`x+` の二回目以降の繰り返しの中の失敗は、繰り返しを正常に終え、続きの式を試す
- 規則の本体の失敗は、規則の呼び出しの失敗として、すべての呼び出し元へ伝わる
- 直接の左再帰の規則で、左再帰の呼び出しで始まる選択肢の中の失敗は、成長を止め、それまでの種を規則の結果にする（[ADR 0001](0001-bounded-left-recursion.md)）。続きは呼び出し元の式である

ラベルが安全であるための十分条件は、`e` の失敗が開始規則の外まで伝わるあいだ、どの後戻りの地点でも、試される別の道が成功しえないことである。
先読み（`&e`、`!e`）の中の送出は普通の失敗として扱われる（[ADR 0021](0021-error-recovery.md)）ので、先読みに入った時点で失敗の伝わり方の検査を終える。

### 次の文字による近似

別の道が成功しえないことを、入力の次の一文字で判定する。
各式について、次の三つの文字の集合を計算する。
集合の要素は文字と入力の終わり（EOF）である。

- **C(x)**：`x` が一文字以上を消費して成功するとき、最初の文字としてありうるもの
- **E(x)**：`x` が何も消費せずに成功するとき、次の文字としてありうるもの（そうした成功がなければ空）
- **M(x)**：次の文字がこれなら、`x` が必ず成功するもの（下からの近似）

S(x) = C(x) ∪ E(x) は、`x` が成功しうる次の文字の上からの近似である。
連接は `C(x y) = C(x) ∪ (E(x) ∩ C(y))`、`E(x y) = E(x) ∩ E(y)` で合成する。
否定先読みは `E(!x) = 全体 − M(x)` とする。これにより `!.` は入力の終わりでだけ成功すると分かる。
意味述語、引数付き規則の引数、解析環境は、どの文字でも成功しうるものとして扱う。
規則の参照は、文法全体の不動点で計算する。

後戻りの地点では、次のように判定する。

- **分かっている文字 K**：後戻りの地点の位置で入力の次の文字としてありうるものは、その地点から `e` までに成功した式の列 `p` から `K = C(p) ∪ (E(p) − M(e))` と分かる。`p` が何も消費しなかった場合は `e` がその位置で失敗したので、`e` が必ず成功する文字は除ける
- **別の道**：選択肢の後続の `ai+1 ... an`、繰り返しの続き（規則の残りの式と、規則の終わりなら呼び出し元の続き）、左再帰の成長の停止の続き
- **判定**：別の道 `y` について `S(y) ∩ K = ∅` なら、`y` は成功しえない
- **共通の接頭辞**：選択肢が構文の上で同じ式で始まる場合（`Ws? a / Ws? b`）は、その式を除いてから判定する。PEG の式の照合は決定的なので、`x a / x b` は `x (a / b)` と同じ結果になる

失敗が規則の外へ伝わるときは、呼び出し元ごとに検査を続ける。
`K` は呼び出し元の接頭辞と合成する。
同じ呼び出しの位置を同じ `K` でふたたび訪れたら、その道の検査を打ち切る。
文字の集合は文法に現れる範囲の組み合わせであり有限なので、検査は終わる。

### 対象外の構成

次の位置のラベルは、安全とも危険とも判定せず、「検査できない」と報告する。

- 間接の左再帰に関わる規則で、成長する選択肢（同じ強連結成分の規則の呼び出しで始まる選択肢）の中のラベル。成長の主（[ADR 0001](0001-bounded-left-recursion.md) の head）が実行時に決まり、続きを静的に決められないため

### 報告

- 検査は peg-grammar の静的検査に加え、結果を警告として返す。警告は解析と生成を止めない
- 警告は、ラベルの位置、ラベルの名前、危険と判定した理由（どの後戻りの地点で、どの別の道が、どの文字で成功しうるか）を含む
- peg-cli は警告を標準エラー出力に書く。`--Werror` を指定すると、警告があれば失敗する
- 作者が安全を確かめたラベルは、`%safe label` で警告を止める。理由はコメントに書く。使われないラベルの名前を `%safe` に書くとエラーにする

## 実装しないこと

- ラベルの自動挿入（Medeiros et al. 2020 の方式）。仕様書の未決事項に残す
- 二文字以上の先読みによる判定。誤りの多い位置を見てから、別の ADR で検討する
- 先読みの中のラベル（効果がない）や、回復の規則のないラベルなど、安全性以外の lint

## テスト設計

- **典型例**：次の文法で、判定が期待どおりであること
  - 危険：`'a' ('b' ^l) / 'a' 'c'`、`('x' ('y' ^l))* 'x' 'z'`、`('a' ^l)?` の後に `'a'` が続く文法、左再帰の `E <- E '+' (T ^l) / T` で `E` の後に `'+'` が続きうる文法
  - 安全：`'a' ('b' ^l) / 'c'`、共通の接頭辞を持つ `Ws 'a' ('b' ^l) / Ws 'c'`、繰り返しの続きが区切りで始まる `'[' (V (',' (V ^l))*) ']'`、規則を跨いで失敗が開始規則まで伝わる文法
  - 検査できない：間接の左再帰の成長する選択肢の中のラベル
- **健全性**：安全と判定したラベルについて、ラベルを外した文法との受理の一致を確かめる。リポジトリのラベルを付けた文法（JSON の回復の文法、TOML、記法の文法、codegen の Recover の fixture）からラベルを外した変種を生成し、各文法の正しい入力の一文字の削除と重複のすべてで、二つのパーサーの受理と拒否が一致すること
- **無作為な文法**：小さな文法を無作為に作り、安全と判定したラベルについて、ラベルを外した文法と短い入力の全列挙で受理が一致すること（プロパティテスト）
- **リポジトリの文法**：リポジトリのラベルを付けた文法で警告が出ないこと。偽陽性で警告が出る場合は、`%safe` と理由を文法に書く
- **報告**：警告の位置と理由の文言の golden テスト。`--Werror` と `%safe` の動作

## 実装の段階

[ADR 0027](0027-switch-to-self-hosted-parser.md) の後に行う。
本 ADR を採択するとき、仕様書の未決事項から安全性の検査を外し、ラベルの自動挿入だけを残す。
`%safe` は記法の追加なので、`docs/syntax.md` の更新も採択と同じコミットで行う。

## トレードオフ

- 次の一文字による判定は、空白の読み飛ばしのような共通の接頭辞を、構文の上で同じ式である場合しか越えられない。`Ws? a / Sp b` のように別の規則で書いた空白は越えられず、偽陽性になる
- 健全性は、検査の規則の正しさに依存する。無作為な文法の全列挙のテストで裏付けるが、証明はしない
- 警告にしてエラーにしないのは、偽陽性があるためである。CI で検査を強制したい利用者は `--Werror` を使う
- `%safe` は作者の主張を信じる。誤った `%safe` は、ラベルがない場合と同じく、テストでしか見つからない
