# ADR 0024: 成長中の左再帰の種に依存した項目だけを捨てる

ステータス: 採択

## 文脈

[ADR 0013](0013-roadmap-toolchain-memo.md) は、左再帰の成長ループの各反復の終わりに、その反復で書かれたメモ表の項目を一律に捨てると決めた。
種に依存しない項目まで捨てる代わりに、依存の追跡をせずに正しさを保つためである。
そのトレードオフの節は、この破棄のコストを「左再帰の規則の評価は定数倍遅くなるが、[ADR 0007](0007-performance-discipline.md) の計算量の保証（最悪二乗）は変わらない」と見積もっていた。

この見積もりは、成長ループが入れ子になる場合に成り立たない。
Lua の文法（[ADR 0022](0022-lua-conformance.md)）を書く前に、左再帰の段を重ねた文法で確かめた。
`E1 <- E1 'o1' E2 / E2`、…、`En <- En 'on' Atom / Atom`、`Atom <- 'x' / '(' E0 ')'` の形の文法に、`x` を d 重の括弧で囲んだ入力を与えたときの、規則の本体の評価の回数は次のとおりである。

| 左再帰の段の数 | d = 0 | d = 1 | d = 2 | d = 3 |
|---|---|---|---|---|
| 2 | 11 | 55 | 231 | 935 |
| 4 | 47 | 799 | 12,831 | 205,343 |
| 8 | 767 | 197,119 | 50,463,231 | 20 秒で終わらない |

括弧が一段深くなるたびに、評価の回数はおよそ 2 の段数乗倍になる。
原因は二つある。

一つめは、同じ位置の内側の段の評価のやり直しである。
`Ek` の成長ループは、最後の反復で `Ek 'ok' Ek+1` の照合に失敗し、二つめの選択肢の `Ek+1` を評価する。
`Ek+1` の項目は直前の反復で書かれて捨てられているので、`Ek+1` は成長ループごと評価し直される。
これが段ごとに重なり、一つの位置で 2 の段数乗の評価になる。

二つめは、後ろの位置の項目の破棄である。
括弧の中の `E0` の項目は、外側の成長ループの反復の中で書かれるため、反復の終わりに捨てられる。
外側の反復のたびに、括弧の中の式の全体が評価し直される。
括弧の入れ子の深さについて、評価の回数が指数で増えるのはこのためである。

Lua の式は 12 段の優先順位を持ち、そのうち 9 段を左再帰で書く。
関数の呼び出しの引数や表の構築子の中に式が入れ子になるので、いまの実行時ライブラリでは実用の時間で解析できない。
Golem の式の言語も、優先順位の段を左再帰で書くと同じ問題に当たる。

### 依存する項目の範囲

成長中の種に依存しうる項目は、限られている。
規則の評価は、自分の位置より前の位置を参照しない。
したがって、位置 `i` で成長中の規則の種を参照できるのは、位置 `i` で評価された規則だけである。
さらに、位置 `i` で評価された規則でも、その評価の中で種を参照しなかったもの（上の例の `Ek+1`）は種に依存しない。

種を参照したかどうかは、メモ表の参照のたびに伝えれば、評価の中で確定できる。
依存を記録して、依存するものだけを捨てる。

## 実装すること

### 依存の記録

- 実行中の成長ループに、外側から順に 1、2、… と段の番号を付ける。成長ループが始まるときに番号を一つ増やし、終わるときに戻す
- メモ表の項目は、結果、失敗の記録、構文エラーに加えて、依存する成長ループの段の番号の集合（以下、依存集合）を持つ
- 評価の文脈は、いま評価している規則の本体がこれまでに参照した依存集合を持つ。規則の本体を評価するときは、呼び出し元の集合を退避して空から始め、終わったら、本体の集合を項目に記録したうえで、呼び出し元の集合に合併して戻す。失敗の記録（[ADR 0005](0005-error-reporting.md)）の退避と合併と同じ形である
- メモ表の項目を再生するときは、その項目の依存集合を文脈の集合に合併する
- 成長ループの種の項目（最初の失敗と、反復ごとに伸びた結果）は、その成長ループの段の番号だけからなる依存集合を持つ。種を参照した評価は、これによって依存を受け継ぐ
- 成長ループが終わったときの最終の項目の依存集合は、採用した反復の本体の依存集合から、その成長ループ自身の番号を除いたものとする

### 破棄

- 依存集合が空の項目は、書いた時点で確定とし、破棄の記録に載せない
- 依存集合が空でない項目は、書いたときに最も内側の成長ループの反復の記録に載せる
- 段 `k` の成長ループの反復の終わりに、その反復の記録を調べる。依存集合が `k` を含む項目は捨てる。含まない項目は、外側の成長ループの反復の記録に移す
- 段 `k` の反復の記録に載る項目の依存集合は、`k` 以下の番号だけを含む。内側の成長ループの番号に依存した項目は、内側の反復の終わりに捨てられ、内側の最終の項目からは内側の番号が除かれるためである。このため、終わった成長ループの番号が、残った項目に残ることはない

### 試験用の設定

- `Config` に、[ADR 0013](0013-roadmap-toolchain-memo.md) の一律の破棄に切り替える設定（`cfgDiscardAll`）を加える。既定は偽とする。新旧の破棄の結果を比べる試験のためのものである
- 破棄をしない設定（`cfgDiscard`）は残す

## 実装しないこと

- 文法の静的な解析による依存の判定（Warth らの involved set に相当するもの）。動的な記録のほうが精密であり、上の例の `Ek+1` のように、同じ位置の同じ規則でも、評価によって依存の有無が変わる場合を扱える
- 位置だけによる判定（成長中の規則と同じ位置の項目をすべて捨てる方式）。二つめの原因は解消するが、一つめの原因が残り、一つの位置で 2 の段数乗の評価になる
- 依存集合の表現の最適化。集合は `IntSet` とし、ほとんどの項目で空になる

## テスト設計

- **新旧の一致**：左再帰を含むすべての fixture の文法（codegen の Arith、Calc、Located など）と、実行時ライブラリのテストの左再帰の文法について、無作為な入力で、新しい破棄と一律の破棄（`cfgDiscardAll`）が同じ結果、同じ失敗の報告、同じ構文エラーを返すこと（プロパティテスト）
- **破棄の必要性**：破棄をしないと結果が変わる既存のテスト（`abcbc` の例）が、新しい破棄でも正しい結果を返すこと
- **入れ子の計算量**：上の文脈の表の文法（左再帰の段の数を 8 とする）を `conformance/bench/` に置き、括弧の入れ子の深さ d に対して評価の回数が d に比例すること。d を 2 倍にしたとき、評価の回数が 2.5 倍以下に収まることを確かめる
- **段の数の計算量**：同じ形で段の数を 2、4、8 と変えた文法で、`x` だけの入力の評価の回数が段の数に比例すること
- **既存の保証**：[ADR 0007](0007-performance-discipline.md) の計算量のテスト（二乗の上限）と、JSON、CommonMark の適合性テストが引き続き通ること
- **病的な文法**：[ADR 0007](0007-performance-discipline.md) の病的な文法（`conformance/bench/Pathological.peg`）は、種に依存しない `A` の項目が一律の破棄で捨てられることで二乗になっていた。本 ADR の下では `A` の項目が残って線形になるため、`L` と `A` に `%nomemo` を付けて、二乗の上限の検査が最悪の場合を扱い続けるようにする
- **計測**：JSON と CommonMark のベンチマークの時間とメモリを、変更の前後で `docs/benchmarks/` に記録する。左再帰を使わない文法では、依存集合の受け渡しの分だけ遅くなりうるためである

## 実装の段階

[ADR 0022](0022-lua-conformance.md)（Lua）の実装の前提であり、その前に行う。
[ADR 0013](0013-roadmap-toolchain-memo.md) の段階の順では、左再帰（段階 8）の修正にあたる。
本 ADR を採択するとき、[ADR 0013](0013-roadmap-toolchain-memo.md) のステータスの行を「採択→成長中の項目の破棄は ADR 0024」に変える。

## トレードオフ

- すべてのメモ表の参照と規則の評価で依存集合の受け渡しが入るため、左再帰を使わない文法も少し遅くなる。依存集合はほとんど空なので、`IntSet` の空の合併の分で済むと見込む。計測で確かめる
- メモ表の項目が一つ欄を増やすため、項目あたりのメモリが増える。空の `IntSet` は共有されるので、増えるのはポインタ一つ分である
- 正しさの根拠が「依存集合が種への依存を漏れなく表す」ことに移る。メモ表を経由しない値の受け渡し（引数付き規則の引数や意味述語が参照する束縛）も、その値を計算した評価の依存集合が文脈に合併されるので、漏れはない。この推論は試験の「新旧の一致」で裏付ける
