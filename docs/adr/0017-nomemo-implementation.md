# ADR 0017: %nomemo を実装する

ステータス: 採択

## 文脈

ADR 0006 は `%nomemo Name` を予約し、実装するかどうかの判断をベンチマークの実測に委ねた。
ADR 0007 のベンチマークで、JSON の文法のメモ表の常駐量を測った。
80 万文字の JSON 文書の解析で、最大の常駐メモリは約 248MB だった。
入力 1 文字あたり約 310 バイトであり、書籍一冊分の原稿（数 MB）を扱う Golem では GB の単位に達する見込みがある。

メモ表の項目の大半は、空白や一文字の字句のように、同じ位置で二度評価されることがほとんどない規則のものと考えられる。
JSON の文法の `Ws`、`Hex`、`Unit` がその例である。
こうした規則のメモ化を外せば、計算量を大きく損なわずにメモリを減らせる見込みがある。

ADR 0006 は、実装する場合の制約を先に定めていた。
左再帰に関与する規則への指定は静的検査でエラーとすること、メモ化の有無が解析結果を変えてはならないこと、の二つである。

## 実装すること

- `%nomemo Name` を実装する。指定した規則は、評価のたびに規則の本体を評価し、メモ表に項目を作らない。生成コードは、該当の規則の表を確保しない
- 左再帰に関与する規則への指定は、静的検査でエラーとする（ADR 0006）
- 引数付き規則（ADR 0012）への指定は許す
- 失敗の情報は、メモ化する規則と同じく規則の評価ごとに記録して合流させる。メモ化の有無が失敗の報告を変えないためである（ADR 0005）
- JSON の文法で、どの規則にメモ表の項目が集まっているかを規則ごとに数える仕組みを、ベンチマークの `--memo-report` に加える。`%nomemo` を付ける規則を選ぶ材料にする
- 測定の結果は `docs/benchmarks/` に日付と計測した環境を付けたスナップショットとして置く。ADR 0007 は計測値をリポジトリに記録しないと定めたが、その趣旨は退行の判定に絶対値を使わないことにある。判断の根拠として残す計測は、これとは別のものとして記録する

## 実装しないこと

- メモ化を外す規則の自動選択はしない。どの規則を外すかは利用者が文法に書く
- 既定をメモ化なしとし、`%memo` で指定する方式は採らない（ADR 0006）
- メモ表の大きさの上限や、古い項目の破棄はしない（ADR 0006）

## テスト設計

- **静的検査**：左再帰に関与する規則への `%nomemo` がエラーになること。未定義の規則への `%nomemo` がエラーになること（既存の検査）
- **結果の不変**：`%nomemo` を付けた文法と付けない文法で、無作為な入力に対する解析の結果と失敗の報告が一致すること（プロパティテスト）
- **メモ表の大きさ**：`%nomemo` を付けた規則について、メモ表の項目が作られないこと（評価回数のフックと項目数で確かめる）
- **JSON**：JSON の文法の字句の規則に `%nomemo` を付けた版で、ADR 0010 の適合性テストが同じ結果を保つこと

## 実装の段階

ADR 0013 の段階 11 の後に置く。ADR 0016 との順序は問わない。

## トレードオフ

- メモ化を外した規則が深い後戻りの中で何度も呼ばれる文法では、計算量が線形でなくなる。外す規則を誤ると性能が悪化するため、規則ごとの項目数の報告と、外した前後のベンチマークの比較を手順として README に書く
- `docs/benchmarks/` の計測値は特定のマシンの値であり、他のマシンとは比べられない。スナップショットには計測環境を明記する
