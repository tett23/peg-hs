# ADR 0075: アクションのない規則の型を、推論するか生成する

ステータス: 採択

## 文脈

アクション `{ … }` を書かずに済む場合は、これまでに四つ決めた。

- 値を持つ要素がちょうど一つの選択肢は、その値を返す（[ADR 0004](0004-peg-notation.md)、[ADR 0065](0065-omittable-identity-actions.md)）
- 型が `()` の規則の、`()` 以外の値を持つ要素のない選択肢は、`()` を返す（[ADR 0063](0063-omit-unit-actions.md)、[ADR 0064](0064-unit-rules-always-return-unit.md)）
- 型注釈のない規則の型は `()` である（[ADR 0066](0066-omit-unit-type-annotations.md)）
- `%syntax` の文法では、型注釈のない規則の、アクションのない選択肢は、要素によらず `()` を返す。値は構文木から取り出す（[ADR 0068](0068-untyped-rules-in-syntax-grammars.md)）

これで省けないのは、値を持つ要素が二つ以上の選択肢と、型注釈のない規則で値を返したい選択肢である。
前者はいまは静的検査の誤り（`an alternative without an action must have exactly one element with a value, but it has 2`）になり、後者は GHC の型の誤りになる。
どちらも、利用者は値の型を verbatim ブロックに書き、型注釈を書き、束縛を書き、アクションで組み立てる必要がある。

```hpeg
%{
data Expr = Add Expr Term | Lit Term
}%

Expr :: Expr
Expr <- l:Expr '+' r:Term { Add l r }
      / t:Term            { Lit t }
```

この型とアクションは、文法の形から機械的に決まる。
リポジトリの持ち主は、省けるアクションは省いてコードを自動で生成し、ある程度の遅さは許容する、と決めた。
速さが要る利用者だけが、型注釈とアクションを手で書いて速くする経路を残す。

自動で作る値の形として、三つを比べた。

- **型と構築子を生成する**：規則ごとに Haskell の代数的データ型を生成し、選択肢ごとに構築子を作る。BNFC の LBNF（ラベル付き BNF）が同じ方式で、文法から抽象構文木の型を生成する
- **型を推論し、値が二つ以上なら組にする**：新しい型は作らない。選択肢ごとに型が違う規則（`Num / Ident`）は書けない
- **構文木を既定にする**：`%syntax` を書かなくても、型注釈とアクションのない文法は構文木の入口を持つ（[ADR 0068](0068-untyped-rules-in-syntax-grammars.md) の書き方を既定にする）。値はパターン照合できる型にならず、取り出し関数で読む

リポジトリの持ち主は、型と構築子を生成する方式を選び、そのうえで、生成しなくても型が決まる規則は型を推論すると決めた。
`Paren <- '(' Sp Expr ')' Sp` のように、どの選択肢も同じ型の値を一つだけ返す規則は、構築子で包まずにその値を返す。
包むと、利用者は意味のない構築子（`Paren`）を剥がすコードを書くことになるからである。

Haskell の構築子には名前が要る。
生成する型の構築子の名前は、利用者が書かなくても既定の名前を付ける。
名前を書く記法は、既定の名前を変えたいときのために用意する。

## 実装すること

### 規則の分類

型注釈とアクションのない規則を、次の三つに分ける。
対象は、`%syntax` を持たない文法の、型注釈がなく、どの選択肢もアクションを持たない規則である。
型注釈のある規則、アクションを持つ規則、`%syntax` の文法の規則は、これまでどおりに扱う。

| 分類 | 条件 | 規則の型 | 選択肢の値 |
|---|---|---|---|
| `()` の規則 | どの選択肢も `()` 以外の値を持つ要素を持たない | `()` | `()` |
| 型を推論する規則 | どの選択肢も、`()` 以外の値を持つ要素をちょうど一つ持ち、それらの型がすべて同じ | その型 | その要素の値 |
| 型を生成する規則 | それ以外 | 生成した型 | 構築子に要素の値を並べたもの |

```hpeg
Sp <- ' '*                       # () の規則
Num <- $[0-9]+ Sp                # 型を推論する規則。型は Text
Paren <- '(' Sp Expr ')' Sp      # 型を推論する規則。型は Expr（下）
Atom <- Num / Paren              # 型を生成する規則。Text と Expr が違う
Expr <- Expr '+' Sp Atom          # 型を生成する規則。値の数が 2 と 1
      / Atom
```

### 分類の決め方

規則どうしは互いに依存するので、二段の不動点で決める。

1. **`()` かどうか**：はじめにすべての対象の規則を `()` の規則とみなす。ある選択肢が `()` 以外の値（キャプチャ、`()` でない型注釈のある規則の呼び出し、`()` でない対象の規則の呼び出し、それらの繰り返しと省略）を持つ規則を、`()` でない規則に移す。移る規則がなくなるまで繰り返す。値の数え方は [ADR 0030](0030-unit-values-are-not-counted.md) と [ADR 0064](0064-unit-rules-always-return-unit.md) のとおりとする（`()` の要素は数えず、`[()]` と `Maybe ()` も `()` の値とみなす）。この段で、各選択肢の値を持つ要素の数が決まる
2. **推論か生成か**：`()` でない規則のうち、値を持つ要素の数が 1 でない選択肢を持つ規則は、型を生成する規則に決まる。残りの規則は型を推論する候補とし、型を未定として始める。候補の各選択肢の要素の型を、わかっているものから求める。型が未定の候補の呼び出しは、まだ数えない。わかった型が一つなら候補の型とし、二つ以上の違う型が現れたら型を生成する規則に移す。変わる規則がなくなるまで繰り返す。終わっても型が未定の候補は、型を生成する規則とする

要素の型は、[値を持つ式](../syntax.md#値を持つ式)の表のとおりとする。
型を推論する規則の呼び出しは推論した型、型を生成する規則の呼び出しは生成した型になる。
二つの型が同じかどうかは、型の文字列を空白を除いて比べて決める。
型の別名（`type Name = Text`）は別の型とみなす。
比べられない場合は型を生成する側に倒すので、生成したモジュールの型が合わなくなることはない。

この分類で `()` でない規則は、いまはほぼすべて誤り（静的検査か GHC の型の誤り）になる。
例外は、`()` の別名を型注釈に書いた規則（`B :: Unit`、`type Unit = ()`）の呼び出しだが、`A <- B` は型を推論する規則になり、いまと同じく `B` の値を返す。
そのため、いま生成できる文法の意味は変わらない。

### 生成する型

- 型の名前は、規則名の先頭を大文字にしたものとする。大文字のない文字で始まる規則名は、前に `Rule'` を付ける（[ADR 0053](0053-type-names-of-rules-without-case.md) と同じ）
- 選択肢ごとに構築子を一つ作る。値を一つだけ持つ選択肢も構築子で包む
- 構築子の既定の名前は、選択肢が一つなら型の名前と同じ、二つ以上なら型の名前に選択肢の番号（1 から）を付けたもの（`Expr1`、`Expr2`）とする
- 構築子の引数は、選択肢の値を持つ要素の値を、現れる順に並べたものとする。束縛の有無によらない。`()` の要素は並べない
- 値を持つ要素のない選択肢は、引数のない構築子になる
- 構築子が一つで引数が一つの型は、`newtype` にする

上の `Atom` と `Expr` は次の型になる。`Num` と `Paren` は型を推論するので、型を作らない。

```haskell
data Atom = Atom1 Text | Atom2 Expr
  deriving (Eq, Show)

data Expr = Expr1 Expr Atom | Expr2 Atom
  deriving (Eq, Show)
```

### 構築子の名前

選択肢の末尾（アクションを書く位置）に `@名前` を書くと、その選択肢の構築子の名前になる。

```hpeg
Expr <- Expr '+' Sp Atom @Add
      / Atom             @Single
```

- `@名前` を書いた選択肢を含む規則は、型を推論する条件を満たしても、型を生成する規則とする。名前を書くのは、構築子で包みたいからである
- `@名前` は、対象の規則（型注釈とアクションがなく、`%syntax` のない文法の規則）にだけ書ける。ほかの規則に書くと、理由ごとの文言の誤りになる（`error: @Add names a constructor, but rule Expr has a type annotation` など）
- `()` の規則に書いても誤りになる。値を持たない規則の型は `()` である
- 名前は Haskell の構築子の名前（大文字で始まる識別子）でなければならない
- 生成モジュールの中で、構築子の名前は重なってはならない。既定の名前（`Expr1`）が別の規則の型の名前や構築子と重なる場合も誤りとし、`@名前` で付け直すよう文言で促す

### deriving

- 生成する型には、既定で `deriving (Eq, Show)` を付ける
- `%deriving` ディレクティブで、付けるクラスを変える。`%deriving Eq, Ord, Show` のように書く。`%deriving` を引数なしで書くと、何も付けない。`%deriving` は一度だけ書ける
- 構築子の引数に、型注釈で書いた利用者の型が現れ、その型がクラスのインスタンスを持たなければ、GHC の誤りになる。そのときは `%deriving` で付けるクラスを減らすか、インスタンスを書く

### 公開

- 生成する型は、構築子ごと（`Expr(..)`）生成モジュールから公開する
- `peg-hs gen --export`（[ADR 0061](0061-select-generated-exports.md)）で入口を絞ったときは、公開する入口の型から辿れる生成した型だけを公開する

### アクション、束縛、引数との関係

- 対象の規則の選択肢にアクションを一つでも書くと、その規則は対象から外れ、これまでどおり型が `()` の規則になる。値を返す選択肢があれば、これまでどおり誤りになる。型注釈を書けば、これまでどおりアクションで値を組み立てられる
- 型を推論する規則と型を生成する規則は、型注釈とアクションを書いた規則から呼べる。呼び出し元のアクションは、推論した型か生成した型の値を受け取る
- 速さが要る規則は、型注釈とアクションを手で書く。規則ごとに選べるので、時間のかかる規則だけを手で書ける
- 束縛（`l:Expr`）は書いてよい。束縛した値は、意味述語と規則の引数から読める
- 引数付き規則と雛形は、これまでどおり型注釈が要る（[ADR 0066](0066-omit-unit-type-annotations.md)）。雛形の呼び出しは、対象の規則の中に書ける。その値の型は、展開した規則の型注釈の型である

### 記法と整形

- 自己記述の文法（`Peg.hpeg`）と文法の AST に、選択肢の `@名前` と `%deriving` を加える。ロスレスな構文木にも節を加える
- `peg-hs fmt` は、`@名前` を選択肢の末尾に空白一つを挟んで置き、アクションと同じ揃え方（[ADR 0032](0032-grammar-formatter.md)）で揃える。`%deriving` はほかのディレクティブと同じ位置に並べる

### シンタックスハイライト

- tree-sitter の文法に、`@名前` の節（`constructor_name`）と `%deriving` の引数の節（`class_name`）を加える。`highlights.scm` で、`@` を `@punctuation.special`、構築子の名前を `@constructor`、クラスの名前を `@type` とする。`locals.scm` は変えない
- TextMate の文法に同じ区別を加える。scope の名前は、VS Code の Haskell の TextMate の文法の、構築子とクラスの scope に合わせる。スナップショットの golden を作り直す
- 自己記述の文法のハイライトの種類（`Peg.Grammar.Highlight`）に、構築子の名前（`HConstructor`）とクラスの名前（`HClassName`）を加える。文法の範囲の一致のテスト（[ADR 0034](0034-syntax-highlighting.md)）に、構築子の名前の範囲を加える
- リリースのアーカイブ（[ADR 0073](0073-editor-grammars-in-releases.md)）の中身の一覧は変わらない

### 言語サーバー

- semantic tokens：`@名前` の構築子の名前を `enumMember`、`%deriving` のクラスの名前を `type` とする。`tokenTypes` に二つを加える
- ホバー：型を推論する規則には推論した型を、型を生成する規則には生成した型の宣言（`deriving` を含む）を表示する。`()` の表示（[ADR 0066](0066-omit-unit-type-annotations.md)）は `()` の規則に限る。`@名前` の上では、その構築子の型（`Add :: Expr -> Atom -> Expr`）を表示する
- コードアクション：型を生成する規則の、`@名前` のない選択肢に、既定の構築子の名前を `@名前` として書き出す。既定の名前は選択肢の並びで変わるので、長く使う文法で名前を固定するためのものである
- 診断：分類と構築子の名前の誤りは、静的検査の誤りとしてこれまでの経路で送る
- 増分の構文解析（[ADR 0071](0071-incremental-parsing-in-the-language-server.md)）の区切りの規則は、`%deriving` が最上位の要素の頭で始まるので、変えない

### lint

- lint は新しい規則を持たない

### 文書

- docs/syntax.md の「アクションの省略」に、三つの分類、型の推論、型の生成、`@名前`、`%deriving`、誤りを書く。値を持つ要素が 2 個以上の選択肢の誤りの例を、対象の規則の外の例に直す。ディレクティブの表に `%deriving` を加える。冒頭の「反映している ADR」にこの ADR を加える
- README の「最初の文法」の後の書き方の比較（[ADR 0068](0068-untyped-rules-in-syntax-grammars.md)）に、型を推論し生成する書き方を加え、三つ（推論と生成、構文木を使う、型注釈とアクションを書く）を並べる。速さが要るときは型注釈とアクションを書くことと、計測の比を添える。エディタの節のハイライトの説明に、構築子の名前を加える
- docs/specifications.md の生成するコードとエディタの支援の節に、この規則を書く
- [ADR 0066](0066-omit-unit-type-annotations.md) のステータスに、型の推論と生成がこの ADR にあることを加える

### 計測

- JSON の文法を、型注釈とアクションを書かずに推論と生成に任せた形にした `conformance/bench/JsonGenerated.hpeg` をベンチマークに加える
- 実装の後に、いまの `Json.hpeg`（型注釈とアクション）、`JsonUntyped.hpeg`（構文木）、`JsonGenerated.hpeg` の三つで、[ADR 0068](0068-untyped-rules-in-syntax-grammars.md) と同じ合成の JSON の文書を解析する時間と最大の常駐メモリを測り、`docs/benchmarks/` に記録する
- 言語サーバーの 1 回の編集の時間（[ADR 0071](0071-incremental-parsing-in-the-language-server.md) の計測）を測り直し、分類の計算で 16 ms の目安を超えないことを確かめて、同じ記録に書く

## 実装しないこと

- `%syntax` の文法での型の推論と生成。`%syntax` の文法の型注釈のない規則は、[ADR 0068](0068-untyped-rules-in-syntax-grammars.md) のとおり `()` のまま
- 値を持つ要素が二つ以上の選択肢を組（`(a, b)`）にすること。その選択肢を持つ規則は、型を生成する
- 型の別名や型の同値の推論。型の文字列が違えば違う型とみなす
- 構築子の引数に名前を付けること（レコードの構文）。束縛の名前からレコードのフィールドを作ると、型をまたいで名前が重なりやすい
- 生成する型に位置（`Span`）を持たせること。位置が要る規則は、型注釈とアクションで `_span` を使う
- 値を持つ要素が二つ以上のグループ（`(a:A ',' b:B)*`）に値を持たせること。値が要るときは、グループを規則に切り出す
- 言語サーバーでの、生成した型の定義への移動と、構築子の参照の検索
- 型を推論し生成する規則と同じ値を、アクションで書き直す lint

## テスト設計

先に書き、いまの実装で失敗させる。

### 分類

- 型注釈、`%syntax`、アクション、`@名前` の有無と、値を持つ要素の数と型の組み合わせで、分類が上の表のとおりになること
- 不動点：自分を呼ぶ規則（`A <- '(' A ')' / 'x'` は `()`、`A <- '(' A ')' / Num` は `Num` の型を推論）、互いに呼ぶ規則（`A <- B / 'x'` と `B <- '[' A ']' / $[0-9]+` は、`A` の選択肢の値の数が 0 と 1 なので `A` を生成、`B` は生成した `A` と `Text` が違うので生成）、推論の候補が後から生成に移り、呼び出し元も生成に移る場合
- 型の比較：`[Int]` と `[ Int ]` は同じ、`Text` と別名の `Name` は違うとみなすこと
- いまの文法の意味が変わらないこと：`B :: Unit` を呼ぶ `A <- B` が `B` の値を返すこと

### 誤り

- `@名前` を、型注釈のある規則、`%syntax` の文法、アクションのある規則、`()` の規則に書いた場合の文言
- 名前が大文字で始まらない場合、構築子の名前が重なる場合（`@名前` どうし、既定の名前と別の規則の型の名前）の文言
- `%deriving` を二度書いた場合の文言

### 生成

- 生成した宣言の golden：選択肢が一つと二つ以上、引数が 0、1、2 個以上、`newtype` になる場合、`@名前`、`%deriving` の有無と引数なし、`Rule'` の付く規則名、`--export` で入口を絞った場合
- 生成したモジュールが警告なしでコンパイルでき、入口が推論した型と生成した型の値を返すこと。上の文法で、`1+2` が `Expr1 (Expr2 (Atom1 "1")) (Atom1 "2")` になること
- いま生成できるリポジトリのすべての文法の生成コードが、この変更で変わらないこと（golden の再生成で差分がないこと）

### 記法、整形、ハイライト

- 自己記述の文法の構文解析と、ロスレスな構文木の往復（`@名前` と `%deriving` を含む文法の、構文木のテキストが入力と一致すること）
- `peg-hs fmt` の golden：`@名前` の揃え方と `%deriving` の位置。整形が冪等であること
- tree-sitter：`test/highlight/` に `@名前` と `%deriving` の断言を加え、コーパスに例を加える。範囲の一致のテストに構築子の名前を加え、自己記述の文法、tree-sitter、TextMate の三つで一致すること。リポジトリのすべての文法を `ERROR` なく読むこと
- TextMate：スナップショットの golden に新しい scope が現れること

### 言語サーバー

- semantic tokens：`@Add` が `enumMember`、`%deriving Eq` の `Eq` が `type` になること
- ホバー：型を推論する規則、型を生成する規則、`()` の規則、`@名前` の上で、上のとおりの文字列になること
- コードアクション：既定の名前を書き出した文法の生成コードが、書き出す前と同じになること
- 増分の構文解析：`@名前` と `%deriving` を含む文法とその変異で、全体の解析との一致のテスト（[ADR 0071](0071-incremental-parsing-in-the-language-server.md)）が通ること

### JSON での一致

- `JsonGenerated.hpeg` の値を、テストのコードで `Json.hpeg` の値の型に写したものが、無作為な JSON の文書と JSONTestSuite の全件で、`Json.hpeg` の値と同じであること（プロパティテストと適合性テスト）

### 計測

- 自動テストにはしない。実装の後に三つの変種と言語サーバーを測り、`docs/benchmarks/` に記録する

## トレードオフ

- 規則の型が、型注釈ではなく分類で決まる。空白の規則に `$` を一つ足すと、その規則の型が `()` から `Text` に変わり、呼び出し元の分類も変わりうる。ホバーで推論した型と生成した型を表示して、変化を見えるようにする
- 型の推論は、型の文字列の比較だけで行う。型の別名や、同じ型の違う書き方（`Data.Text.Text` と `Text`）は違う型とみなし、型を生成する側に倒れる。推論が外れても型の誤りにはならないが、利用者の思うより構築子が増えることがある
- 生成した型は、文法の形をそのまま写す。利用者の扱いやすい型にするには、`@名前` を付けるか、生成した型から別の型に写す関数を書く。写す分だけ時間とメモリがかかる
- 既定の構築子の名前（`Expr1`、`Expr2`）は、選択肢を並べ替えたり足したりすると変わり、生成モジュールの公開 API が変わる。長く使う文法では、コードアクションで `@名前` を書き出して固定する
- 速さは、アクションを書いた文法より落ちうる。キャプチャした `Text` と構築子を、使うかどうかによらず作るからである。どの程度落ちるかは計測で記録する。速さが要る利用者は、規則ごとに型注釈とアクションを書いて速くできる
- `@` と `%deriving` の二つの記法が増え、自己記述の文法、整形、tree-sitter、TextMate、言語サーバーのすべてに手が入る。`@` はいまの記法で使っていない文字である
