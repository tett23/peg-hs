# ADR 0026: 値が使われない位置の式は、値を捨てる形で生成する

ステータス: 採択

## 文脈

Lua の文法（ADR 0022）を書いたとき、次の規則の生成コードが GHC の型の誤りになった。

```
LiteralString <- s:$('"' DqChar* '"' / LongBracket) { s }
```

括弧のグループは、どの選択肢も値をちょうど一つ持つので、値を持つグループとして生成される（ADR 0004）。
一つめの選択肢の値は `DqChar*` の `[()]`、二つめは `LongBracket` の `()` であり、型が合わない。
しかし、テキストキャプチャ `$e` の値は消費した入力の `Text` であり、`e` の値は使われない（docs/syntax.md）。
使われない値の型が合わないことで文法が通らないのは、生成器の誤りである。
Lua の文法では、補助の規則 `ShortString :: ()` を立てて回避した。

同じことは、値が使われない位置のすべてで起きうる。

- テキストキャプチャ `$e` の `e`
- 先読み `&e`、`!e` の `e`
- アクションを書いた選択肢の、束縛しない要素
- 値を持たないグループ（どれかの選択肢の値が 0 個か 2 個以上）の中の要素

## 実装すること

- 生成器は、式を「値を使う」か「値を捨てる」かのどちらかの文脈で生成する。上に挙げた四つの位置の式は、値を捨てる文脈で生成する
- 値を捨てる文脈では、括弧のグループを値を持たないグループとして生成する。各選択肢は値 `()` を返し、選択肢の中の要素も値を捨てる文脈で生成する
- 値を捨てる文脈は、`*`、`+`、`?`、失敗ラベル `^label` の中の式にも及ぶ。型付きの値の生成では、`*`、`+`、`?` は値を集めない形（`skipMany`、`skipMany1`、`skipOptional`）にする。失敗ラベルの回復の規則の値は捨てる（ADR 0021 の値を持たない式のラベルと同じ扱い）
- 構文木の生成（ADR 0019）では、値を捨てても構文木の子は変わらない
- 束縛した要素、値の受け渡し（アクションの省略）で使われる要素、値を持つグループの中の値を使う要素は、これまでどおり値を使う文脈で生成する。そこで選択肢の型が合わないのは文法の誤りであり、GHC が `.peg` の位置で報告する（ADR 0014）

## 実装しないこと

- 値を使う位置のグループで、選択肢の型が合うかどうかの静的な検査。型を知るのは GHC であり、peg-grammar は Haskell の型を解釈しない
- 値を捨てる文脈での規則の呼び出しの変更。規則の値は計算されずに捨てられる（遅延評価）ので、呼び出しの形は変えない

## テスト設計

- **fixture**：テキストキャプチャ、肯定先読み、否定先読み、アクションを書いた選択肢の束縛しない要素のそれぞれに、選択肢の値の型が異なるグループを置いた文法を codegen の fixture に加える。生成コードがコンパイルでき、解析の結果が期待どおりであること。`%syntax` を付けた文法でも同じこと
- **既存の文法**：既存のすべての fixture と適合性テストの文法を再生成し、すべてのテストが通ること
- **Lua の文法**：回避のために立てた `ShortString` を元の形（`$('"' DqChar* '"' / '\'' SqChar* '\'' / LongBracket)`）に戻し、Lua の適合性テストが通ること

## 実装の段階

ADR 0022 の実装で見つかった誤りの修正であり、ADR 0025 の後に行う。

## トレードオフ

- 既存の文法の生成コードが変わる。値を捨てる位置の `*`、`+`、`?` がリストや `Maybe` を作らなくなるので、割り当ては減る方向にしか変わらない
- 値を捨てる文脈は生成器の内部の区別であり、記法には現れない。文法の作者が束縛を付け外しすると、グループの選択肢の型の要求が変わる
