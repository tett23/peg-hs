# ADR 0064: 型が () の規則で、アクションを省略した選択肢は常に () を返す

ステータス: 採択

## 文脈

[ADR 0063](0063-omit-unit-actions.md) は、型が `()` の規則で、単位でない値を持つ要素が一つもない選択肢のアクションを省略できるようにした。
値は `()` になると定めたうえで、束縛した単位の要素については「一つだけなら、これまでどおりその値を返す」と書いた。

ところが、単位の値は `()` だけではない。
[ADR 0030](0030-unit-values-are-not-counted.md) は、単位の式に `*`、`+`、`?` を付けた式も単位とし、その値は `[()]` や `Maybe ()` になる。
アクションを省略した選択肢は、数える要素がちょうど一つなら、その要素の値をそのまま返す（[ADR 0004](0004-peg-notation.md)、[ADR 0030](0030-unit-values-are-not-counted.md)）。
そのため、`Ws :: ()` の規則で `Spaces <- Ws*` と書くと、選択肢の値は `[()]` になり、規則の型 `()` と合わない。
生成したモジュールは、GHC の型の誤りでコンパイルできない。

[ADR 0063](0063-omit-unit-actions.md) を実装し、リポジトリの文法から `{ () }` を除いたところ、記法自身の文法から生成したパーサーがこの型の誤りでコンパイルできなくなった。
同じ形は、束縛した要素（`x:Ws*`）でも起きる。
[ADR 0063](0063-omit-unit-actions.md) の「束縛した単位の要素が一つだけなら、これまでどおりその値を返す。どちらも値は `()` である」という記述は、`()` 以外の単位の値を見落としている。

文法の作者が `Spaces <- Ws*` と書いて期待するのは、`Spaces` の型 `()` の値である。
型が `()` の規則の値は `()` しかないので、数える要素の値を返す理由はない。

## 実装すること

### 値の規則

- 規則の型注釈が `()` で、アクションを省略した選択肢に単位でない値を持つ要素が一つもないとき、選択肢の値は常に `()` とする。数える要素が一つでも、その値は返さない
- 束縛した単位の要素も同じに扱う。`x:Ws*` だけの選択肢の値も `()` である。束縛した名前はどこからも使われないので、lint の使われない束縛の警告（[ADR 0033](0033-grammar-linter.md)）はこれまでどおり出る
- 型が `()` でない規則の、アクションを省略した選択肢は、これまでどおり数える要素の値を返す（[ADR 0004](0004-peg-notation.md)、[ADR 0030](0030-unit-values-are-not-counted.md)）
- 型が `()` の規則で、単位でない値を持つ要素がちょうど一つの選択肢は、これまでどおりその値を返し、型の不一致は GHC が報告する

これまで書けた文法の値は変わらない。
型が `()` の規則で、数える要素の値が `()` のとき（`Spaces <- Ws`）は、返す値はもともと `()` である。
`()` 以外の単位の値（`[()]`、`Maybe ()`）を返していた場合は、規則の型と合わず、もともとコンパイルできなかった。

### 生成

- 上の選択肢は、要素を値を捨てる文脈（[ADR 0026](0026-discard-unused-values.md)）で生成し、`()` を返す。束縛した要素は、意味述語や引数から参照できるように、これまでどおり束縛する
- `%syntax` の文法では、構文木の子は `{ () }` を書いた場合と同じにする

### lint

- 型が `()` の規則で、上の規則によって省略できる `{ () }` に、[ADR 0063](0063-omit-unit-actions.md) の notice（`omittable-unit-action`）を出す。`Spaces <- Ws* { () }` も対象になる
- `{ () }` を省略した選択肢には、notice も警告も出さない。束縛を含む選択肢の使われない束縛の警告は、`{ () }` を書いた場合と同じく出る
- リポジトリの文法は、書き直した後に `peg-hs lint` が何も出力しない状態にする。notice も警告も残さない

### 文書

- [docs/syntax.md](../syntax.md) の「アクションの省略」の節に、型が `()` の規則では、単位の繰り返しや省略の要素が一つだけでも値は `()` になることを書く。冒頭の「反映している ADR」にこの ADR を加える
- [ADR 0063](0063-omit-unit-actions.md) のステータスを「採択→単位の要素が一つの選択肢の値は ADR 0064」に変える

## 実装しないこと

- 型が `()` でない規則の値の規則の変更
- `[()]` や `Maybe ()` を `()` とみなす一般の型の変換。この ADR は、型が `()` の規則でアクションを省略した選択肢だけを扱う

## テスト設計

先に書き、いまの実装（[ADR 0063](0063-omit-unit-actions.md) の実装の 1 つめのコミット）で失敗させる。

- **生成とコンパイル**：型が `()` の規則で、`Ws*`、`Ws+`、`Ws?`、`x:Ws*`、ラベルを付けた `Ws*` のそれぞれ一つだけの選択肢を、アクションなしで書いた fixture が、警告なしでコンパイルでき、値が `()` であること
- **`%syntax`**：同じ文法に `%syntax` を付けた版で、構文木が `{ () }` を書いた版と同じ子を持つこと
- **値が変わらないこと**：`Spaces <- Ws`（数える要素の値が `()`）の生成物が、この変更の前と同じ値を返すこと。型が `()` でない規則の、アクションを省略した選択肢の値が変わらないこと
- **lint**：`Spaces <- Ws* { () }` に notice が出て、`Spaces <- Ws*` には何も出ないこと。`Spaces <- x:Ws*` には使われない束縛の警告だけが出ること
- **リポジトリの文法**：書き直した後に、記法自身の文法を含むすべての生成物がコンパイルでき、すべてのテストが通ること。`peg-hs lint` の出力が空であること

## トレードオフ

- 型が `()` の規則では、アクションを省略した選択肢の値の決め方が、ほかの型の規則と変わる。ほかの型では数える要素の値を返し、`()` の規則では常に `()` を返す。型が `()` の規則の値は `()` しかありえないので、利用者から見た違いは、もともと型の誤りになっていた文法が書けるようになることだけである
- 束縛した単位の要素だけの選択肢でアクションを省略すると、束縛は意味を持たない。使われない束縛の警告が出るので、作者は気付ける
