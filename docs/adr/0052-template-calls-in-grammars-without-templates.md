# ADR 0052: 雛形のない文法での雛形の呼び出しを誤りにする

ステータス: 採択

## 文脈

規則の雛形（[ADR 0031](0031-rule-templates.md)）は、`List<p, sep>` のように規則や式を引数に取り、呼び出しごとに普通の規則へ展開する。
雛形でない規則を `<...>` で呼ぶと、展開は「rule B is not a template」の誤りを報告する。

ところが、雛形を一つも定義していない文法では、この誤りが出ない。

```hpeg
%module M
A :: ()
A <- B<'x'> B { () }

B :: ()
B <- 'b' { () }
```

この文法に対して、`peg-hs gen` は次のように止まる。

```text
peg-hs: a template call must be expanded before generating code
CallStack (from HasCallStack):
  error, called at src/Peg/Codegen.hs:558:19 in peg-codegen-0.1.0.0-inplace:Peg.Codegen
```

`peg-hs lint` は何も報告せずに成功し、言語サーバーも誤りを出さない。
文法に雛形を一つでも定義すると、同じ呼び出しは正しく「rule B is not a template」の誤りになる。

原因は雛形の展開（`Peg.Grammar.Templates.expandTemplates`）の近道である。
展開は、文法に雛形がなければ、呼び出しを調べずに文法をそのまま返す。
雛形の呼び出しが残った文法が静的検査を通り、生成器の内部の検査で初めて止まる。
生成器の文言は利用者に向けたものではなく、位置も示さない。

## 実装すること

- 雛形の展開の近道を、文法に雛形の定義も雛形の呼び出しもない場合に限る。雛形の呼び出しが一つでもあれば、雛形がなくても展開を行い、雛形でない規則の呼び出しを「rule B is not a template」の誤りにする
- 呼び出した名前の規則がない場合も、同じ誤りになる。これまでの雛形のある文法と同じ扱いである
- 生成器の内部の検査（`a template call must be expanded before generating code`）は残す。展開を経ずに生成器を呼ぶ利用者のための検査である。文言に、`expandTemplates` を先に呼ぶことを加える

## 実装しないこと

- 雛形でない規則を `<...>` で呼ぶことを、引数のない呼び出しとして受け入れること。書き誤りを見逃すことになる
- 「did you mean」のような、近い名前の雛形の候補を示すこと

## テスト設計

先に書き、失敗させてから実装する。

- **展開**：雛形のない文法で、雛形でない規則と、存在しない規則を `<...>` で呼ぶと、それぞれ「rule B is not a template」の誤りになり、位置が呼び出しの位置であること（peg-grammar のテスト）
- **近道**：雛形の定義も呼び出しもない文法は、展開の前後で同じ文法であること。リポジトリのすべての文法で確かめる
- **コマンド**：上の文法で、`peg-hs gen` と `peg-hs lint` が誤りを位置付きで報告し、終了状態が 1 であること。バックトレースを出さないこと（peg-cli のテスト）
- **言語サーバー**：上の文法の診断に、同じ誤りが出ること（peg-lsp のテスト）
- **生成物**：リポジトリのすべての生成物が変わらないこと

## トレードオフ

- 雛形の呼び出しのない文法では、これまでどおり展開を省くので、展開の費用は増えない。呼び出しを探すために文法を一度たどる費用だけが増える
- 近道の条件が二つになるので、展開を省いてよい条件を、テストで固定しておく必要がある
