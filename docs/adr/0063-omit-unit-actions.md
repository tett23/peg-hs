# ADR 0063: 型が () の規則で、値のない選択肢のアクションを省略する

ステータス: 採択→単位の要素が一つの選択肢の値は [ADR 0064](0064-unit-rules-always-return-unit.md)

## 文脈

[ADR 0004](0004-peg-notation.md) は、アクションを省略できるのを、値を持つ要素がちょうど一つの選択肢に限った。
値を持つ要素が 0 個か 2 個以上の選択肢でアクションを省略すると、静的検査の誤りになる。
[ADR 0030](0030-unit-values-are-not-counted.md) は、束縛しない `()` の値（単位の値）を数えないようにしたが、単位でない値が一つもない選択肢では、これまでどおり単位の要素も数える。

そのため、型が `()` の規則でも、次の選択肢はアクションを省略できない。

```text
Sp :: ()
Sp <- ' '*          # 値を持つ要素が 0 個（リテラルの繰り返しは値を持たない）
Kw :: ()
Kw <- 'if' !IdentChar   # 0 個
Gap :: ()
Gap <- Sp Sp        # 単位の要素が 2 個
```

どれも、誤りの文言は「an alternative without an action must have exactly one element with a value」で、`{ () }` を書けば通る。
リポジトリの文法には、`{ () }` が 33 ファイルに 393 か所ある。
その多くは、空白、区切り、キーワードを読む `()` の規則の選択肢の末尾にある。

型が `()` の規則の値は `()` しかありえない。
値のない選択肢に `{ () }` を書かせても、文法の作者が伝える情報は増えない。
一方で、アクションの書き忘れを静的検査が見つけられることには意味がある。
型が `()` でない規則でアクションを書き忘れたら、値を決められないので、これまでどおり誤りにする必要がある。
型注釈によって値の数え方が変わるのは、[ADR 0030](0030-unit-values-are-not-counted.md) と同じ考え方である。

## 実装すること

### アクションの省略の規則

[ADR 0004](0004-peg-notation.md) と [ADR 0030](0030-unit-values-are-not-counted.md) の規則に、次の場合を加える。

- 規則の型注釈が `()`（空白を除いた文字列が `()`。[ADR 0030](0030-unit-values-are-not-counted.md) の判定と同じ）で、選択肢に単位でない値を持つ要素が一つもないとき、その選択肢はアクションを省略でき、値は `()` になる
- この場合、単位の要素はいくつあってもよい。`Sp <- ' '*`、`Kw <- 'if' !IdentChar`、`Gap <- Sp Sp` はどれも書ける
- 束縛した単位の要素（`u:Sp`）は、[ADR 0030](0030-unit-values-are-not-counted.md) のとおり数える。束縛した単位の要素が一つだけなら、これまでどおりその値を返す。二つ以上なら、値は `()` とする。どちらも値は `()` である
- 要素のない選択肢（`S <- 'a' /` の後ろの空の選択肢）は、これまでどおりアクションを省略できない。空の選択肢を書くときは `{ () }` を書く。tree-sitter の文法は空の選択肢を読まないので（[ADR 0045](0045-fixes-before-v0-1-0.md)）、それと合わせる
- 型が `()` でない規則の、値のない選択肢は、これまでどおり誤りになる。誤りの文言は変えない

### 生成

- 省略した選択肢は、要素を値を捨てる文脈（[ADR 0026](0026-discard-unused-values.md)）で生成し、`()` を返す
- `%syntax` の文法では、構文木の子は省略しなかった場合と同じになる
- 雛形（[ADR 0031](0031-rule-templates.md)）の展開した規則は、型の変数を置き換えた後の型注釈で判定する

### リポジトリの文法の書き直し

- リポジトリのすべての文法（記法自身の文法、codegen の fixture、適合性テストの文法、言語サーバーの JSON の文法、エディタのテストの文法、文書の例）から、この規則で省略できる `{ () }` を除く
- 書き直しは機械的に行い、生成し直した生成物と、すべてのテスト（適合性テストを含む）で、受理と値が変わらないことを確かめる
- 記法自身の文法の書き直しは、新しい規則を実装した生成器で一度生成し直せば足りる。記法の構文は変わらないので、[ADR 0027](0027-switch-to-self-hosted-parser.md) の二回に分けた手順は要らない

### lint の notice

省略できる `{ () }` を書くことは、誤りではない。
lint の警告は、誤りである書き方だけに出し、警告が一つでもあれば失敗する（[ADR 0033](0033-grammar-linter.md)）。
そこで、警告とは別に、失敗させない知らせ（notice）の水準を lint に設け、省略できる `{ () }` を知らせる。

- lint に notice の水準を加える。notice は、文法を直すと簡潔になるが、直さなくても誤りではない書き方を知らせる
- notice は、`peg-hs lint` の終了状態を変えない。notice だけなら終了状態は 0 である。警告があれば、これまでどおり 1 である
- 出力は警告と同じ形で、`warning:` の代わりに `notice:` と書く。`G.hpeg:3:13: notice: the action can be omitted: the rule has type () and the alternative has no value [omittable-unit-action]; remove { () }` のようにする
- 規則の名前は `omittable-unit-action` とする。対象は、アクションのコードが空白を除いて `()` であり、上の「アクションの省略の規則」で省略できる選択肢である。位置はアクションの始まりとする
- notice も、警告と同じく選んだり抑えたりできない（[ADR 0033](0033-grammar-linter.md)）。直せば消える
- 言語サーバー（[ADR 0035](0035-language-server.md)）は、notice を診断の重大度 Information として報告する
- `%syntax` の文法でも同じに扱う。構文木の子は省略しても変わらないからである
- lint の偽陽性のテスト（[ADR 0033](0033-grammar-linter.md)、[ADR 0049](0049-lint-false-positive-test-and-expected-sets.md)）は、選択肢やラベルを消す警告を対象とする。notice はアクションを消すだけで、受理する言語を変えないので、その対象にしない

### 文書

- [docs/syntax.md](../syntax.md) の「アクションの省略」の節に、型が `()` の規則の場合を加え、よくある誤りの表の `Unit <- 'unit'` の例を、型が `()` でない規則の例に改める。冒頭の「反映している ADR」にこの ADR を加える
- docs/specifications.md の記法の説明と、README の例（`Sp <- ' '* { () }` など）を新しい形にする
- docs/syntax.md の lint の節と、README の `lint` の説明に、notice の水準と `omittable-unit-action` を書く。docs/specifications.md の lint の説明にも加える
- [ADR 0004](0004-peg-notation.md) のステータスを「採択→型が () の規則のアクションの省略は ADR 0063」に変える

## 実装しないこと

- 整形（[ADR 0032](0032-grammar-formatter.md)）による `{ () }` の自動の削除。整形は字句を変えない
- 省略できる `{ () }` を警告（lint を失敗させるもの）にすること。`{ () }` を書くことは誤りではないので、notice にとどめる
- notice を失敗にするオプション。lint の結果を設定で変えないという [ADR 0033](0033-grammar-linter.md) の方針に従う
- 型が `()` 以外の、情報を持たない型（`data Space = Space` など）や、型の別名（`type Unit = ()`）での省略。[ADR 0030](0030-unit-values-are-not-counted.md) と同じく、型を文字列として扱う
- 要素のない選択肢のアクションの省略

## テスト設計

先に書き、いまの実装で失敗させる。

### 静的検査（peg-grammar）

- 型が `()` の規則で、次の選択肢がアクションなしで誤りにならないこと：リテラルだけ（`' '*`）、リテラルと先読み（`'if' !IdentChar`）、単位の要素が二つ（`Sp Sp`）、意味述語を含む選択肢、束縛した単位の要素が二つ
- 型が `()` でない規則で、値のない選択肢をアクションなしで書くと、これまでと同じ文言の誤りになること
- 型が `()` の規則で、単位でない値を持つ要素が一つある選択肢は、これまでどおりその値を返すので、型の不一致は GHC が報告すること（静的検査は誤りにしない）
- 型が `()` の規則の空の選択肢（`S <- 'a' /`）が、これまでどおり誤りになること
- 型の別名（`type Unit = ()`）の規則では、これまでどおり誤りになること

### 生成と実行（peg-codegen）

- 上の形を含む fixture を加え、生成したモジュールが警告なしでコンパイルでき、`{ () }` を書いた版と受理と最遠の失敗の位置が一致すること（プロパティテスト）
- 同じ fixture に `%syntax` を付けた版で、構文木がロスレスで、`{ () }` を書いた版と同じ子を持つこと
- 雛形の展開した規則の型が `()` になる場合も省略できること

### lint の notice

- 省略できる `{ () }` に `omittable-unit-action` の notice が出て、位置がアクションの始まりであること。型が `()` でない規則の `{ () }`、単位でない値を持つ選択肢の `{ () }`、空の選択肢の `{ () }`、コードが空白を除いて `()` でないアクション（`{ pure () }` など）には出ないこと。`{ ( ) }` のように空白を含む `()` には出ること
- notice だけの文法で `peg-hs lint` の終了状態が 0 で、標準エラーに `notice:` の行を出すこと。警告と notice がある文法では終了状態が 1 であること
- 出力の golden（[ADR 0033](0033-grammar-linter.md) の警告の文言の golden）に notice を加えること
- 言語サーバーの診断で、notice の重大度が Information であること
- notice に従ってアクションを消した文法が、元の文法と同じ受理と値を返すこと（上の生成と実行のプロパティテストで確かめる）

### 書き直した文法

- 書き直したリポジトリの文法に、`omittable-unit-action` の notice が一つもないこと（peg-grammar のテスト）
- 書き直したリポジトリの文法で、すべてのテスト（適合性テスト、生成物の一致、範囲の一致、整形、lint）が通ること。範囲の一致の golden（[ADR 0034](0034-syntax-highlighting.md)）は、アクションの範囲が減るので作り直す
- tree-sitter の文法が、書き直した文法を `ERROR` なしで読むこと
- 書き直す前と後で、適合性テストの結果（JSON、TOML、Lua、CommonMark の件数）が変わらないこと

## トレードオフ

- 型注釈を `()` から別の型に変えると、アクションを省略した選択肢が誤りになる。そのときは静的検査が位置を示すので、アクションを書き足せばよい。[ADR 0030](0030-unit-values-are-not-counted.md) のトレードオフと同じ種類の依存である
- 値のない選択肢の書き方が二通りになる（`{ () }` を書くか書かないか）。どちらも同じ意味である。lint は省略できる `{ () }` に notice を出し、リポジトリの文法は省略する形にそろえる
- lint に、失敗させない水準が加わる。これまで lint の出力は、どれも直さなければ失敗する警告だった。notice を見落としても困らないが、CI のログの中で警告と見分けられるよう、`notice:` と書き分ける
- リポジトリの文法の書き直しで、生成物の差分が大きくなる。書き直しを、規則の実装とは別のコミットにする
- 要素のない選択肢は省略できないので、規則が一つだけ例外を持つ。tree-sitter の文法が空の選択肢を読まないこと（[ADR 0045](0045-fixes-before-v0-1-0.md)）と食い違わないためである
