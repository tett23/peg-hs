# ADR 0004: .peg 記法を確定する

ステータス: 採択

## 文脈

peg-grammar の実装には記法の確定が先行する。
束縛の方法、アクション省略時の挙動、ヘッダの書式、コメント記法の四点が主な決定であり、いずれも後から変えると既存の文法ファイルを壊す。

位置参照（happy の `$1 $2`）は PEG では採らない。
PEG の逐次には値を持たない述語（`&` `!`）やリテラルが混ざるため「何番目か」の数え方が曖昧になり、文法の編集で番号がずれるためである。

## 実装すること

### ファイル構造

`.peg` ファイルは、ディレクティブと verbatim ブロックの列、続いて規則の列からなる。

- `%module A.B.C`：生成モジュール名。必須
- `%start Name`：開始規則。省略時は最初に定義された規則
- `%{ ... }%`：生成モジュールへ丸写しする Haskell コード（import、補助関数）。複数書けるものとし、出現順に連結して生成モジュールの import 位置以降に置く
- コメントは `#` から行末まで。リテラル、文字クラス、アクションの内側では無効

### 規則

規則は型注釈と定義の組で書く。

```
Name :: Type
Name <- 選択肢 / 選択肢 / ...
```

型注釈の `::` の右は行末までを Haskell の型として丸写しする。
型注釈のない規則は静的検査でエラーとする。

### 式

Ford の標準構文をすべて受理する。
結合の強さは、接尾辞（`*` `+` `?`）が最も強く、次に接頭辞（`&` `!` `$`）、逐次、選択 `/` の順とする。
`$[0-9]+` は `$(([0-9])+)` と読む。

- リテラルは `'...'` と `"..."` の両方を許す
- 文字クラスは `[a-z0-9]` の形。エスケープは `\n` `\t` `\r` `\\` `\'` `\"` `\]` `\[` `\-` と `\u{XXXX}` を許す
- `.` は Unicode コードポイント一つに一致する。文字クラスもコードポイント単位で解釈する

### 束縛と値

- 束縛は `名前:式` の形で、選択肢の逐次の直下にのみ書ける。名前は Haskell の小文字識別子
- 値を持つのは、非終端（その規則の型）、`$e`（消費した入力の `Text`）、およびそれらに接尾辞を付けたもの（`e*` `e+` は `[a]`、`e?` は `Maybe a`）である
- リテラル、文字クラス、`.`、述語は値を持たない。値を持たない式への束縛は静的検査でエラーとする
- 括弧グループの値は、内側の逐次が値をちょうど一つ持つときその値とし、それ以外は値なしとする。グループ内の束縛は外から見えない

### アクション

- 各選択肢は末尾に `{ Haskell 式 }` のアクションを持てる。式は選択肢内の束縛名を参照できる
- アクションの読み取りは波括弧の釣り合いを数えて行い、Haskell の文字列・文字リテラル内の波括弧は数えない
- アクションを省略した選択肢は、値を持つ要素（束縛の有無を問わない）がちょうど一つのときその値をそのまま返し、それ以外は静的検査でエラーとする。`/ Term` の形はこの規定により動く

## 実装しないこと

- 位置参照（`$1` `$2`）は実装しない
- 負の文字クラス `[^...]` は実装しない。`![a-z] .` の形で書く
- 大文字小文字を無視するリテラル（PEG.js の `"abc"i`）は実装しない
- 回数指定の繰り返し `e{n,m}` は実装しない
- アクション内の Haskell ブロックコメント `{- -}` は波括弧走査の対象外とし、含まれていた場合の動作は保証しない
- 失敗ラベルの構文はこの ADR では定めない（別の ADR で扱う）

## テスト設計

- **記法のゴールデンテスト**：代表的な `.peg` ファイル群に対する文法 AST のスナップショット
- **静的検査**：値を持たない式への束縛、同一選択肢内の束縛名の重複、アクション省略と値の個数の不整合（0 個と 2 個以上）、型注釈のない規則、未知のディレクティブ、のそれぞれがエラーになること
- **アクション走査**：波括弧を含む文字列リテラル入りのアクション（`{ pack "{" }` など）が正しく読めること
- **Unicode**：コードポイント境界（サロゲートペア相当の文字、結合文字列）で `.` と文字クラスが一文字を正しく数えること
- **コメント**：`#` がリテラル・文字クラス・アクションの内側で無効であること

## トレードオフ

- コメント記法 `#` は、同一ファイルに埋まる Haskell 断片の `--` と流儀が混在する。PEG 論文および他言語の PEG ツール（PEG.js、pest）との移植性を優先した
- 波括弧の釣り合いによるアクション走査は Haskell の完全な字句解析ではない。ブロックコメントという既知の穴は上記の通り仕様外として明記する
- 束縛を逐次直下に限定したため、深い入れ子から値を取り出すには規則を分割する必要がある。規則の分割はメモ化の単位を細かくする方向に働くため、許容できる制約と判断した
