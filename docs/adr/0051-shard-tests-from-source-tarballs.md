# ADR 0051: ソースのアーカイブからのテストを --shard で分ける

ステータス: 採択

## 文脈

[ADR 0046](0046-docs-cli-and-ci-before-v0-1-0.md) は、CI の package のジョブを haddock と sdist の二つに分け、sdist のジョブでソースのアーカイブからテストも動かすようにした。
その後の計測（[2026-10-13-ci-split-package.md](../benchmarks/2026-10-13-ci-split-package.md)）で、ワークフロー全体は 2 分 4 秒から 2 分 58 秒に延びた。
時間を決めているのは sdist のジョブ（174 秒）である。

sdist のジョブの段の 138 秒は、アーカイブからのビルドとテストからなる。
テストのスイートが報告した時間の合計は約 79 秒で、このうち 65 秒が peg-grammar-test だった。
リポジトリのテストのジョブでは、peg-grammar-test を `--shard` で三つのジョブに分けている（[ADR 0042](0042-shard-peg-grammar-test.md)）。
アーカイブのテストだけは、分けずに一つのジョブで動かしている。

アーカイブでテストする目的は、公開する各パッケージが、アーカイブの中のファイルだけでビルドでき、テストが通ることを確かめることである（[ADR 0009](0009-hackage-publication.md)）。
事例の数を減らすと、リポジトリのテストとアーカイブのテストで確かめる範囲が変わる。
[ADR 0042](0042-shard-peg-grammar-test.md) と同じく、事例の数は変えずに、テストを複数のジョブに分ける。

## 実装すること

### sdist のジョブを三つに分ける

- sdist のジョブを、`sdist-1` から `sdist-3` の三つのジョブ（matrix）にする
- 各ジョブは、五つのパッケージのアーカイブを作って展開し、すべてをビルドする。ここまでは、いまの sdist のジョブと同じである
- 各ジョブは、peg-grammar-test を `--shard i/3`（`i` はジョブの番号）で動かす。`--shard` は peg-grammar-test の独自のオプションなので、このスイートだけに渡す
- peg-runtime、peg-codegen、peg-lsp、peg-cli のテストは、三つのうち一つのジョブ（`sdist-2`）でまとめて動かす。リポジトリの計測で、`--shard 2/3` が最も短かったためである（[計測](../benchmarks/2026-10-13-ci-shard-grammar.md)）
- 飛ばしたテストの報告（[ADR 0046](0046-docs-cli-and-ci-before-v0-1-0.md)）は、各ジョブで行う

### 文書

- CONTRIBUTING（日本語と英語）の CI のジョブの説明を改める

## 実装しないこと

- アーカイブのテストの事例の数を減らすこと。リポジトリのテストと確かめる範囲を同じに保つ
- アーカイブのビルドの成果物をジョブの間で共有すること、またはキャッシュすること。ビルドは各ジョブで約 60 秒かかるが、アーカイブを展開したファイルは毎回新しく、ビルドの成果物を当てられるかを確かめる必要がある。三つに分けても足りなければ、別の ADR で検討する
- peg-grammar-test のほかのスイートのシャーディング

## テスト設計

自動テストは書けないので、実装の後に動かして確かめる。

- 三つの sdist のジョブのログに出る peg-grammar-test のテストの名前を合わせると、分ける前の sdist のジョブのテストの一覧と一致すること
- peg-runtime、peg-codegen、peg-lsp、peg-cli のテストが、`sdist-2` で一度ずつ動くこと
- 飛ばしたテストの数の合計が、分ける前と同じ（29 件）であること
- すべてのキャッシュが当たる実行で、ワークフロー全体が 2 分 58 秒より短くなること。各 sdist のジョブの時間と、ワークフローの時間を決めるジョブを `docs/benchmarks/` に記録する

## トレードオフ

- ジョブが二つ増え、それぞれでアーカイブのビルド（約 60 秒）と準備（約 35 秒）を繰り返す。合計の計算時間は増えるが、[ADR 0041](0041-split-test-jobs-and-cores.md) と同じく、待つ時間を減らすことを優先する
- ビルドを各ジョブで繰り返すので、sdist のジョブは、ビルドと準備の約 95 秒より短くならない。ワークフローの時間は、sdist のジョブと test-conformance のジョブ（約 111 秒）のどちらか長いほうで決まると見込む
- peg-grammar-test 以外のスイートを `sdist-2` に集めるので、三つのジョブの時間は偏りうる。計測で偏りを確かめ、必要なら置き場所を変える
