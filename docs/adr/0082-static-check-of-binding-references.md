# ADR 0082: 束縛の参照を生成の前に検査する

ステータス: 採択→群の内側の束縛の見え方は [ADR 0083](0083-bindings-inside-a-group-are-not-visible.md)

## 文脈

[ADR 0003](0003-typed-semantic-actions.md) は、アクションが参照する束縛名が選択肢の中にない場合に、生成の前の静的な検査で誤りにすると決めた。
[ADR 0012](0012-context-sensitive-extensions.md) は、意味述語と規則の呼び出しの引数が参照できる束縛を、同じ逐次の中で左にあるものに限り、右にある束縛の参照を静的な誤りにすると決めた。

どちらの検査も、実装されていない。
今は、GHC のコンパイルの誤りに任せている。
たとえば次の文法は、`gen` を通る。

```text
%module H
S :: Int
S <- &{ y > 0 } y:N { y }
N :: Int
N <- $[0-9] { 1 }
```

生成したモジュールを GHC でコンパイルすると、`H.hpeg:3:9: error: [GHC-88464] Variable not in scope: y` になった。
`LINE` プラグマ（[ADR 0014](0014-generated-module-api.md)）のおかげで、誤りは文法の位置を指す。
群の内側の束縛をアクションで参照する文法（`S <- (y:N) { y }`）、ほかの選択肢の束縛を参照する文法（`S <- x:N { x } / M { x }`）、引数が右の束縛や自分の束縛を参照する文法（`S <- x:A(y) y:B { x }`、`S <- x:A(x) { x }`）も、`gen` を通り、GHC が `Variable not in scope` を出した。
束縛と同じ名前を文字列の中にだけ書いた文法（`S <- x:N { length "y" + x }`）は、コンパイルも通った。
しかし、言語サーバー（[ADR 0035](0035-language-server.md)）と wasm のプレイグラウンド（[ADR 0078](0078-grammar-analysis-in-wasm.md)）は生成したモジュールをコンパイルしないので、この誤りは出ない。
文法を書いている途中では、誤りに気付けない。

[ADR 0081](0081-missing-tests.md) を書くための照合で、この二つの検査がないことがわかった。
作業者の指示で、検査を実装する。

検査するには、アクション、意味述語、引数の Haskell のコードの中で、どの名前が参照されているかを知る必要がある。
生成器は Haskell の構文を理解しない方針である（[ADR 0014](0014-generated-module-api.md)）。
lint の `unused-binding`（[ADR 0033](0033-grammar-linter.md)）は、コードを識別子に使えない文字で区切って名前を拾っている。
文字列やコメントの中の名前も拾うが、lint の警告にとっては「使っている」と見なす側にずれるだけなので、偽陽性は出ない。
誤りにする検査では、同じずれが、正しい文法を拒む偽陽性になる。
そこで、識別子の字句だけを正しく読む小さな字句解析を書く。
Haskell の構文の解析ではなく、字句の水準の読み取りである。

もう一つの限界がある。
アクションのコードは、束縛のほかに、Prelude、import した名前、verbatim ブロックで定義した名前も参照する。
生成器はそれらの名前を知らない。
そのため、「選択肢の中に束縛がない名前」をすべて誤りにすることはできない。
検査できるのは、その規則のどこかで束縛されている名前が、参照した位置からは見えない場合だけである。

## 実装すること

### 見える束縛と見えない束縛

コードの位置から見える名前は、生成したコードで GHC が見る名前と同じである。

- 規則の引数
- 予約束縛（`_env`、`_col` など、[ADR 0012](0012-context-sensitive-extensions.md)）
- アクションからは、選択肢の逐次の直下の束縛すべて
- 意味述語と引数からは、同じ逐次の中でその位置より左にある束縛と、外側の逐次の中で群より左にある束縛

規則の中で束縛されているのに、その位置から見えない名前を参照したら、誤りにする。
見えない束縛は、次の三つである。

- 意味述語か引数の位置より右にある束縛。自分の束縛（`x:A(x)` の引数の `x`）も含む。誤りは `the predicate refers to x, which is bound to its right` か `the argument refers to x, which is bound to its right` とする。
- 群の内側の束縛を、群の外から参照する。誤りは `x is bound inside a group, which the code cannot see` とする。
- 同じ規則のほかの選択肢の束縛を参照する。誤りは `x is not bound in this alternative` とする。

誤りの位置は、コードの中の名前の位置とする。

規則の中で束縛されていない名前は検査しない。
束縛かどうかを決められないからである。

### 識別子の字句の読み取り

`Peg.Grammar` に、Haskell のコードから参照している変数名とその位置を取り出す関数を置く。
読み取りは、次のものを飛ばす。

- 文字列のリテラル（`"..."`、エスケープを含む）と文字のリテラル（`'a'`、`'\n'`）。識別子の途中の `'`（`x'`）と区別する。
- 行のコメント（`--` から行末まで。`-->` のような演算子は除く）と、入れ子のブロックのコメント（`{- ... -}`）。
- 修飾した名前（`M.x`、`Data.Map.lookup`）。修飾の部分が大文字で始まる。
- レコードのフィールドの選択（`r.x`）。`.` の前に空白がない。

バッククォートで囲んだ名前（`` `div` ``）は、参照として数える。
Template Haskell の引用と準引用は扱わない（下の「実装しないこと」）。

lint の `unused-binding` も、この読み取りに置き換える。
文字列とコメントの中の名前を使っていると見なさなくなるので、警告が増える場合がある。
これは今の偽陰性が消えるだけなので、lint の偽陽性はない（[ADR 0033](0033-grammar-linter.md) の方針）。

### どこで動くか

検査は `Peg.Grammar.Check.check` に入れる。
`gen`、`parse`、言語サーバー、wasm の `analyze` が、ほかの検査の誤りと同じく報告する。
`docs/syntax.md` の束縛の節の誤りの表に三つの誤りを足し、冒頭の「反映している ADR」の一覧にこの ADR を足す。
`docs/specifications.md` の検査の項にも書く。

## 実装しないこと

- 規則の中で束縛されていない名前の検査。Prelude、import、verbatim ブロックの名前と区別できない。この場合は、今までどおり GHC が `Variable not in scope` で報告する。
- Haskell の構文の解析。読み取るのは識別子の字句だけである。
- Template Haskell の引用（`[| ... |]`）と準引用（`[q| ... |]`）の中の名前。中身を通常のコードとして読むので、まれに誤りが出る。
- `_col` をアクションで参照するような、予約束縛を使える場所の検査（[ADR 0012](0012-context-sensitive-extensions.md)）。この ADR の範囲は、利用者の束縛の参照だけである。

## テスト設計

先に書いて失敗させてから実装する。

- 誤りになるもの（`packages/peg-grammar/test/Main.hs`）
  - 述語が右の束縛を参照する（`S <- &{ y > 0 } y:N { y }`）。誤りの位置は述語の中の `y` である。
  - 引数が右の束縛か自分の束縛を参照する（`S <- x:A(y) y:B`、`S <- x:A(x)`）。
  - アクションが群の内側の束縛を参照する（`S <- (y:N) { y }`）。
  - アクションが同じ規則のほかの選択肢の束縛を参照する（`S <- x:N { x } / M { x }`）。
  - テンプレートの値の引数が右の束縛を参照する。
- 誤りにならないもの
  - 述語が左の束縛と外側の左の束縛を参照する（`S <- x:N (y:N &{ x > 0 && y > 0 })*`）。
  - 規則の引数と予約束縛の参照。
  - 束縛と同じ名前が、文字列、文字のリテラル、行のコメント、入れ子のブロックのコメント、修飾した名前、フィールドの選択、識別子の一部（`y'`、`ys`）にだけ現れる。
  - 規則の中で束縛されていない名前（`show`、verbatim ブロックの関数）。
  - リポジトリのすべての文法（conformance、フィクスチャ、自己記述の文法、`docs/syntax.md` の文法）。
- 識別子の字句の読み取り（`packages/peg-grammar/test`）
  - 上の飛ばすものの境界（エスケープした引用符を含む文字列、`'\''`、`-->`、`{- {- -} -}`、`M.x`、`r.x`、`` `div` ``）。
  - 無作為の Haskell の式の断片で、取り出した位置の名前が、元のテキストのその位置の部分文字列に等しい。
- GHC との一致（`packages/peg-codegen/test`）
  - 誤りになる例の文法を検査なしで生成すると、GHC のコンパイルが `Variable not in scope` で失敗することを確かめる。誤りにならない例は、コンパイルが通ることを確かめる。生成器の内部の関数で検査を通さずに生成するか、検査を外した生成物をフィクスチャとして持つかは、実装で決める。
- 言語サーバーと wasm（`packages/peg-lsp/test`、`wasm/test`）
  - 述語が右の束縛を参照する文法を開くと、その位置の診断が返る。wasm の `analyze` も同じ診断を返す。
- lint（`packages/peg-grammar/test`）
  - 束縛の名前が文字列の中にだけ現れるとき、`unused-binding` の警告が出る。リポジトリの文法の lint の結果は変わらない。

## トレードオフ

- 束縛と同じ名前の大域の関数を、束縛より左の述語で参照すると、誤りになる。GHC は大域の関数として受け入れる書き方なので、これは偽陽性である。束縛の名前を変えれば避けられる。束縛の名前と大域の関数の名前を重ねる書き方はまれだと判断した。
- 字句の読み取りは、Haskell の字句の規則の一部しか実装しない。読み取りが誤ると、偽陽性か偽陰性になる。偽陰性の場合は、今までどおり GHC が報告する。
- lint の `unused-binding` の警告が増える文法がありうる。文字列の中の名前を使っていると見なしていたのは誤りなので、受け入れる。
