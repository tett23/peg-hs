# ADR 0027: 記法の既定のパーサーを自己記述のパーサーに切り替える

ステータス: 採択

## 文脈

仕様書の設計原則は、`.peg` 記法のパーサーを、記法が安定した段階で peg-hs 自身で生成したパーサーに置き換えるとしている。
ADR 0015 は、切り替えの条件を「CommonMark の全件適合を含むすべての検査に合格した後」とした。
CommonMark の 652 件の全件適合（ADR 0018）、Lua（ADR 0022）と TOML（ADR 0023）の適合性テストを含め、この条件は満たされた。
識別子と空白を Unicode に広げる差（ADR 0020）も解消済みである。

切り替えの準備として、二つのパーサーの差を測った。
差は三つあった。

### 受理する言語の差

リポジトリの文法 18 個（JSON、Lua、TOML の文法、自己記述の文法、codegen の fixture 14 個）のそれぞれについて、7 文字おきの位置で一文字を削除した入力と、一文字を重複させた入力を作った。
計 9,828 個の入力を二つのパーサーに与えた。

| 結果 | 件数 |
|---|---:|
| 両方が受理し、文法の AST が異なる | 0 |
| 受理と拒否が分かれる | 62 |

分かれた 62 件は、すべて自己記述のパーサーだけが受理していた。
手書きのパーサーの拒否の理由で分類すると、次のとおりである。

| 手書きのパーサーの誤り | 件数 |
|---|---:|
| 文字クラスの範囲が空（`[b-a]`） | 50 |
| アクションの Haskell の断片の中の閉じていない文字列リテラル | 10 |
| アクションの Haskell の断片の中の閉じていない文字リテラル | 1 |
| 規則の呼び出しの空の引数（`B()`） | 1 |

自己記述のパーサーはこれらの入力を受理し、壊れた文法を生成器に渡す。
空の範囲は何にも一致しない文字クラスになり、閉じていない文字列は生成コードのコンパイルの誤りになる。
いまの移行テスト（ADR 0015）は、リポジトリの文法と少数の断片だけを比べており、この差を検出していなかった。

### 誤りの報告の差

手書きのパーサーは、誤りの種類ごとに文言を持つ。
自己記述のパーサーは、最遠位置と期待集合（ADR 0005）だけを報告する。

| 入力の誤り | 手書きのパーサー | 自己記述のパーサー |
|---|---|---|
| `'a { 1 }`（閉じていないリテラル） | 3:14: unterminated literal | 3:14: expected '\\'', '\\\\' or '\\\\u{' |
| `A :: ` の後に型がない | 2:6: expected a type | 2:6: expected [ \\t] |
| `( 'a' { 1 }`（グループの中のアクション） | 3:12: actions are not allowed inside a group | 3:12: expected '!', '"', '#', '$', '&', '(', ')', '.', '/', '[', '\\'', '^' or [*+?] |
| `'\q'`（未知のエスケープ） | 3:7: unknown escape \\q | 3:8: expected [ntr\\\\'"\\]\\[\\-] |
| 閉じていない `%{` | 5:1: unterminated %{ block | 5:1: expected '}%' or any character |
| `A(x) <- ...`（定義に引数を書いた） | 3:3: expected a parameter of the form name :: Type | 3:4: expected '"', '(', ',', '[', '\\'' or '{' |

期待集合は文法の終端の一覧であり、記法の利用者には読みにくい。
ラベル付きの失敗（ADR 0021）は、この種の報告を規則の作者の言葉にするためにある。
自己記述の文法にラベルを付ければ、手書きのパーサーの文言を保てる。

### 速度の差

各文法の解析時間（20 回の平均）は次のとおりだった。

| 文法 | 文字数 | 手書き | 自己記述 |
|---|---:|---:|---:|
| `conformance/json/Json.peg` | 2,572 | 2.1 ms | 2.5 ms |
| `packages/peg-grammar/grammar/Peg.peg` | 6,525 | 5.1 ms | 8.3 ms |
| `conformance/lua/Lua.peg` | 9,384 | 1.7 ms | 17.9 ms |
| `conformance/commonmark/Block.peg` | 15,081 | 20.2 ms | 24.4 ms |

自己記述のパーサーは 1.2〜10 倍遅い。
文法ファイルは小さく、最も遅い場合でも 20 ms に満たない。

## 実装すること

### 段階 1：差をなくす

手書きのパーサーを残したまま、自己記述のパーサーを手書きのパーサーに合わせる。

- **受理する言語**：上の四つの誤りを、自己記述のパーサーでも拒否する。文字クラスの範囲と規則の引数は、意味述語（ADR 0012）で検査する。Haskell の断片の中の文字列リテラルと文字リテラルは、手書きのパーサーと同じ規則で読む
- **誤りの文言**：手書きのパーサーが文言を持つ位置に、自己記述の文法でラベルを付ける。`parseGrammarSelfHosted` は、送出されたラベル（`parseErrorLabel`）を手書きのパーサーの文言に対応させる。対応表は `Peg.Grammar.Parser` に置く。ラベルが送出されずに失敗した場合は、これまでどおり期待集合を報告する
- **ラベルの位置**：ラベルは、そこで失敗したらどの選択肢でも成功しえない位置にだけ付ける（ADR 0021）。そのような位置がなく、文言を保てない誤りは、その旨をテストに記録する

### 段階 2：切り替える

- `parseGrammar` を自己記述のパーサーにする。`parseGrammarSelfHosted` は公開しない
- 手書きのパーサーを削除する。二つのパーサーを残すと、記法を変える ADR のたびに両方を直すことになり、自己記述化の目的に反する
- ADR 0015 が「今後」とした、ベンチマークの計測対象を自己記述のパーサーに替える。`parseGrammar` が自己記述のパーサーになるので、ベンチマークの本体は変わらない

### 自己記述の文法を変える手順

自己記述のパーサーは、`grammar/Peg.peg` から peg-hs 自身で生成し、コミットしたもの（`SelfHosted.hs`）である。
記法に新しい構文を加えて、その構文を `Peg.peg` 自身で使う場合は、二回に分けて生成する。

1. 新しい構文を受理する規則を `Peg.peg` に加え、新しい構文は使わずに再生成する
2. 再生成した生成器で、新しい構文を使う `Peg.peg` を再生成する

この手順を README の開発の節に書く。

## 実装しないこと

- 自己記述のパーサーの速度の改善。文法ファイルは小さく、20 ms を超える例がない
- `.peg` ファイルのための回復（ADR 0021 の回復する入口を使う `.peg` の LSP）。別に ADR を起こす
- 手書きのパーサーを、試験の比較の相手として残すこと。段階 1 の差の検査は、削除の前に済ませる
- 誤りの文言の改善。段階 1 は手書きのパーサーの文言をそのまま保つ

## テスト設計

### 段階 1

- **受理する言語の一致**：CommonMark の文法を含むリポジトリのすべての文法から作った一文字の削除と重複のすべて（上の 9,828 件と同じ作り方）で、二つのパーサーの受理と拒否が一致し、受理した場合は文法の AST が一致すること
- **誤りの文言**：手書きのパーサーが利用者に報告する文言のそれぞれについて、その文言を出す入力を一つ以上用意する。二つのパーサーの報告（文言と行と桁）が一致すること。一致させられない場合は、自己記述のパーサーの報告を記録し、その理由を書く
- **誤りの文言の golden**：上の入力に対する手書きのパーサーの報告を golden ファイルに書き出す。段階 2 では、この golden を自己記述のパーサーの検査に使う

### 段階 2

- **誤りの文言**：段階 1 の golden ファイルと、自己記述のパーサーの報告が一致すること
- **自己記述の不動点**：`Peg.peg` を自己記述のパーサーで解析して生成した `SelfHosted.hs` が、コミット済みのものとバイト単位で一致すること（既存の生成物の一致の検査）
- **既存の検査**：すべての生成物の一致の検査と、すべてのテストスイートが通ること

## 実装の段階

ADR 0026 の後に行う。
ADR 0013 の段階の順では、自己記述化（段階 11）の完了にあたる。
本 ADR を採択するとき、仕様書の設計原則とモジュール構成の「当初は手書き」の記述を更新する。

## トレードオフ

- 手書きのパーサーを削除すると、自己記述のパーサーが壊れたときに比べる相手がなくなる。生成物の一致の検査と誤りの文言の golden が、その代わりになる。壊れた `SelfHosted.hs` をコミットした場合は、git の履歴から前の版を戻して再生成する
- ラベルを使った誤りの文言は、ラベルを付けた位置でしか出ない。手書きのパーサーが任意の場所で出せた文言のうち、ラベルで再現できないものは、期待集合の報告に置き換わる
- 自己記述のパーサーは、手書きのパーサーより最大で 10 倍遅い。`.peg` の解析は生成の時に一度だけ行われるので、利用者が気づく大きさではないと見込む
