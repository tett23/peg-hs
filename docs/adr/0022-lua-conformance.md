# ADR 0022: Lua 5.5 の文法で左再帰を実用の規模で検証する

ステータス: 採択→意味の誤りとした変異の扱いは [ADR 0025](0025-lua-toml-implementation-deviations.md)

## 文脈

[ADR 0010](0010-json-conformance.md) のトレードオフに「JSON の合格は [ADR 0001](0001-bounded-left-recursion.md) の機構について何も保証しない。左再帰の実用文法での検証は別に要る」と書いた。
この検証は、まだ行っていない。
CommonMark（[ADR 0011](0011-commonmark-expressiveness-probe.md)）の文法も、左再帰をほとんど使わない。
左再帰を検査しているのは、機構の単位のテストと、codegen の小さな fixture（Arith、Calc）だけである。

Lua はこの検証に向いている。
マニュアルの完全な構文は、左再帰をそのまま含む。

```
prefixexp ::= var | functioncall | '(' exp ')'
var ::= Name | prefixexp '[' exp ']' | prefixexp '.' Name
functioncall ::= prefixexp args | prefixexp ':' Name args
```

三つの規則は、互いを経由した間接の左再帰になっている。
Medeiros らの論文が間接の左再帰の例に挙げる形（`L <- P '.x' / 'x'`、`P <- P '(n)' / L`）と同じで、それを実在の言語の規模にしたものである。
二項演算子は、優先順位が 12 段ある。
`..` と `^` は右結合で、単項演算子は `^` より弱く、`^` の右の項には単項演算子が付く（`-a^b` は `-(a^b)`、`2^-3` は受理）。

Golem にとっても意味がある。
Golem の式の言語は、呼び出しと `a.b` を最も強く結合する左結合の後置の演算子として持つ。
これは Lua の `prefixexp` と同じ形の左再帰である。
Lua の文法が規模を持って通れば、Golem の式の文法を左再帰のまま書けるという根拠になる。

文脈依存の性質も、検査の材料になる。
長括弧 `[==[ ... ]==]` は、開きの `=` の数と閉じの数が一致しなければならない。
CommonMark のコードフェンスと同じく、パラメータ付きの規則（[ADR 0012](0012-context-sensitive-extensions.md)）の検査になる。
Lua 5.5 の `global` は文脈で決まる語でもある。
手元の参照実装（mise で入れた 5.5.1）は `LUA_COMPAT_GLOBAL` を有効にしてビルドされている。
`global x = 1` は宣言として読まれ、`local global = 1` も `x = global` も受理される。

版は 5.5.1 とする。
2026-10-12 時点の最新の版であり、手元の参照実装と同じ版である。
公式のテストスイート（lua-5.5.1-tests）は 34 個の `.lua` ファイル、約 18,000 行からなる。
どのファイルも正しい Lua のプログラムであり、誤ったコードは `load` に渡す文字列の中にしか現れない。
したがって、テストスイートだけでは受理の側しか検査できない。
拒否の側と、構造（優先順位と結合性）の側は、参照実装から正解を作って補う。
[ADR 0018](0018-tab-partial-consumption.md) で commonmark.js の出力を参照の正解として取り込んだのと同じ方法である。

## 前提

- 左再帰（[ADR 0001](0001-bounded-left-recursion.md)、[ADR 0013](0013-roadmap-toolchain-memo.md)）、パラメータ付きの規則と意味述語（[ADR 0012](0012-context-sensitive-extensions.md)）が実装済みであること
- 正解を作るときだけ Lua 5.5.1 の参照実装が要る。テストの実行には要らない。正解はコミットする

## 実装すること

### 配置

- `conformance/lua/` に文法と生成物を置く。JSON と CommonMark と同じく `peg-conformance` に入れる
- テストスイートを `conformance/data/lua-5.5.1-tests/` に取り込む。`.lua` ファイルだけを取り込み、`libs/` と `ltests/`（C のソース）は取り込まない
- テストスイートは「See Copyright Notice in file lua.h」とだけ書いている。lua.h の著作権表示（MIT）を同じディレクトリに LICENSE として置き、取り込んだ版と取得元の URL を SOURCE に記す

### 文法

- マニュアルの「The Complete Syntax of Lua」を、できるだけそのまま書く。とくに `prefixexp`、`var`、`functioncall` の三つの規則は、間接の左再帰のまま書く。書き換えが必要になった場合は、書き換えた箇所と理由を記録する（[ADR 0011](0011-commonmark-expressiveness-probe.md) の失敗分類と同じ扱い）
- 二項演算子は、優先順位の段ごとに一つの規則とする。左結合は左再帰（`Add <- Add "+" Mul / Mul` の形）で書き、右結合（`..`、`^`）は右再帰で書く
- 文としての式は、呼び出しだけを受理する。`a.b` だけの文は構文エラーになる。マニュアルのとおり `stat` の選択肢に `functioncall` を置くと、この規則は文法の構造から出てくる
- 長括弧の文字列と長いコメントは、開きの `=` の数を引数に取るパラメータ付きの規則で閉じを照合する
- 字句の規則は参照実装の字句解析器に合わせる
  - 数は `[0-9A-Za-z._]` と指数の符号の最長の並びを一つの字句として切り出し、その字句が数の形かを意味述語で判定する。参照実装と同じく、`1..2` は数の誤りとして拒否する
  - 文字列のエスケープ（`\z`、`\xXX`、`\ddd`、`\u{XXX}`）の形と範囲を検査する。`\ddd` は 255 まで、`\u{XXX}` は 2^31 未満とする
  - 名前は ASCII の英字、数字、`_` に限る。参照実装の C ロケールでの判定と同じである
- 予約語は名前として受理しない。`global` だけは、手元の参照実装と同じく文脈で決まる語として扱う。文の先頭で、後ろに名前、`<`、`*`、`function` のいずれかが続く場合だけ宣言として読む
- 文法は `%syntax` を付けて書き、型付きの値と構文木の両方の入口を生成する

### 入力の読み方

- ファイルはバイト列として読み、各バイトを同じ値のコードポイントに写して `Text` にする（Latin-1 としての復号）。Lua のソースはバイト列であり、テストスイートの `strings.lua` は UTF-8 として正しくないバイトを含むためである
- 1 行目が `#` で始まる場合は、その行を読み飛ばしてから解析する。これは言語の構文ではなく、参照実装の `luaL_loadfilex` が行う処理である。`all.lua` と `main.lua` が該当する。`load` に渡す文字列ではこの読み飛ばしは行わないため、拒否の正解の照合でも行わない

### AST と正規形

- AST は `peg-conformance` に定義する。文、式、関数本体、テーブルの構築子を区別する
- 式の AST から、構造を表す S 式の正規形を作る関数を用意する。形は次の「構造の正解」に合わせる。たとえば `a.b(c)[d]` は `(idx (call (idx a b) c) d)`、`a:b(c)` は `(call (idx a b) a c)` になる

### 構造の正解

優先順位と結合性を、参照実装に解析させた結果と比べる。
二つの方法を併用する。
どちらの方法も、正解を作るスクリプトを `conformance/lua/golden/` に置き、正解とスクリプトの両方をコミットする。

- **メタメソッドによる追跡**：葉をすべて名前とする式を無作為に作る。参照実装の側では、名前をメタテーブルを持つ表に束縛する。算術、ビット演算、連結、単項の `-` と `~`、`#`、添字、呼び出しの各メタメソッドが、自分の構造を表す S 式の文字列を返す。式を評価すると、参照実装が解析した木の形が S 式として得られる。この方法で、上位の 9 段（`|`、`~`、`&`、シフト、`..`、加減、乗除、単項、`^`）と後置の演算子を検査する。葉を名前に限るのは、数の定数どうしの部分式が定数畳み込みで値に変わり、構造が見えなくなるためである
- **評価による比較**：`or`、`and`、比較演算子はメタメソッドで構造を取り出せない（`and` と `or` は上書きできず、比較の結果は真偽値に変換される）。この 3 段と `not` は、小さな整数、`true`、`false`、`nil`、加減、比較、`and`、`or`、`not` からなる式を無作為に作り、参照実装で評価した値を正解とする。型の誤りによる実行時エラーも正解として記録する。テストの側は、AST を評価する小さな評価器（`peg-conformance` に置く）で同じ値かエラーになることを確かめる。構造を誤って解析すると、値が変わるか、型の誤りの有無が変わる

追跡の方法が使えることは、手元の参照実装で確かめた。
`a|b~c&d<<e..f+g*h^-i` は `(| a (~ b (& c (<< d (.. e (+ f (* g (^ h (neg i)))))))))` を返す。
`a..b..c` は `(.. a (.. b c))` を、`-a^b` は `(neg (^ a b))` を返す。

### 拒否の正解

- テストスイートの各ファイルに、決まった種から作る変異（字句一つの削除、字句一つの重複、隣り合う字句の交換、括弧一つの削除）を加え、参照実装の `load` で受理か拒否かを判定する
- 変異した入力そのものはコミットせず、ファイル名、字句の位置、変異の種類、判定の組をコミットする。テストは取り込んだファイルから同じ変異を作り直して照合する
- `load` の拒否には、構文の誤りではないものが含まれる。const の変数への代入、見えないラベルへの `goto`、ループの外の `break`、局所変数のスコープに飛び込む `goto`、未知の属性、宣言のない名前への参照（`global` の宣言の後）、上限の超過などである。これらは参照実装の誤りの文言で分類し、構文としては受理すべきものとして扱う。分類の規則は正解を作るスクリプトに置き、分類した件数を正解の一部として記録する

## 実装しないこと

- 意味の検査（上に挙げた const、`goto`、`break`、スコープ、上限）は行わない。この ADR は構文の検証である
- Lua の実行や、AST の評価器の拡張（評価器は「評価による比較」に必要な範囲だけとする）
- 文字列のエスケープの復号した値の保持。エスケープの形と範囲の検査だけを行い、AST は字句の原文を保持する
- Lua 5.4 以前、Lua 5.5 の `LUA_COMPAT_GLOBAL` を無効にした構成（`global` を常に予約語とする構成）
- テストスイートの C の部分（`libs/`、`ltests/`）

## テスト設計

- **受理**：テストスイートの 34 ファイルをすべて受理すること
- **構造（追跡）**：メタメソッドによる追跡の正解のすべての式で、AST の正規形が正解の S 式と一致すること
- **構造（評価）**：評価による比較の正解のすべての式で、評価器の結果が正解の値またはエラーと一致すること
- **拒否**：変異の正解のうち、参照実装が構文の誤りとして拒否したものをすべて拒否し、受理したもの、および意味の誤りとして分類したものをすべて受理すること
- **長括弧**：`=` の数が 0、1、多数の長括弧の文字列とコメント、数の合わない閉じを含む入力の受理と拒否（単体のテスト）
- **`global`**：宣言としての `global`（`global x`、`global function f`、`global *`、属性付き）と、名前としての `global` の両方を含む入力（単体のテスト）
- **ロスレス性**：テストスイートの全ファイルで、構文木のテキストが入力と一致すること
- **決定性**：生成物の再生成がコミット済みのものとバイト単位で一致すること（[ADR 0010](0010-json-conformance.md) と同じ）
- **計算量**：テストスイートの全ファイルの解析で、メモ表の項目数が入力長に対して線形であることを、[ADR 0007](0007-performance-discipline.md) の項目数の検査と同じ方法で確かめる

## 完了条件

- 上記のテスト設計のすべてが通ること
- 文法の書き換えが必要になった箇所の記録と、テストスイート全体の解析の時間とメモリの計測を `docs/conformance/lua/` にスナップショットとして置くこと

## トレードオフ

- 構造の正解は無作為に作った式の標本であり、優先順位と結合性のすべての組み合わせを網羅する保証はない。段の数が 12 と小さいため、標本の数を十分にとれば実用上は足りると見込む
- 「評価による比較」は、構造の誤りが値を変えない場合を見逃す。たとえば `a == b == c` の結合の誤りは、値によっては結果が同じになる。下位の 3 段は文法が単純な左結合なので、この弱さは受け入れる
- 意味の誤りの分類は参照実装の誤りの文言に依存する。版を上げると文言が変わりうるため、正解を作り直すときに分類の件数の変化を確認する
- 入力を Latin-1 として復号するため、Lua の文法の `Text` の位置はバイトの位置と一致するが、UTF-8 の文字の位置とは一致しない。Lua のソースはバイト列なので、この選択が正しい
- 正解を作るのに参照実装が要る。正解をコミットするので、CI と開発者の環境には Lua は要らない
