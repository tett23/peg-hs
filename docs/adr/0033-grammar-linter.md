# ADR 0033: 文法ファイルの lint（peg-hs lint）

ステータス: 採択

## 文脈

静的検査（`Peg.Grammar.Check`）は、生成できない文法を誤りとして拒否する。
一方、生成はできるが明らかに意図と違う書き方がある。
後ろの選択肢が決して試されない、束縛した値が使われない、効果のないラベルがある、といった書き方である。
これらは文法の誤りの兆候であり、生成の前に知らせたい。

lint の規則を利用者が書けるようにしたり、警告を個別に抑制できるようにしたりすると、警告の意味が文法ごとに変わる。
抑制の指示は放置されやすく、警告が出ないことが文法の正しさを意味しなくなる。
そのため、規則は peg-hs が固定で持ち、利用者は規則を加えることも、警告を抑制することもできないものとする。

警告を抑制できない以上、規則は偽陽性を持ってはならない。
誤った警告を消す手段がないからである。
規則は、警告が必ず実際の問題を指し、文法を機械的に直せば消えるものに限る。

## 実装すること

### コマンド

- `peg-hs lint [FILE...]` は、各ファイルを解析し、静的検査を通った文法に lint の規則を適用して、警告を標準エラー出力に書く
- ファイルを指定しない場合の対象は、`peg-hs fmt` と同じとする（ADR 0032）
- 警告が一つでもあれば失敗する（終了状態 1）。抑制の手段がなく、どの警告も文法を直せば消えるためである
- 規則を選ぶ、加える、止めるためのオプション、設定ファイル、文法中の指示は設けない
- 警告は、位置、規則の名前、文言、直し方の示唆を含む

### 規則

規則は次の五つとする。
どれも、文法の意味から結論が必ず導けるものである。

- **到達しない選択肢（必ず成功する選択肢の後）**：必ず成功する選択肢（`e?`、`e*`、空の逐次、それらだけからなる逐次）の後ろの選択肢は、決して試されない
- **到達しない選択肢（リテラルの接頭辞）**：リテラル一つだけの選択肢 `'='` の後ろに、そのリテラルを接頭辞に持つリテラルで始まる選択肢 `'==' ...` があると、後ろの選択肢は決して成功しない。前の選択肢が先に成功するためである
- **到達しない選択肢（重複）**：位置と束縛を除いて同じ選択肢が二度あると、二つめは決して成功しない
- **効果のないラベル**：先読み（`&e`、`!e`）の中で、送出がそのまま先読みの失敗になる位置にあるラベルは、受理にも回復にも効果がない（ADR 0021）
- **使われない束縛**：アクション、意味述語、規則の引数のどれにも識別子として現れない束縛。アクションを省略した選択肢の束縛も、値は使われるが名前は使われないので対象とする

使われない束縛の判定は、Haskell の断片を字句に分け、束縛の名前が識別子として現れるかを見る。
文字列リテラルやコメントの中の出現も「使われている」とみなす。
判定の誤りは警告しない側に倒れるので、偽陽性にならない。

### ラベルの安全性の検査との関係

ラベルの安全性の検査（ADR 0028）は、lint の規則に含めない。
次の一文字による近似であり、安全なラベルにも警告するため、偽陽性のない規則に限るという原則に合わない。
ラベルの安全性の検査は、これまでどおり生成器の警告として行い、`%safe` もこれまでどおり使える。
`%safe` は lint の警告を止めない。lint の規則のどれにも作用しない。

## 実装しないこと

- 利用者の定義する規則、規則の選択と設定、警告の抑制（文法中の指示、コメント、設定ファイル、コマンドのオプション）
- 偽陽性を持ちうる規則（命名の流儀、規則の長さ、到達するかどうかを近似で判定する規則など）
- 警告の自動修正（`--fix`）。修正の内容が文法の作者の意図に依存する場合があるため
- エディタとの連携（LSP の診断）。LSP を扱う ADR で検討する

## テスト設計

- **規則ごとの例**：各規則について、警告する例と警告しない例。とくに、警告しない側の境界（必ず成功するとは限らない選択肢、リテラルの接頭辞でない場合、束縛の名前が別の識別子の一部である場合、先読みの外のラベル）
- **偽陽性がないこと**：到達しない選択肢と効果のないラベルの規則について、ADR 0028 のインタプリタで無作為な文法を評価し、警告した選択肢を消した文法、警告したラベルを外した文法が、短い入力の全列挙で元の文法と同じ受理と同じ失敗の報告を返すこと（プロパティテスト）
- **リポジトリの文法**：リポジトリのすべての文法に警告がないこと。警告が出た場合は文法を直し、CI で `peg-hs lint` を実行する
- **出力**：警告の文言の golden テストと、終了状態
- **ファイルの探索**：ファイルを指定しない場合の対象が `peg-hs fmt` と同じであること

## 実装の段階

ADR 0032 の後に行う。

## トレードオフ

- 偽陽性のない規則に限るので、規則は少なく、見つけられる問題は限られる。代わりに、警告は必ず実際の問題であり、警告のない文法をそのまま信頼できる
- 警告を抑制できないので、規則を加えるときは、既存の文法に新しい警告が出ることを受け入れる必要がある。規則を加える ADR は、リポジトリの文法と Golem の文法を直すことを含める
- ラベルの安全性の検査を lint から外したので、`peg-hs lint` が成功しても、ラベルの安全性は生成器の警告で別に確かめる必要がある
