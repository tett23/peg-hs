# ADR 0016: 生成モジュールで言語拡張を有効にする %language ディレクティブ

ステータス: 採択

## 文脈

verbatim ブロックは生成モジュールの import の位置以降に置かれる（ADR 0004）。
GHC は `{-# LANGUAGE #-}` プラグマをモジュールの先頭でしか受け付けないため、verbatim ブロックに書いても効かない。
CommonMark の文法では、アクションのすべての文字列リテラルを `T.pack "..."` と書く必要があった。
`OverloadedStrings` を使えない不便は、`Text` を扱う文法のほとんどで生じる。

言語拡張を有効にする手段を設けるにあたって、一つ注意がある。
言語拡張は利用者の断片だけでなく生成コードにも効くので、生成コードの意味を変える拡張がある。
たとえば `RebindableSyntax` は、生成コードの `do` 記法を利用者の定義した `>>=` で解釈させる。

## 実装すること

### 記法

- `%language 拡張名, 拡張名, ...` ディレクティブを加える。複数回書いてよく、書いた順に連結する
- 拡張名は GHC の言語拡張の名前の字句（英字で始まる英数字の並び。`No` で始まる否定形を含む）でなければならない。生成器は名前の存在までは確かめず、存在しない名前は GHC のエラーになる
- 生成器は、生成モジュールの先頭（`module` 行の前）に、書かれた順のまま `{-# LANGUAGE 拡張名 #-}` を一つずつ出力する。生成の決定性（ADR 0002）を保つため、並べ替えや重複の除去はしない

### 生成コードを壊す拡張

- `RebindableSyntax` は静的検査で拒否する。生成コードの `do` 記法と数値リテラルの解釈を変えるためである
- `NoImplicitPrelude` を指定した文法では、ADR 0015 で加えた `import Prelude` の補完をしない。利用者が暗黙の Prelude を明示的に断ったためである
- 上記以外の拡張は許す。生成コードは、主要な拡張の下で意味が変わらないように書く。この性質はテストで確かめる

## 実装しないこと

- `OPTIONS_GHC` など LANGUAGE 以外のプラグマは出力しない。コンパイラの設定は利用者の cabal ファイルで行う
- 拡張名の存在の検査はしない。GHC の版によって使える拡張が変わるためである
- 生成コードの中でだけ拡張を無効にする仕組みは作らない。Haskell のプラグマはモジュール単位でしか効かない

## テスト設計

- **出力の位置**：`%language` を含む文法の生成物で、プラグマが `module` 行より前に、書いた順で並ぶこと
- **拡張の下での生成コード**：codegen の fixture の一つを、次の拡張を有効にして生成し、`-Wall -Werror` でコンパイルできて、拡張なしと同じ解析結果を返すこと。`OverloadedStrings`、`OverloadedLists`、`LambdaCase`、`Strict`、`StrictData`、`NoImplicitPrelude`（verbatim ブロックで Prelude を qualified に import する）
- **拒否**：`RebindableSyntax` を含む文法が静的検査でエラーになること
- **CommonMark の文法**：`%language OverloadedStrings` を使って `T.pack` を取り除いた文法が、同じ適合の結果を保つこと（`passing.txt` の双方向の検査で確かめる）

## 実装の段階

ADR 0013 の段階 11 の後に置く。

## トレードオフ

- `Strict` の下では、アクションの値や `_span` の位置が遅延されずに計算される。結果は変わらないが、使わない値まで計算するため遅くなりうる。拡張を選んだ利用者の負担とする
- 生成コードを壊す拡張の一覧は、既知のものだけを拒否する方式であり、将来の GHC が加える拡張までは防げない。テストで確かめた拡張の一覧を syntax.md に載せ、それ以外の拡張の組み合わせは保証の外とする
