# ADR 0038: ラベルの安全性の検査の精度を上げ、ラベルを外した文法の入口の重複を直す

ステータス: 採択

## 文脈

Golem の文法（`modules/golem-parser/grammar/Golem.peg`）を peg-hs の main（437bcd8）で生成すると、ラベルの安全性の検査（[ADR 0028](0028-label-safety-check.md)）が 15 か所のラベルに警告を出す。
Golem はこれを [[Golem の ADR 0007](https://github.com/tett23/golem/blob/d1f2f87736e25985737ee9dbd3e150dfd346e29a/docs/golem-parser/adr/0007-grammar-label-safety.md)](https://github.com/tett23/golem/blob/d1f2f87736e25985737ee9dbd3e150dfd346e29a/docs/golem-parser/adr/0007-grammar-label-safety.md) で調べた。
文法を読み、ラベルを外した変種と小さな入力の全列挙で比べた結果は次のとおりである。

- 5 か所は、ラベルが言語を定めていた。Golem は文法を直す
- 残りの 10 か所は安全だが、検査の近似のために警告を受ける
- 直した 5 か所も、同じ近似のために警告が消えない

Golem はこのままだと、15 か所すべてに理由のコメント付きの `%safe` を書くことになる。
`%safe` はラベルの名前で効くので、`close` のように一つの名前を三か所で使うラベルは、一か所が安全でなくても全部の警告が止まる。
[Golem の ADR 0007](https://github.com/tett23/golem/blob/d1f2f87736e25985737ee9dbd3e150dfd346e29a/docs/golem-parser/adr/0007-grammar-label-safety.md) が言うとおり、検査は新しいラベルの見落としを防ぐ役にしか立たなくなる。

近似の中身は、[Golem の ADR 0007](https://github.com/tett23/golem/blob/d1f2f87736e25985737ee9dbd3e150dfd346e29a/docs/golem-parser/adr/0007-grammar-label-safety.md) の分析によれば三種類に分かれる。

1. **規則の呼び出しを越えた共通の接頭辞**：ブロックの選択肢はどれも `Ind(ind)` で始まる。`Ind(n)` は `&{ n == 0 }` と `' ' Ind(n - 1)` の選択で、引数の数だけ空白を読む。`BadIndent(ind)` と `OrphanDef(ind)` は同じ位置で同じ引数の `Ind(ind)` を読むので、読む空白の数は同じである。ところが検査は、別の規則の中にある二つの `Ind(ind)` を同じものとして扱えない。そのため「後の選択肢は空白をもっと読んでから `=:` に出会うかもしれない」とみなす。共通の接頭辞を除いて比べる仕組み（`commonPrefix`）は、同じ選択の中の並んだ選択肢にしか効かない
2. **定数の意味述語**：誤りを拒むための `(&{ False })^bracket` は必ず失敗するが、検査は意味述語を「どの文字でも成功しうる」とみなす。`BadBracket <- LBr (&{ False })^bracket` が後の選択肢にあると、`[` で始まる入力をこの選択肢が読みうると判定される
3. **一文字の先読み**：`%%` と `%`、`[=` と `[`、`*[` と `*` の区別には二文字目が要る。`Comment <- '%%' …` が失敗した位置で、地の文の `Text <- (![\[\\\n] !'%%' .)+` は `!'%%'` のために始まれない。しかし検査は、`!'%%'` が除く文字を一文字では表せない

15 か所のうち、この三つで説明できないのは 2 か所である。
`block`（`Block` の選択の全体）は、空でない行に対して `Paragraph` が必ず何かを読むという、文法の意味に依存する。
`table_cells`（`&{ r == h }`）は、意味述語の値そのものに依存する。
この 2 か所は、作者が `%safe` で引き受けるしかない。

警告とは別に、[Golem の ADR 0007](https://github.com/tett23/golem/blob/d1f2f87736e25985737ee9dbd3e150dfd346e29a/docs/golem-parser/adr/0007-grammar-label-safety.md) は `--strip-labels` の不具合を報告している。
Golem の文法をラベルを外して生成すると、コンパイルできないモジュールになる。
437bcd8 の後の main でも再現した。
`parseSkipBlock` の型の宣言が 5 回、`parseSkipParagraph` が 3 回現れる。

原因は `stripLabels` にある。
回復の規則を残すために、回復の規則を `%entry` に加えるのだが、`%recover` の行ごとに加えて重複を除いていない。
Golem では `SkipBlock` を 5 つのラベルが、`SkipParagraph` を 3 つのラベルが使う。
利用者が `%entry A` を二度書いた場合も、同じ重複した入口が生成される。
静的検査がこれを誤りにしないためである。

警告をすべて検査の改良で消すことはできない。
しかし 13 か所の警告は検査の近似が原因なので、近似を詰めれば `%safe` は 2 か所の、文法の意味に依存するラベルだけに減らせる見込みである。

## 実装すること

### ラベルを外した文法の入口

- `stripLabels` は、回復の規則を `%entry` に加えるとき、名前の重複を除く。開始規則と、すでに `%entry` にある規則は加えない
- 静的検査は、同じ規則を二度書いた `%entry` を誤りにする。文言は「the rule A is named in %entry twice」とし、位置は二つめの `%entry` とする

### 規則の呼び出しを越えた共通の接頭辞

ラベルの失敗を呼び出し元へ伝えるとき、失敗した選択肢がそれまでに読んだ要素の列（接頭辞）を、呼び出し元の文脈に置き直して持ち運ぶ。
後の選択肢と比べる前に、後の選択肢の先頭の規則の呼び出しを展開し、持ち運んだ接頭辞との共通の接頭辞を除く。
共通の接頭辞を除いた残りの最初の文字の集合を比べることは、いまの `laterCheck` と同じである。

- **接頭辞の持ち運び**：規則 `R` の選択肢の `j` 番目の要素で失敗したとき、接頭辞は `R` の選択肢の要素 `0 .. j-1` と、失敗した要素の中で読んだ部分とする。呼び出し元の `j'` 番目の要素が `R(args)` なら、呼び出し元での接頭辞は、呼び出し元の要素 `0 .. j'-1` に、`R` の接頭辞を連ねたものとする
- **引数の置き換え**：接頭辞を呼び出し元へ持ち上げるとき、`R` の仮引数の名前を、Haskell の字句の単位で呼び出しの実引数の字句に置き換える。比べるときは、置き換えた後の引数の字句が一致する呼び出しを同じものとする。同じ位置で同じ引数の規則を呼べば同じ結果になる（PEG の決定性）ので、読む入力も同じである
- **展開の範囲**：後の選択肢の先頭の要素が規則の呼び出しなら、その規則の各選択肢で置き換えて比べる。どれか一つでも残りが重なれば、これまでどおり危険とする。展開の深さは 8 までとし、左再帰の規則、雛形の呼び出し、`%env` の値に依存する可能性のある意味述語（`_env` を含むもの）を含む規則は展開しない
- **意味述語と状態**：接頭辞に意味述語を含んでもよい。同じ位置、同じ引数、同じ環境で評価した意味述語は同じ値を返すからである。`_col` のような位置に依存する予約束縛も、同じ位置なので同じである

### 定数の意味述語

意味述語の Haskell の断片が、前後の空白を除いて `False` なら、検査はその式を決して成功しない式として扱う。
`True` なら、何も読まずに必ず成功する式として扱う。
`&{ False }`、`!{ True }`、`&{ True }`、`!{ False }` がこれにあたる。
ほかの断片の値は推測しない。

### 既知の接頭辞の文字列

失敗した選択肢の先頭がリテラルだけでできているとき、その位置の入力はそのリテラルの文字列で始まることが確定している。
規則がリテラルだけの選択肢からなる場合（`Splat <- '**[' { () } / '*[' { () }`）は、その文字列のどれかで始まる。
後の選択肢を比べるとき、この文字列の集合を一文字目より先まで使う。

- 後の選択肢の先頭の要素を、既知の文字列に対して記号的に評価する。リテラルとクラスは文字を照合する。`!'%%'` のような否定の先読みは、既知の文字列が先読みの中身で必ず始まるなら失敗する。規則の呼び出しは、上の展開の範囲の規則に限って展開する
- 既知の文字列のどれに対しても後の選択肢が必ず失敗すると示せたら、その選択肢は安全とする。示せなければ、これまでどおり一文字の集合で比べる
- 既知の文字列の長さは 4 文字までとする。リテラルがそれより長ければ、先頭の 4 文字だけを使う

### 検査の報告

- 警告の文言は変えない
- 危険と判定した理由が、三つの改良のどれを試したうえでのものかは報告しない。警告を受けた作者は、これまでどおり文法を読んで判断する

### 文書

- [docs/syntax.md](../syntax.md) のラベルの安全性の検査の節に、規則の呼び出しを越えて共通の接頭辞を除くこと、定数の意味述語、二文字目以降を使う比較を書く。`%entry` の重複が誤りになることを書く
- [ADR 0029](0029-label-safety-implementation-deviations.md) のステータスを「採択→偽陽性を減らす改良（二文字の先読み）は [ADR 0038](0038-label-check-precision-and-strip-labels-entries.md)」に変える

## 実装しないこと

- `block` と `table_cells` のような、文法の意味や意味述語の値に依存する安全性の判定。作者が `%safe` で引き受ける
- 意味述語が判定する文字の範囲の宣言（[ADR 0029](0029-label-safety-implementation-deviations.md) の挙げたもう一つの改良）。記法の自己記述の文法の 21 個の `%safe` は、この ADR の後も残る。識別子と空白を意味述語で判定しているためである
- 使われなくなった `%safe` の検出。この ADR で警告が消えたラベルに付けた `%safe` は、害がないまま残る。lint の規則にするかは別の ADR で検討する
- Golem の文法の変更。[Golem の ADR 0007](https://github.com/tett23/golem/blob/d1f2f87736e25985737ee9dbd3e150dfd346e29a/docs/golem-parser/adr/0007-grammar-label-safety.md) が扱う

## テスト設計

ラベルの安全性のテスト（`packages/peg-grammar/test/Labels.hs`）に加える。
先に書き、いまの検査で失敗させる。

### 安全と判定するようになる例

Golem の文法から、警告の原因になった形を小さな文法に写す。
どれも、いまは警告を受け、この ADR の後は警告を受けない。

- **呼び出しを越えた接頭辞**：`Block(n) <- (A(n) / B(n) / P(n))^block`、`A(n) <- Ind(n) [ \t] (&{ False })^indent`、`B(n) <- Ind(n) '=:' …`、`Ind(n) <- &{ n == 0 } / ' ' Ind(n - 1)` の形。引数を置き換えた後に一致する呼び出しを同じものとすること
- **定数の意味述語**：`Inline <- Cmd / Bad / Text`、`Cmd <- '[' Ident (']')^close`、`Bad <- '[' (&{ False })^bracket` の形
- **既知の接頭辞**：`Comment <- '%%' (!'%%' .)* ('%%')^comment_close` の後の `Text <- (![\[] !'%%' .)+`、`Splat <- '**[' / '*['` で始まる選択肢の後の `!Splat Word`、`'[='` の後の `'[' Ident`

### 危険のままの例

改良で検査が緩みすぎないことを確かめる。

- 引数が違う呼び出し（`A(n)` と `B(n + 1)` の先頭の `Ind`）は、同じものとしないこと
- 仮引数と同じ名前の束縛や局所の名前を含む実引数（`Ind(n)` の `n` が呼び出し元で別の意味を持つ場合）で、置き換えを誤らないこと
- `_env` を含む意味述語を含む規則は展開しないこと
- `&{ x == 0 }` のような定数でない意味述語を、定数とみなさないこと
- 既知の文字列が後の選択肢の先読みの中身で必ず始まるとは限らない場合（`'%'` の後の `!'%%'`）は、安全としないこと
- [ADR 0028](0028-label-safety-check.md) の危険な例（`unsafeSnippets`）が、すべて危険のままであること

### 偽陰性がないこと

[ADR 0028](0028-label-safety-check.md) のプロパティテスト（無作為な文法で、警告のない文法がラベルを外した文法と同じ言語を受理すること）を、次の形も生成するように広げる。

- 引数付きの規則の呼び出しで始まる選択肢
- `&{ False }`、`&{ True }` の意味述語
- 先頭が二文字以上のリテラル

インタプリタは、引数付きの規則と定数の意味述語を評価できるように広げる。
定数でない意味述語は、これまでどおり成功するものとして評価する。

### ラベルを外した文法

- 二つのラベルが同じ回復の規則を使う文法を `--strip-labels` で生成し、入口が一つずつで、生成したモジュールがコンパイルできること（codegen のテストの、ラベルを外した変種の生成と同じ方法）
- 同じ規則を二度書いた `%entry` が誤りになること

### Golem の文法での確認

Golem の文法は peg-hs のリポジトリの外にあるので、自動テストにしない。
実装の後に、[Golem の ADR 0007](https://github.com/tett23/golem/blob/d1f2f87736e25985737ee9dbd3e150dfd346e29a/docs/golem-parser/adr/0007-grammar-label-safety.md) の文法の変更を加え、`%safe` を除いた `Golem.peg` を生成して、警告が `block` と `table_cells` の 2 か所だけになることを手で確かめる。
結果は [Golem の ADR 0007](https://github.com/tett23/golem/blob/d1f2f87736e25985737ee9dbd3e150dfd346e29a/docs/golem-parser/adr/0007-grammar-label-safety.md) の実装のときに、Golem の側で記録する。

### 既存のテスト

- リポジトリの文法に警告がないこと、記法の文法とラベルを外した変種の受理の一致、ラベルの警告の golden が、変わらず通ること
- 記法の文法の `%safe` を一つずつ外したとき、警告が出なくなるものがあれば、この ADR の改良が効いた結果として golden に記録する

## トレードオフ

- 検査が複雑になる。いまの検査は、選択肢ごとに一文字の集合を比べるだけで、なぜ危険と判定したかを追いやすい。接頭辞の持ち運び、引数の置き換え、記号的な評価が加わると、警告が出る理由も出ない理由も追いにくくなる。偽陰性がないことのプロパティテストを広げて、この複雑さを支える
- 引数の置き換えは Haskell の字句の単位の文字列の置き換えであり、Haskell の式としての同値は見ない。`n + 1` と `1 + n` は別のものとみなすので、警告が残ることがある。安全側に倒れるので、偽陰性にはならない
- 展開の深さと既知の文字列の長さに上限を置くので、それを越える区別には警告が残る。Golem の文法で必要になる深さと長さは、文法を読んだ限りではどちらも上限に収まる（`'%%='` が 3 文字、`Block` から `Ind` までの呼び出しが数段）。実装の後の Golem での確認で、足りなければ上限を見直す
- 定数の意味述語を特別に扱うのは、誤りを拒むための `(&{ False })^label` という書き方を検査が認めることでもある。この書き方は「ラベルはそこで失敗したらどの選択肢でも成功しえない位置にだけ付ける」という作法とは別の、作者の意図の表し方である。検査はその意図の安全性だけを判定し、書き方の良し悪しは判定しない
