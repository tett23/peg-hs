# ADR 0057: CI で確かめる GHC を ghcup の recommended の版だけにする

ステータス: 採択

## 文脈

[ADR 0045](0045-fixes-before-v0-1-0.md) は、対応する GHC を 9.10、9.12、9.14 に広げた。
`base` の上限を `<4.23` にし、`tested-with` に三つの版を並べ、CI に GHC 9.12.4 と 9.14.1 のジョブ（`ghc-9.12.4`、`ghc-9.14.1`）を加えた。

ところが、CI の実行の上限が厳しい。
二つの GHC のジョブは、それぞれ GHC の導入、全パッケージのビルド、peg-runtime と peg-codegen のテストを行い、約 90 秒かかる（[計測](../benchmarks/2026-10-13-ci-split-package.md)）。
キャッシュが外れたときは依存のビルドからやり直すので、さらに長くなる。
push のたびに二つのジョブが動き、実行の時間を消費する。

開発のツールチェーンは、ghcup が recommended とする版に固定している（[ADR 0013](0013-roadmap-toolchain-memo.md)、いまは GHC 9.10.3）。
ほかのテストのジョブも、この版だけで動く。
そこで、CI で確かめる GHC を recommended の版だけにし、9.12 と 9.14 のジョブを除く。

対応する版そのものは狭めない。
`base` の上限を戻すと、9.12 と 9.14 の利用者が Hackage からそのままでは入れられなくなる。
v0.1.0-rc1 と rc2 は三つの版で確かめており、その後に新しい GHC で動かなくなる変更をわざと入れるわけではない。

## 実装すること

### CI

- CI の `ghc` のジョブ（GHC 9.12.4 と 9.14.1）を除く
- そのほかのジョブは変えない

### 対応する版

- `base` の範囲（`>=4.20 && <4.23`）と、`peg-hs parse` が受け付ける版（9.10、9.12、9.14）は変えない
- `tested-with` を、CI で確かめる版（`GHC == 9.10.3`）だけにする。`tested-with` は確かめた版を示す欄なので、CI で確かめなくなった版は載せない
- 9.12 と 9.14 は、v0.1.0-rc2 の時点で CI で確かめた版として文書に書く。その後は CI で確かめていないことを明示する

### 文書

- README（日本語と英語）の導入の節と既知の制限、CONTRIBUTING（日本語と英語）の開発の環境と CI のジョブ、docs/specifications.md の生成モジュールの節を、「CI で確かめるのは 9.10。9.12 と 9.14 は v0.1.0-rc2 まで CI で確かめた」に改める
- CONTRIBUTING の、9.12 と 9.14 での手元の確かめ方（`cabal build -w ghc-9.14.1 all`）は残す
- [ADR 0045](0045-fixes-before-v0-1-0.md) のステータスを「採択→CI で確かめる GHC の版は ADR 0057」に変える

## 実装しないこと

- `base` の上限を戻し、対応する版を 9.10 だけにすること。利用者から見て対応が狭まる
- 新しい GHC で動くかを、CI の外で定期的に確かめる仕組み。上限の緩い環境が用意できたら、別の ADR で検討する

## テスト設計

- **CI**：自動テストは書けないので、変更の後の CI で、`ghc` のジョブがなくなり、ほかのジョブが通ることを確かめる
- **パッケージ**：`cabal check` が通ること
- **`peg-hs parse`**：受け付ける版のテスト（[ADR 0036](0036-parse-command.md)、[ADR 0045](0045-fixes-before-v0-1-0.md)）が変わらずに通ること

## トレードオフ

- 9.12 と 9.14 で動かなくなる変更が入っても、CI では気付けない。利用者からの報告か、手元での確かめで初めて分かる。上限の広さと、確かめている範囲が食い違う
- recommended の版が変わったときは、`cabal.project` の `with-compiler`、CI の `GHC_VERSION`、`tested-with` を同じコミットで変える必要がある。CONTRIBUTING にこの手順を書いて防ぐ
