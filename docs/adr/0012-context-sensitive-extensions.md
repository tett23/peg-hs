# ADR 0012: 意味述語、引数付き規則、解析環境、桁の参照を記法に加える

ステータス: 採択→タブの部分消費（実装しないこと）は [ADR 0018](0018-tab-partial-consumption.md)

## 文脈

[ADR 0011](0011-commonmark-expressiveness-probe.md) は、v1 の記法（[ADR 0004](0004-peg-notation.md)）では CommonMark の次の構文を書けない見込みだと整理した。

- **字下げの状態**：リスト項目の継続行に要る字下げ幅が、項目の開始記号の幅で決まる。入れ子のコンテナでは、各行がコンテナの接頭辞の列全体に照合し直される
- **前方参照**：`[foo]` がリンクになるかが、文書の後方にあるかもしれない定義で決まる
- **タブの桁**：ブロック構造の判定で、タブを 4 桁ごとのタブ位置まで展開されたものとして扱う
- **後読み**：強調の区切り記号の扱いが、直前の文字に依存する

どれも、照合の判断が「いまの位置から先の入力」以外の情報に依存するという点で共通している。
依存先は三種類に分けられる。
字下げ幅は、同じ解析の中で先に読んだ値である。
リンク定義は、解析の外から与えられる値である。
タブの桁は、入力と位置から計算できる値である。

拡張の設計で守るべきものは、パックラットのメモ表の健全性である。
メモ表は「同じ規則を同じ位置で評価すれば同じ結果になる」ことを前提にしており、[ADR 0001](0001-bounded-left-recursion.md) の成長ループも同じ前提で動く。
Parsec 型の可変な利用者状態は、この前提を直接壊す。
状態の値によって同じ規則と位置の結果が変わり、バックトラックと成長ループの再実行が状態の巻き戻しを要求するためである。

本 ADR は、三種類の依存先それぞれに、前提を保ったまま情報を届ける仕組みを一つずつ与える。
不変条件は次の一文で表せる。

> 規則の結果は、規則、引数、位置の組と、解析環境だけの関数である。

## 前提

- [ADR 0001](0001-bounded-left-recursion.md)（左再帰）が実装済みであること
- [ADR 0011](0011-commonmark-expressiveness-probe.md) の初回スナップショットが記録済みであること。本 ADR の実装後に二回目を記録し、拡張の効果を適合率の差として残す

## 実装すること

### 意味述語

- `&{ 式 }` と `!{ 式 }` を加える。式は `Bool` 型の純粋な Haskell 式で、`&{ }` は真のとき、`!{ }` は偽のときに入力を消費せず成功する。記法は PEG.js に倣う
- 式が参照できるのは、同じ逐次の中で述語より左にある束縛、規則の引数、`_env`、`_col` に限る
- 述語は値を持たない（[ADR 0004](0004-peg-notation.md) の分類で、先読み述語と同じ扱い）
- 述語の失敗は期待集合に項目を加えない。否定先読みと同じく、期待の語彙で表せないためである（[ADR 0005](0005-error-reporting.md)）

参照できる値はすべて「規則、引数、位置、環境」から決まるため、述語は不変条件を壊さない。

### 引数付き規則

規則は引数を取れる。
型注釈で引数の名前と型を宣言し、呼び出しでは Haskell 式を渡す。

```
Indent(w :: Int) :: ()
Indent <- &{ _col >= w } { () }
        / ' ' Indent(w)
```

- 呼び出しの式が参照できるのは、意味述語と同じく、左にある束縛、規則の引数、`_env`、`_col` である
- 規則名と `(` の間に空白を置かない。空白を置いた `A (B / C)` は従来どおり、非終端と括弧グループの逐次と読む。引数を取らない規則を `A(B / C)` の形で書いた場合は、引数の個数の不一致として静的検査でエラーになるため、誤読は黙って通らない
- 引数の型は `Ord` のインスタンスでなければならない。メモ表の鍵は「規則と位置」から「規則と位置と引数」に広がり、生成コードは位置ごとに引数を鍵とする表を持つ
- 引数付き規則が左再帰に関与することは、静的検査で拒否する。成長ループと引数の組み合わせの意味論は、Medeiros らの定式化の範囲外だからである

### 解析環境

- `%env 型` ディレクティブで、解析全体を通じて不変な値の型を宣言する。宣言した文法では、生成されるパーサーの入口が環境の値を引数に取る
- 予約束縛 `_env` で、アクション、意味述語、規則の引数から環境を参照できる
- 環境は解析中に変化しないため、メモ表の鍵に含める必要がない

前方参照は、解析を二回行うことで扱う。
一回目のパーサー（たとえばブロック構造の文法）がリンク定義を集め、利用者のコードがそれを環境として二回目のパーサー（インラインの文法）に渡す。

### 桁の参照

- 予約束縛 `_col` で、その評価位置の桁を参照できる。参照できる場所は意味述語と規則の引数である
- 桁は行頭を 0 とし、Unicode のコードポイント一つを 1 桁と数える
- `%tabstop N` ディレクティブを宣言した文法では、タブを次の N の倍数の桁まで進めるものとして数える。宣言しない文法ではタブも 1 桁である
- `_col` の数え方は [ADR 0008](0008-source-positions.md) の `Pos` の桁とは独立とする。`%tabstop` は `_col` にだけ作用し、診断に使う位置情報を変えない

桁は入力と位置から計算できる値なので、不変条件を壊さない。

### 予約名

`_env` と `_col` は、[ADR 0008](0008-source-positions.md) がアンダースコア始まりの名前を生成器の予約としたことの範囲内で追加する。

## 実装しないこと

- 可変な利用者状態（Parsec の `getState` / `putState` に相当するもの）は、将来も導入しない。理由は文脈の節に述べた
- 後読みの構文は導入しない。CommonMark の強調は、仕様が定める区切り記号の後処理で扱う（[ADR 0011](0011-commonmark-expressiveness-probe.md)）。直前の文字が必要な判断は、直前の文字を束縛して意味述語に渡す形で書ける
- タブの部分消費は扱わない。CommonMark では、コンテナの字下げがタブの途中までを消費し、残りの桁が内容の字下げとして数えられる場合がある。PEG は文字を単位として消費するため、この挙動は本 ADR の拡張でも書けない。該当する例は [ADR 0011](0011-commonmark-expressiveness-probe.md) の失敗分類に残る
- 引数付き規則の左再帰は扱わない（上記）
- 意味述語の失敗にラベルを付ける仕組みは、ラベルの意味論の ADR に委ねる

## テスト設計

- **意味述語**：真偽のそれぞれで入力を消費しないこと、左にある束縛だけを参照できること（右にある束縛の参照が静的エラーになること）
- **引数付き規則**：同じ規則を異なる引数で同じ位置から呼んだとき、メモ表が引数ごとに別の結果を返すこと。評価回数のフック（[ADR 0003](0003-typed-semantic-actions.md)）で、同じ規則、位置、引数の組の評価が一回に限られることを確かめる
- **呼び出しの構文**：`A(x)` が呼び出しに、`A (x)` が逐次になること。引数の個数の不一致、引数付き規則の左再帰、`Ord` を持たない引数型（生成後のコンパイルエラーとして現れること）を検査する
- **解析環境**：異なる環境の値で同じ入力を解析すると、述語を通じて結果が変わること。`%env` を宣言しない文法の入口の型が、従来と変わらないこと
- **桁**：`%tabstop 4` の有無で `_col` が変わり、`Pos` の桁が変わらないこと。行頭、タブの直後、マルチバイト文字の直後の値
- **不変条件**：無作為に生成した文法と入力について、メモ化を無効にした評価器との結果の一致を確かめるプロパティテスト（[ADR 0005](0005-error-reporting.md) のメモ化整合テストを、拡張を含む文法に広げる）
- **効果の測定**：[ADR 0011](0011-commonmark-expressiveness-probe.md) の CommonMark の文法を拡張を使って書き直し、二回目のスナップショットを記録する。適合率の目標は置かない

## トレードオフ

- 引数付き規則はメモ表の鍵を広げる。引数の値の種類が多い文法では、メモ表のメモリが引数の種類の数に比例して増える。CommonMark の字下げ幅のように値の範囲が小さい用途を想定しており、大きな値を引数に流す文法の性能は保証しない
- 引数付き規則の左再帰を禁じたため、左再帰で書きたい構文と字下げに依存する構文が同じ規則に重なる場合は、規則を分けて書く必要がある
- 意味述語と引数の式は Haskell の式であり、型の誤りは生成後の GHC のエラーとして現れる。[ADR 0002](0002-standalone-code-generator.md) と [ADR 0003](0003-typed-semantic-actions.md) で残した、`.peg` 側の行番号への写像の問題がさらに広がる
- 前方参照を二回の解析で扱う方式は、二つの文法の分担を利用者が設計することを要求する。CommonMark のブロックとインラインの分担は仕様の構造そのものなので自然に収まるが、一般の言語で同じ分担が自然に引けるとは限らない
- 本 ADR は [ADR 0011](0011-commonmark-expressiveness-probe.md) の測定より前に、仕様の記述から予想される穴に対して設計している。測定の結果、予想と異なる穴が多数を占めた場合は、本 ADR の拡張とは別の対処を新たな ADR で検討する
