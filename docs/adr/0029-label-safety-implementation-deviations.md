# ADR 0029: ラベルの安全性の検査の実装で [ADR 0028](0028-label-safety-check.md) から外れた点

ステータス: 採択→偽陽性を減らす改良（二文字の先読み）は [ADR 0038](0038-label-check-precision-and-strip-labels-entries.md)

## 文脈

[ADR 0028](0028-label-safety-check.md)（ラベルの安全性の静的な検査）を実装した。
実装の過程で、ADR の定義と例の誤り、テスト設計を満たすための追加、リポジトリの文法の変更が生じた。
[ADR 0028](0028-label-safety-check.md) はコミット後に変更できないので、ここに記録する。

## 実装すること

### 安全性の定義：ほかのラベルはないものとみなす

[ADR 0028](0028-label-safety-check.md) は、ラベルが安全であることを「`e` が失敗する入力のどれについても、ラベルがなければ解析全体が失敗すること」と定めた。
最初の実装は、検査するラベルだけを外し、ほかのラベルは残したまま判定した。
無作為な文法のプロパティテストが、この判定の反例を見つけた。
`S <- (('b' ^l) ^l) / 'c' A` で、内側のラベルは外側のラベルが送出するので安全、外側のラベルは内側が失敗しないので安全、と判定されたが、両方を外すと `c` で始まる入力を受理する。

各ラベルを、ほかのラベルをすべて外した文法の上で判定する。
入れ子の外側のラベルは、失敗をそのまま外へ伝えるものとして扱う。
すべてのラベルがこの意味で安全なら、ラベルを付けた文法とすべて外した文法は同じ言語を受理する。
最初の送出までは二つの文法の評価が一致し、送出したラベルが安全なら、外した文法はその後で失敗するからである。

### [ADR 0028](0028-label-safety-check.md) の例の誤り

[ADR 0028](0028-label-safety-check.md) のテスト設計は、危険な例に「`('a' ^l)?` の後に `'a'` が続く文法」を挙げた。
この文法は安全である。
`'a'` が失敗するとき次の文字は `a` ではないので、省略可能な式が何も読まずに終わっても、続く `'a'` も失敗する。
テストでは `('a' ^l)?` の後に `'b'` が続く文法を危険な例とした。

### 先読みの中の検査

[ADR 0028](0028-label-safety-check.md) は「先読みに入った時点で、失敗の伝わり方の検査を終える」とした。
先読みの中の送出は先読みの失敗になるが、先読みの中の後戻りは止まる。
そのため、先読みの中の選択肢は検査し、失敗が先読みの境界に達したところで検査を終える。

### 健全性のテストの入力

[ADR 0028](0028-label-safety-check.md) は、ラベルを外した変種との比較を「各文法の正しい入力の一文字の削除と重複のすべて」で行うとした。
TOML（toml-test の全件）と JSON（JSONTestSuite の受理すべき入力）は、すべての位置で比較した。
記法の文法の入力はリポジトリの文法（約 96,000 文字）であり、すべての位置では解析に 2 分以上かかる。
文法ごとに約 200 の位置を等間隔に選んで比較した。

### ラベルを外した変種の生成

- peg-cli に `--strip-labels MODULE` を加え、ラベル、`%recover`、`%safe` を外した文法を別のモジュール名で生成する。再生成のスクリプトが、TOML の文法、記法の文法、codegen の Recover の fixture の変種を生成する
- 回復の規則は、外さずに入口（`%entry`）にする。外すと、回復の規則だけが使う import が使われなくなり、生成コードが `-Werror` でコンパイルできない
- 記法の文法の変種は、生成コードが `Peg.Grammar.Assemble` を import する。peg-grammar のテストでこの変種をコンパイルするため、`Peg.Grammar.Assemble` を公開するモジュールにした。Haddock に、自己記述のパーサーとそのテストのためのモジュールであることを書いた
- 生成物の一致の検査に、ラベルを外した三つの変種と、自己記述のパーサー（`SelfHosted.hs`）を加えた。[ADR 0027](0027-switch-to-self-hosted-parser.md) のテスト設計は自己記述のパーサーの一致の検査を既存のものとしたが、実際にはなかった

### 記法の文法のラベル

健全性のテストで、記法の文法の二つのラベルが言語を変えていることが分かった。

- `hsstring`：アクションの中の閉じていない文字列は、ラベルがなければ引用符を普通の文字として読み、受理される
- `argument`：`B()` は、ラベルがなければ引数のない呼び出しと空のグループとして読まれ、受理される

どちらも [ADR 0027](0027-switch-to-self-hosted-parser.md) で手書きのパーサーに合わせて拒否するために付けたラベルであり、[ADR 0028](0028-label-safety-check.md) の意味では安全ではない。
文法を変え、ラベルがなくてもこれらの入力を拒否するようにした。
引用符は文字列と文字リテラルの規則でだけ読み、識別子の直後に `(` がある参照は呼び出しとして読む。
ラベルは誤りの文言のために残る。
ラベルを付けた文法では、変更した選択肢に達する前にラベルが送出するので、受理する言語は変わらない。誤りの報告が変わらないことは [ADR 0027](0027-switch-to-self-hosted-parser.md) の golden テストで、受理した文法の AST が変わらないことはリポジトリのすべての生成物の一致で確かめた。

### リポジトリの文法の偽陽性

検査は、リポジトリの文法に次の警告を出した。
どれも安全であることを健全性のテストで確かめ、`%safe` と理由を文法に書いた。

| 文法 | ラベル | 原因 |
|---|---:|---|
| 記法の文法 | 21 | 識別子と空白を意味述語で判定しており、意味述語をどの文字でも成功しうるとみなすため |
| TOML | 1（`table`） | `[[` と `[` を一文字目で区別できないため |
| codegen の Recover の fixture | 2（`name`、`close`） | 失敗した位置から段落の繰り返しが続きうるとみなすため。続きの段落は同じ位置で同じように失敗する |

JSON の回復の文法には警告が出なかった。
偽陽性を減らす改良（二文字の先読みや、意味述語で判定する文字の範囲の宣言）は、別の ADR で検討する。

## 実装しないこと

- 上記の偽陽性を減らす改良

## テスト設計

- 上記の変更のテストは、[ADR 0028](0028-label-safety-check.md) のテスト設計のテストに含まれる。入れ子のラベルの反例は、無作為な文法のプロパティテストが検出する形で残っている
- peg-cli にテストスイートを加え、警告、`--Werror`、`%safe`、`--strip-labels` の動作を確かめる

## 実装の段階

[ADR 0028](0028-label-safety-check.md) の実装に含めて行った。
本 ADR を採択するとき、[ADR 0028](0028-label-safety-check.md) のステータスの行を「採択→安全性の定義と記法の文法の変更は ADR 0029」に変える。

## トレードオフ

- ほかのラベルをないものとみなす定義は、ラベルを付けた文法の実際の評価より厳しい。ほかのラベルが送出して止めるおかげで安全なラベルにも警告する。その代わり、警告がなければラベルをすべて外した文法と同じ言語を受理する、という分かりやすい保証になる
- `Peg.Grammar.Assemble` の公開は、公開する API を増やす
