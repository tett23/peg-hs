# ADR 0031: 式を引数に取る規則の雛形

ステータス: 採択

## 文脈

引数付き規則（[ADR 0012](0012-context-sensitive-extensions.md)）の引数は Haskell の値であり、メモ表の鍵になる。
規則や式を引数として渡すことはできない。
そのため、文法によく現れる形を一つの規則にまとめられず、使う場所ごとに書き下すことになる。

Lua の文法（[ADR 0022](0022-lua-conformance.md)）では、次の二つが目立った。

- **予約語**：`KEnd <- 'end' ![a-zA-Z0-9_] Sp { () }` の形の規則を 23 個書いた。違うのはリテラルだけである
- **区切りのある列**：`ExpList <- e:Exp es:MoreExp* { e : es }` と `MoreExp <- ',' Sp e:Exp { e }` の組を、式、名前、変数、属性付きの名前、フィールドについて繰り返した

TOML の文法（[ADR 0023](0023-toml-conformance.md)）にも、配列の要素とインラインの表のキーと値で同じ形がある。
Golem の文法も、コマンドの引数やキーと値の列で同じ形を使う。

[ADR 0030](0030-unit-values-are-not-counted.md) は、空白の規則を挟むための補助の規則をなくす。
本 ADR は、形そのものを一度だけ書けるようにする。

### 方式の選択

二つの方式を検討した。

- **生成時の展開（単相化）**：雛形の呼び出しを、引数ごとに別の規則として生成する。`List<Exp, ','>` と `List<Name, ','>` は別の規則になり、それぞれがメモ表を持つ。左再帰の解析、静的検査、構文木は、展開した後の規則に対してこれまでどおり働く
- **高階の Haskell 関数**：雛形を、パーサーを引数に取る Haskell の関数として生成する。生成コードは小さくなるが、メモ表の鍵にパーサーを含められないので、雛形の結果をメモ化できない。左再帰の検査も、関数を跨いで行えなくなる

生成時の展開を採る。
メモ化と左再帰（[ADR 0001](0001-bounded-left-recursion.md)）の意味論を、展開した後の普通の規則の意味論に帰着できるからである。

## 実装すること

### 記法

雛形は、規則名の直後の山括弧で引数を宣言する。
引数は式であり、雛形の本体の中では非終端のように書く。

```
# 予約語：リテラルの後に識別子の文字が続かず、空白を読む
K<w> :: ()
K<w> <- w ![a-zA-Z0-9_] Sp { () }

# 区切りのある一つ以上の列
List<p :: a, sep> :: [a]
List<p, sep> <- x:p xs:(sep Sp p)* { x : xs }
```

呼び出しは、規則名の直後の山括弧に引数の式を書く。

```
Stat <- K<'while'> c:Exp K<'do'> b:Block K<'end'> { SWhile c b }
ExpList :: [Exp]
ExpList <- List<Exp, ','>
```

- 規則名と `<` の間に空白を置かない。`<-` は、これまでどおり定義の矢印である
- 引数の式は、選択や逐次を含む任意の式を書ける。カンマや `>` を含む式は括弧で囲む
- 値を使う引数（本体で束縛する、またはアクションの省略で返す引数）は、型注釈で `p :: a` の形の型変数を宣言する。値を使わない引数（上の `w` と `sep`）は型を書かない
- 型を書かない引数は、本体の中では値を持たないものとして数え、値を捨てる文脈（[ADR 0026](0026-discard-unused-values.md)）で生成する。`List<Exp, Comma>` の `Comma` が値を持つ規則でも、グループの値の数は変わらない
- 雛形の型注釈の中の型変数は、呼び出しごとに引数の型に置き換える

### 展開

- 生成器は、文法の解析の後、静的検査の前に雛形を展開する。雛形の呼び出しのそれぞれを、引数の組（位置を除いて同じ式なら同じ組とみなす）ごとの規則に置き換える
- 展開した規則の名前は生成器の内部の名前とし、利用者のコードからは見えない
- 型を宣言した引数には、型の分かる式だけを渡せる。規則の呼び出し（その規則の型）、テキストキャプチャ（`Text`）、別の雛形の呼び出し（置き換えた後の型）である。それ以外を渡すとエラーにする
- 雛形の本体が雛形を呼ぶ場合も展開する。展開が引数を大きくしながら続く場合（`T<p> <- T<(p p)>` など）は、展開の深さの上限でエラーにする
- 雛形は引数付き規則（[ADR 0012](0012-context-sensitive-extensions.md)）の引数を取れない。雛形は `%entry`、`%start`、`%recover` の規則にできない

### 構文木と誤りの報告

- `%syntax` の文法では、展開した規則は `%inline`（[ADR 0019](0019-lossless-syntax-tree.md)）として扱う。雛形の呼び出しはノードを作らず、子を呼び出し元に並べる
- 展開した規則の中の誤り（静的検査の誤り、GHC の型の誤り）は、雛形の定義の位置で報告し、どの呼び出しから展開したかを添える
- ラベルの安全性の検査（[ADR 0028](0028-label-safety-check.md)）は、展開した規則に対して行い、警告は雛形の定義の位置で報告する

## 実装しないこと

- 高階の Haskell 関数としての生成（上記）
- 雛形の部分適用や、雛形を引数として渡すこと
- 雛形と引数付き規則を組み合わせること
- 型変数を引数の型から推論すること。値を使う引数の型は、型注釈に型変数で書く

## テスト設計

- **展開**：同じ引数での二回の呼び出しが一つの規則になり、異なる引数では別の規則になること。メモ表が展開した規則ごとに別であること（評価の回数のフック）
- **型の置き換え**：`List<Exp, ','>` の型が `[Exp]` になり、生成コードがコンパイルできること。型の分からない引数を型を宣言した引数に渡すと、エラーになること
- **左再帰**：雛形の呼び出しを含む左再帰の文法（`E <- l:E Op<'+'> r:T` など）が、展開した後の規則で左再帰として扱われること
- **再帰的な展開**：雛形が雛形を呼ぶ文法の展開と、深さの上限のエラー
- **構文木**：雛形の呼び出しがノードを作らず、構文木がロスレスであること
- **誤りの位置**：展開した規則の中の誤りが、雛形の定義の位置と展開元の呼び出しで報告されること
- **書き直し**：Lua の文法の予約語の規則と区切りのある列を雛形で書き直し、Lua の適合性テストが通ること。TOML の文法の配列とインラインの表も同様にすること

## 実装の段階

[ADR 0030](0030-unit-values-are-not-counted.md) の後に行う。
記法の変更なので、採択するときに `docs/syntax.md` を更新する。
自己記述の文法（`Peg.peg`）に雛形の記法を加えるので、[ADR 0027](0027-switch-to-self-hosted-parser.md) の二回に分けた生成の手順に従う。

## トレードオフ

- 生成時の展開は、引数の組の数だけ規則とメモ表を増やす。生成コードとメモ表のメモリは、雛形を書き下した場合と同じであり、増えはしない
- 雛形の構文木のノードを作らない決定は、構文木の上で雛形の呼び出しを一つの単位として扱えないことを意味する。区切りのある列のように、呼び出し元のノードの子として並ぶほうが自然な用途を優先した
- 型注釈の型変数の置き換えは文字列の置き換えであり、型変数の名前が Haskell の型の名前と重なると誤る。型変数は小文字で始まる名前に限り、単語の境界で置き換える
