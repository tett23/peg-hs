# ADR 0066: 型注釈のない規則の型を () とする

ステータス: 採択→%syntax の文法の扱いは [ADR 0068](0068-untyped-rules-in-syntax-grammars.md)

## 文脈

[ADR 0004](0004-peg-notation.md) は、すべての規則に型注釈を求めた。
型注釈のない規則は、`rule A has no type annotation` の誤りになる。

リポジトリの文法には型注釈が 879 行あり、そのうち 241 行が `:: ()` である。
空白、区切り、キーワードを読む規則の多くは、型が `()` である。
[ADR 0063](0063-omit-unit-actions.md) と [ADR 0064](0064-unit-rules-always-return-unit.md) で、型が `()` の規則は値のない選択肢の `{ () }` を省略できるようになった。
型注釈も省略できれば、空白の規則は一行で書ける。

```text
Sp :: ()
Sp <- ' '*
```

が、次のようになる。

```text
Sp <- ' '*
```

型注釈は、規則の型のほかに二つのものを宣言する。
引数付き規則の引数（`B(ind :: Int) :: ()`、[ADR 0012](0012-context-sensitive-extensions.md)）と、雛形の引数（`List<p :: a, sep> :: [a]`、[ADR 0031](0031-rule-templates.md)）である。
これらは型注釈にしか書けないので、型注釈を省くと宣言できない。

型注釈を求める理由の一つは、書き忘れを見つけることだった。
型注釈を省いた規則を `()` とみなすと、値を返すつもりの規則で型注釈を書き忘れても、静的検査は誤りにしない。
ただし、その規則のアクションが `()` 以外の値を返せば、GHC が型の不一致を文法の行で報告する（[ADR 0014](0014-generated-module-api.md)）。
アクションを省略した選択肢が単位でない値を返す場合も同じである。
書き忘れは、静的検査の代わりに GHC が見つける。

## 実装すること

### 型注釈の省略

- 型注釈のない規則の型を `()` とする。`rule A has no type annotation` の誤りをなくす
- 型注釈のない規則は、単位の値の判定（[ADR 0030](0030-unit-values-are-not-counted.md)）でも、アクションの省略（[ADR 0063](0063-omit-unit-actions.md)、[ADR 0064](0064-unit-rules-always-return-unit.md)）でも、型注釈 `()` の規則と同じに扱う
- 引数付き規則と雛形は、これまでどおり型注釈を求める。引数を宣言できないためである。型注釈のない規則の定義に引数（`B(ind) <- ...`）や雛形の引数（`T<p> <- ...`）があれば、誤りにする。文言は `rule B has parameters, so it needs a type annotation` とする
- 型注釈だけで定義がない規則、型注釈の重複は、これまでどおり誤りにする

### 生成と道具

- 生成器は、型注釈のない規則を、型 `()` の規則として生成する。生成物は、`:: ()` を書いた場合と同じにする
- 言語サーバーのホバー（[ADR 0035](0035-language-server.md)）は、型注釈のない規則の型を `()` と示す
- 整形（[ADR 0032](0032-grammar-formatter.md)）は、型注釈を加えも消しもしない

### lint の info

- [ADR 0063](0063-omit-unit-actions.md) の info の水準（[ADR 0067](0067-lint-info-with-verbose.md)）に、規則 `omittable-unit-annotation` を加える
- 対象は、型注釈が `()`（空白を除いた文字列が `()`）で、引数も雛形の引数も持たない規則の型注釈である
- 位置は型注釈の始まりとし、文言は `the type annotation can be omitted: a rule without one has type () [omittable-unit-annotation]; remove the line A :: ()` とする

### リポジトリの文法の書き直し

- リポジトリのすべての文法から、この info が出る型注釈を機械的に除く
- 書き直した後に、生成物が書き直す前と同じ値を返すこと、`peg-hs lint --verbose` の出力が空であること、すべてのテストと適合性テストが通ることを確かめる

### 文書

- [docs/syntax.md](../syntax.md) の型注釈の節に、型注釈を省いた規則の型が `()` であることと、引数を持つ規則には型注釈が要ることを書く。よくある誤りの表の「型注釈を書き忘れた」を、引数を持つ規則の誤りに改める。冒頭の「反映している ADR」にこの ADR を加える
- docs/specifications.md の記法の説明と、README の例を新しい形にする
- [ADR 0004](0004-peg-notation.md) のステータスに、型注釈の省略がこの ADR にあることを加える

## 実装しないこと

- 型の推論。型注釈のない規則は、選択肢の値によらず `()` とする
- `()` 以外の既定の型
- 引数付き規則と雛形の型注釈の省略
- 整形による型注釈の自動の削除

## テスト設計

先に書き、いまの実装で失敗させる。

- **静的検査**：型注釈のない規則が誤りにならず、型が `()` として扱われること。型注釈のない規則を呼ぶグループで、その値を数えないこと（[ADR 0030](0030-unit-values-are-not-counted.md)）。型注釈のない規則で、値のない選択肢のアクションを省略できること（[ADR 0063](0063-omit-unit-actions.md)）
- **引数を持つ規則**：型注釈のない引数付き規則と雛形が、上の文言の誤りになること
- **生成**：型注釈のない規則を含む fixture の生成物が、`:: ()` を書いた版と、規則の型の部分を除いて同じ値を返すこと（プロパティテスト）。警告なしでコンパイルできること
- **書き忘れ**：型注釈のない規則のアクションが `Int` を返すと、生成したモジュールのコンパイルが、そのアクションの行を指す GHC の型の誤りになること
- **言語サーバー**：型注釈のない規則のホバーが `()` を示すこと
- **lint**：`:: ()` の型注釈に info が出て、引数付き規則と雛形の `:: ()` には出ないこと
- **リポジトリの文法**：書き直した後に、`peg-hs lint --verbose` の出力が空で、すべてのテストが通ること。範囲の一致の golden（[ADR 0034](0034-syntax-highlighting.md)）を作り直し、tree-sitter が `ERROR` なく読むこと

## トレードオフ

- 値を返すつもりの規則で型注釈を書き忘れても、静的検査では見つからない。アクションの型の誤りとして、GHC が文法の行で報告する。誤りの位置は文法を指すが、文言は「`()` を期待した」という GHC の文言になるので、静的検査の文言より分かりにくい
- 型注釈のある規則とない規則が混ざるので、規則の型を知るには、型注釈がないことも読み取る必要がある。言語サーバーのホバーが型を示す
- 引数を持つ規則だけが型注釈を求めるので、規則が一つ例外を持つ。引数を宣言する場所が型注釈しかないためである
- リポジトリの文法の書き直しで、差分が大きくなる。規則の実装とは別のコミットにする
