# ADR 0014: 生成モジュールの公開 API、名前の衛生、位置の規約

ステータス: 採択→エクスポートの選択は [ADR 0061](0061-select-generated-exports.md)

## 文脈

[ADR 0002](0002-standalone-code-generator.md) と [ADR 0003](0003-typed-semantic-actions.md) は、生成器が何を生成するかを定めたが、生成されたモジュールを利用者がどう呼ぶかは定めていない。
入口の関数の名前と型、失敗の型、エクスポートの範囲は、Hackage への公開後は PVP の管理対象になる（[ADR 0009](0009-hackage-publication.md)）。
実装者がその場で決めて golden テストに焼き付ける前に、ここで固める。

あわせて、次の三つを決める。

- **名前の衛生**：生成器が内部で使う識別子が、利用者が規則名や verbatim ブロックに書いた名前と衝突しない仕組み
- **位置の規約**：[ADR 0008](0008-source-positions.md) の `Pos` は「バイトオフセット、行、桁」とだけ定め、行と桁の数え方を定めていなかった
- **行番号の写像**：アクションの型の誤りが、生成されたファイルの行番号で報告される問題。[ADR 0002](0002-standalone-code-generator.md)、[ADR 0003](0003-typed-semantic-actions.md)、[ADR 0012](0012-context-sensitive-extensions.md) が未解決として残していた

公開 API の文書（Haddock）は英語で書く。
ADR と仕様書は日本語のままとする。

## 実装すること

### 入口

- 開始規則（[ADR 0004](0004-peg-notation.md) の `%start`、省略時は最初の規則）に対して、入口 `parse` を生成する
- `%entry Name` ディレクティブで、開始規則以外の規則にも入口を生成できる。入口の名前は `parse` に規則名を連結したもの（`%entry Term` なら `parseTerm`）とする。主な用途は、部分の規則の単体テストである
- 入口の型は `Text -> Either ParseError a` とする。`a` は規則の型である。文法が `%env E` を宣言している場合（[ADR 0012](0012-context-sensitive-extensions.md)）は `E -> Text -> Either ParseError a` とする
- 入口は入力の全体の消費を要求する。規則が成功しても入力が残っていれば失敗とし、その位置で入力の終端を期待した旨を期待集合に含める。入力の接頭辞だけを解析する入口は生成しない

### 失敗の型

`ParseError` は peg-runtime が定義し、生成コードはそれを返す。

- `ParseError` は、最遠位置の `Pos`、期待集合、失敗ラベルの三つを持つ。失敗ラベルの欄は [ADR 0005](0005-error-reporting.md) の予約に対応する席であり、v1 では常に空である
- 期待集合の要素は、リテラル、文字クラス、任意の一文字、入力の終端の四種とし、リテラルと文字クラスは文法に書かれた原文を保持する
- 期待集合は重複を除き、決まった全順序で並べて保持する。同じ入力に対して常に同じ値になり、表示も一意に決まる
- 人間向けの表示関数 `renderParseError` を peg-runtime が提供する。書式は `行:桁: expected A, B or C` とし、要素が一つなら `expected A` とする

### エクスポート

- 生成モジュールは明示的なエクスポート一覧を持つ。一覧に含めるのは、入口と、`%export` ディレクティブで指定した名前である
- `%export` には、verbatim ブロックで定義した名前を Haskell のエクスポート項目の書式で並べる（`%export Expr(..), evalExpr`）
- 規則の内部実装、メモ表のレコード、生成器の補助の名前はエクスポートしない。これらは PVP の管理対象外であり、生成器の版が変われば自由に変わる

### 名前の衛生

- 生成器が導入するトップレベルと局所の識別子は、すべて接頭辞 `peg'` を持つ（`peg'rule'Expr`、`peg'memo` など）
- 生成コードは、peg-runtime を別名 `PegRt` で、Prelude を別名 `PegPrelude` で、いずれも qualified に import して使う。利用者が verbatim ブロックで Prelude を隠しても、生成コードは影響を受けない
- 利用者の verbatim ブロックで、`peg'` で始まる名前を定義すること、`PegRt` と `PegPrelude` を別名に使うことを禁じる。生成器はトップレベルの定義と import の別名を字句の水準で検査し、該当すればエラーとする。局所の定義までは検査しない
- アクションの中で見える名前は、利用者の束縛、規則の引数、予約束縛（`_span`、[ADR 0012](0012-context-sensitive-extensions.md) の `_env` と `_col`）、verbatim ブロックと import に由来する名前に限る。生成器の局所変数は `peg'` 接頭辞によって、利用者の名前を隠さない

### 位置の規約

[ADR 0008](0008-source-positions.md) の `Pos` の各欄を次のように定める。

- **バイトオフセット**：入力の先頭を 0 とする UTF-8 のバイト単位の位置
- **行**：1 から数える。改行は LF だけとし、CRLF は CR を行末の一文字とする LF として数える。単独の CR は改行としない
- **桁**：1 から数える。Unicode のコードポイント一つを 1 桁とし、タブも 1 桁とする

行と桁を 1 から数えるのは、`ファイル:行:桁` の形の診断を多くのエディタが解釈できるためである。
[ADR 0012](0012-context-sensitive-extensions.md) の `_col` は 0 から数え、`%tabstop` でタブを展開する。
`_col` は照合の判断に使う計算上の値であり、タブ位置の剰余の計算に 0 始まりが向くため、`Pos` の桁とは別の規約のままとする。

### 行番号の写像

- 生成コードは、アクション、意味述語と引数の式（[ADR 0012](0012-context-sensitive-extensions.md)）、verbatim ブロック、型注釈を出力する箇所の直前に、`{-# LINE #-}` と `{-# COLUMN #-}` のプラグマを出力する。GHC はこれらの断片の型の誤りを `.peg` ファイルの行と桁で報告する
- 断片の直後には、生成ファイル自身の位置へ戻すプラグマを出力する
- 式の断片は括弧で囲み、`{-# COLUMN #-}` は断片の先頭の直前に同じ行で置く。GHC 9.10.3 で確かめたところ、`{-# COLUMN #-}` を行頭に単独で置くとレイアウト規則の上で字句として扱われ、構文エラーになった。括弧の内側で `{-# LINE #-}` を行頭に置き、次の行に `{-# COLUMN N #-}断片` と続ける形では、型の誤りが `.peg` の行と桁で報告された
- プラグマに書くファイル名は、生成器に与えられたパスをそのまま使い、絶対パスに直さない。生成の決定性（[ADR 0002](0002-standalone-code-generator.md)）を、実行するマシンのディレクトリ構成から独立させるためである。純関数の生成コア（`Grammar -> Text`）は、このファイル名を引数に取る

### 文書と警告

- peg-* の公開パッケージの公開モジュールは、Haddock を英語で書く
- 生成モジュールの入口には、英語の Haddock コメントを生成する（どの規則の入口であり、何を返すか）
- 生成器が出力した部分は、`-Wall` の下で警告を出さない。利用者が書いた断片の警告は利用者の責任とする

### 実装の段階

[ADR 0013](0013-roadmap-toolchain-memo.md) の順序のうち、位置の規約と失敗の型は段階 2（peg-runtime）で、それ以外は段階 3（peg-grammar のディレクティブの受理）と段階 4（peg-codegen）で実装する。

## 実装しないこと

- 入力の接頭辞だけを解析する入口、解析を再開する入口
- `String` や `ByteString` を受け取る入口。入力は `Text` だけとする
- 失敗の表示の多言語化、色付け、ソースの該当行の引用
- エクスポートの自動推論（verbatim ブロックの定義を解析して公開すべき型を推測すること）
- verbatim ブロックの局所の定義に対する名前の検査
- ADR と仕様書の英訳。翻訳の扱いは README で示す

## テスト設計

- **入口の型**：開始規則の入口、`%entry` による入口、`%env` を宣言した文法の入口が、それぞれ定めた型を持つこと（型を固定するコンパイルテスト）
- **全体の消費**：規則が成功して入力が残る場合に失敗し、期待集合に入力の終端が含まれること
- **期待集合の順序**：選択肢の順序を入れ替えた二つの文法で、同じ入力に対する `ParseError` が等しく、`renderParseError` の表示も一致すること
- **位置の規約**：LF、CRLF、単独の CR、タブ、マルチバイト文字を含む入力で、行、桁、バイトオフセットが規約どおりになること
- **名前の衛生**：verbatim ブロックで `peg'` で始まる名前を定義した文法と、`PegRt` を別名に使った文法がエラーになること。`import Prelude ()` を含む文法の生成コードがコンパイルできること。利用者の束縛名が、生成器のどの局所変数とも衝突せずに使えること
- **エクスポート**：`%export` に挙げた名前だけが入口とともに公開され、内部の名前が公開されないこと
- **行番号の写像**：型の誤りを含むアクションを持つ文法を生成してコンパイルし、GHC のエラーが `.peg` ファイルの該当の行と桁を指すこと
- **決定性**：同じ文法を異なる作業ディレクトリから同じ相対パスで生成し、出力がバイト単位で一致すること
- **警告**：警告を出さない利用者の断片だけからなる文法の生成コードが、`-Wall -Werror` でコンパイルできること

## トレードオフ

- 入力の全体の消費を要求するため、文書の一部だけを読みたい用途では、利用者が文法の末尾に任意の入力を受ける規則を書く必要がある
- `%export` を書かせるのは手間だが、エクスポートを自動で推論すると、生成器が利用者の Haskell コードを解析することになる。生成器は Haskell の構文を理解しない方針（アクションも波括弧の釣り合いで読む、[ADR 0004](0004-peg-notation.md)）を保つ
- 名前の検査は字句の水準なので、検査をすり抜ける書き方（CPP による定義など）は防げない。すり抜けた場合は GHC のコンパイルエラーとして現れ、黙って誤動作することはない
- `Pos` の桁と `_col` で数え方が異なるため、二つを混同した利用者は 1 桁と 0 始まりの差で誤る。syntax.md で両者の違いを明記する
- `%entry` と `%export` は [ADR 0004](0004-peg-notation.md) の記法に二つのディレクティブを加える。[ADR 0004](0004-peg-notation.md) の「未知のディレクティブはエラー」の規定とは、本 ADR が既知のディレクティブを増やす形で両立する
