# ADR 0040: 雛形を引数付き規則と組み合わせる

ステータス: 却下

## 文脈

規則の雛形（[ADR 0031](0031-rule-templates.md)）は、`List<p :: a, sep>` のように規則や式を引数に取り、呼び出しごとに別の規則へ展開する。
単相化によるジェネリクスである。
展開した後の規則は普通の規則なので、メモ化と左再帰（[ADR 0001](0001-bounded-left-recursion.md)）の意味論がそのまま保たれる。

ところが、引数付き規則（[ADR 0012](0012-context-sensitive-extensions.md)）を含む文法では、雛形が使えない。
[ADR 0031](0031-rule-templates.md) は「雛形と引数付き規則を組み合わせること」を実装しないことに挙げた。
使えない場面は二つある。

一つは、雛形の引数が呼び出し元の引数を使う場合である。

```
B(ind :: Int) :: ()
B <- Lines<Item(ind)> { () }

Lines<p> :: ()
Lines<p> <- p ('\n' p)* { () }
```

生成はできるが、展開した規則 `Lines'0 <- Item(ind) ('\n' Item(ind))*` には `ind` がなく、GHC が `Variable not in scope: ind` で失敗する。
展開した規則は呼び出し元の外にあるので、呼び出し元の引数が見えない。

もう一つは、雛形の本体が値の引数を必要とする場合である。
雛形は、規則や式の引数（`<...>`）しか取れない。
引数付き規則のような Haskell の値の引数（`(n :: Int)`）を宣言すると、「the template T cannot take parameters」で拒否される。

Golem の文法（`modules/golem-parser/grammar/Golem.peg`）は、字下げの深さを引数で渡す引数付き規則を多く使う。
同じ形が字下げの深さを変えて何度も現れる。

```
Blocks <- Block(ind) (BlankLines? &(Ind(ind) !BlankLine .) Block(ind))* { () }
BulletList <- ListItem(ind, 0) (BlankLines? ListItem(ind, 0))* { () }
OrderedList <- ListItem(ind, 1) (BlankLines? ListItem(ind, 1))* { () }
DefList <- DefGroup(ind) (BlankLines? &(Ind(ind) '=' [ \t]) DefGroup(ind))* { () }
DefBody <- &(Ind(ind + 2) ![ \t] !BlankLine .) Block(ind + 2) (BlankLines? &(Ind(ind + 2) ![ \t] !BlankLine .) Block(ind + 2))* { () }
```

「空行を挟んで同じものが続く」形は、雛形の典型である。
しかし、要素（`ListItem(ind, 0)`）は呼び出し元の `ind` を使い、続きの判定（`&(Ind(ind) …)`）は字下げの深さを値として要る。
いまの雛形では、どちらも書けない。

雛形の展開を高階の Haskell 関数に置き換える方式は、[ADR 0031](0031-rule-templates.md) が退けたとおり、メモ化と左再帰の検査を失う。
展開の方式を保ったまま、展開した規則に値の引数を持たせれば、二つの場面を解決できる。
展開した規則は引数付き規則になり、引数はメモ表の鍵に入る（[ADR 0012](0012-context-sensitive-extensions.md)）。

## 実装すること

### 雛形の値の引数

雛形は、規則や式の引数（`<...>`）に加えて、引数付き規則と同じ値の引数（`(...)`）を持てる。

```
Indented<p>(n :: Int) :: ()
Indented<p> <- &(Ind(n) ![ \t] !BlankLine .) p (BlankLines? &(Ind(n) ![ \t] !BlankLine .) p)* { () }

DefBody <- Indented<Block(ind + 2)>(ind + 2) { () }
```

- 型注釈では、雛形の引数の後に値の引数を書く（`Name<p :: a, sep>(n :: Int) :: T`）。定義には値の引数を書かない。引数付き規則と同じである
- 呼び出しでは、雛形の引数の直後に値の引数を書く（`Name<args>(vals)`）。`<` と `(` の間、`>` と `(` の間に空白を置かない
- 値の引数の数が合わない呼び出しは誤りにする。文言は引数付き規則の誤り（「rule N expects 1 argument(s), but got 2」）にならい、規則名の代わりに雛形の名前を書く
- 展開した規則は、雛形の値の引数をそのまま引数に持つ引数付き規則になる。呼び出しは、値の引数を渡す普通の規則の呼び出しに置き換わる。展開の鍵（雛形の引数の組）に値の引数は含めない。値は実行時に渡るからである

### 呼び出し元の引数を使う雛形の引数

雛形の引数の中の Haskell の断片（規則の引数、意味述語、雛形の値の引数）が、呼び出し元の規則の引数を使う場合、展開した規則はその引数を受け取る。

```
B(ind :: Int) :: ()
B <- Lines<Item(ind)> { () }
```

は、次のように展開する。

```
B <- Lines'0(ind) { () }

Lines'0(ind :: Int) :: ()
Lines'0 <- Item(ind) ('\n' Item(ind))* { () }
```

- 雛形の引数の断片を Haskell の字句に分け、呼び出し元の規則の引数の名前と一致する識別子を、展開した規則の引数にする。型は、呼び出し元の型注釈の型とする
- 展開した規則の引数の並びは、雛形の値の引数の後に、取り込んだ引数を名前の順に並べたものとする
- 展開の鍵に、取り込んだ引数の名前と型を加える。別の規則から同じ字句の引数（`Lines<Item(ind)>`）で呼んでも、`ind` の型が同じなら同じ展開した規則を使う。型が違えば別の規則になる
- 雛形の引数の断片が、呼び出し元の選択肢の束縛を使う場合は誤りにする。文言は「the argument of the template T uses the binding x, which a template cannot take; pass it as a value argument」とする。束縛の値は、雛形の値の引数として明示的に渡す
- 雛形が雛形を呼ぶ場合も同じ規則で展開する。展開した規則の引数は、内側の雛形の呼び出しの「呼び出し元の規則の引数」になる

### 静的検査と他の機能

- 展開した規則が引数を持つので、引数付き規則の制約がそのまま掛かる。左再帰に加わる展開した規則が引数を持てば、引数付き規則の左再帰の誤り（[ADR 0012](0012-context-sensitive-extensions.md)）になる。誤りは、[ADR 0031](0031-rule-templates.md) と同じく雛形の定義の位置で報告し、展開元の呼び出しを添える
- `%syntax` の文法では、展開した規則はこれまでどおり `%inline` として扱う
- ラベルの安全性の検査（[ADR 0028](0028-label-safety-check.md)、[ADR 0038](0038-label-check-precision-and-strip-labels-entries.md)）は、展開した後の文法に対して行う。展開した規則の呼び出しは引数付き規則の呼び出しなので、[ADR 0038](0038-label-check-precision-and-strip-labels-entries.md) の引数の置き換えがそのまま働く
- 記法の自己記述の文法（`grammar/Peg.peg`）の `Primary` に、値の引数を持つ雛形の呼び出しを加える。AST の `ETemplate` に値の引数を加える
- 整形（[ADR 0032](0032-grammar-formatter.md)）、lint（[ADR 0033](0033-grammar-linter.md)）、ハイライト（[ADR 0034](0034-syntax-highlighting.md)）、言語サーバー（[ADR 0035](0035-language-server.md)）を、値の引数を持つ雛形の呼び出しに対応させる。lint の使われない束縛の判定は、値の引数の断片も束縛の使用とみなす

### 文書

- [docs/syntax.md](../syntax.md) の雛形の節に、値の引数と、呼び出し元の引数を使う雛形の引数を書く。冒頭の「反映している ADR」に本 ADR を加える
- [ADR 0031](0031-rule-templates.md) のステータスを「採択→雛形と引数付き規則の組み合わせは ADR 0040」に変える

## 実装しないこと

- 雛形の展開を高階の Haskell 関数に置き換えること（[ADR 0031](0031-rule-templates.md) と同じ理由）
- 雛形の引数の断片で、呼び出し元の選択肢の束縛を使うこと。束縛の型は、束縛した式から推論しないと分からない。値の引数で明示的に渡す
- 雛形を雛形の引数として渡すこと（高階の雛形）と、雛形の部分適用。Golem の文法を含め、リポジトリの文法に必要な場面が見つかっていない
- 値の引数を使う雛形の引数の型の推論（[ADR 0031](0031-rule-templates.md) と同じく、値を使う雛形の引数は型変数を宣言する）
- `%entry`、`%start`、`%recover` に雛形を指定すること（[ADR 0031](0031-rule-templates.md) と同じ）

## テスト設計

### 展開

- 呼び出し元の引数を使う雛形の引数（`B(ind) <- Lines<Item(ind)>`）が、引数 `ind :: Int` を持つ展開した規則になり、呼び出しが `Lines'0(ind)` になること
- 二つの規則から同じ字句と同じ型の引数で呼ぶと、展開した規則が一つになること。型が違うと別の規則になること
- 雛形の値の引数（`Indented<p>(n :: Int)`）を持つ雛形の展開した規則が、`n` を引数に持つこと。値の引数と取り込んだ引数の並びが、値の引数、取り込んだ引数（名前の順）であること
- 雛形が雛形を呼ぶとき、外側の展開した規則の引数を内側の雛形の引数が使えること

### 誤り

- 雛形の引数が呼び出し元の束縛を使うと、上の文言の誤りになること
- 値の引数の数が合わない呼び出しが誤りになること。値の引数を宣言していない雛形に値の引数を渡すと誤りになること
- 雛形の定義に値の引数を書くと、引数付き規則と同じ誤りになること
- 引数を取り込んだ展開した規則が左再帰に加わると、引数付き規則の左再帰の誤りになり、雛形の定義の位置と展開元の呼び出しで報告されること

### 生成と実行

- codegen の fixture に、Golem の形を写した文法（字下げの深さを引数で渡す、空行を挟んで同じものが続く入れ子のリスト）を加え、生成コードが警告なしでコンパイルでき、入れ子の深さごとに期待どおりの値を返すこと
- 同じ fixture に `%syntax` を付けた版で、構文木がロスレスであること
- 雛形を書き下した文法と、雛形を使った文法とで、無作為な入力に対する受理と値が一致すること（プロパティテスト）

### 周辺の機能

- 記法の文法：`Name<args>(vals)` の解析、`Name<args> (vals)`（空白あり）が値の引数として読まれないこと（逐次の二つの要素になること）
- 整形：golden に値の引数を持つ雛形の型注釈と呼び出しを加えること
- lint：値の引数の断片の中の束縛を使用とみなすこと
- ハイライト：tree-sitter のコーパスとハイライトのテスト、TextMate のスナップショットに値の引数を持つ呼び出しを加えること。三つの文法の範囲の一致のテストが通ること
- 言語サーバー：値の引数を持つ雛形の呼び出しの semantic tokens（`macro`）と、定義への移動

### 既存の文法

- リポジトリのすべての文法の生成物が変わらないこと。値の引数を持つ雛形も、引数を取り込む雛形の引数も、まだ使っていないため

## トレードオフ

- 取り込む引数の判定は字句の一致による。雛形の引数の断片の中で、呼び出し元の引数と同じ名前を局所的に束縛すると（`\ind -> …` など）、不要な引数を取り込む。展開した規則に使われない引数が一つ増えるだけで、値は変わらない。生成コードの未使用の変数の警告を避けるため、取り込んだ引数のうち展開した規則が使わないものは `_` で始まる名前で受ける
- 展開した規則が引数付き規則になるので、引数付き規則の制約（左再帰に加われないこと）を受ける。引数を取り込まない雛形の呼び出しは、これまでどおり左再帰に加われる
- 取り込んだ引数の型を鍵に含めるので、同じ字句の引数でも型の違う規則から呼ぶと展開した規則が増える。型の違う規則から同じ雛形を呼ぶ文法は少ないと見込む
- 呼び出しで `>` と `(` の間に空白を置けない。`Lines<p> (x)` は、雛形の呼び出しと括弧のグループの逐次として読む。引数付き規則の呼び出し（`Name(args)`）と同じ規則である
