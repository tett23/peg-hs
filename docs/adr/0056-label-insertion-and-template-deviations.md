# ADR 0056: ラベルの挿入と雛形の実装で ADR から外れた点

ステータス: 採択

## 文脈

[ADR 0054](0054-automatic-label-insertion.md)（ラベルの挿入と回復の提案）と [ADR 0055](0055-templates-and-parameterized-rules-in-stages.md)（雛形と引数付き規則）を実装したところ、ADR のとおりでは ADR 自身のテスト設計を満たせない箇所が見つかった。
実装は、テスト設計を満たす側に合わせて ADR から外れた。
外れた点は、どれも利用者に見える振る舞いに関わる。
コミットした ADR は書き換えられないので、本 ADR で外れた点を記録し、仕様として追認する。

外れた点は四つある。

### ラベルの安全性の検査がラベルを数えていた

ラベルの安全性の検査（[ADR 0028](0028-label-safety-check.md)、[ADR 0038](0038-label-check-precision-and-strip-labels-entries.md)）は、失敗した選択肢と後の選択肢を比べるとき、二つが同じ要素で始まれば、共通の部分を除いて比べる。
この「同じ要素」の判定は、要素の式をそのまま比べていた。
そのため、二つの選択肢の片方にだけラベルが付いていると（`'a' ^x 'b'` と `'a' 'c'`）、`'a' ^x` と `'a'` を別の要素とみなし、共通の部分を短く数えていた。

[ADR 0054](0054-automatic-label-insertion.md) は、安全と判定した候補を一つずつ選び、まとめて挿入する。
テスト設計は、まとめて挿入しても受理する言語が変わらないこと、既存のラベルへの警告が挿入の前と変わらないことを求める。
ところが、ラベルを一つ挿入すると、ほかのラベルの判定で共通の部分の長さが変わり、判定が変わることがあった。

[ADR 0029](0029-label-safety-implementation-deviations.md) は、各ラベルを、ほかのラベルをすべて外した文法の上で判定すると定めている。
ほかのラベルがない文法では、`'a' ^x` と `'a'` は同じ要素である。
判定の定義は [ADR 0029](0029-label-safety-implementation-deviations.md) のままで、比べ方がその定義に合っていなかったことになる。

### ラベルの挿入が lint の警告を消していた

lint の `unreachable-alternative`（[ADR 0033](0033-grammar-linter.md)）は、必ず成功する選択肢（`e?`、`e*` など）の後ろの選択肢を警告する。
lint は、ラベルを含む `e?` や `e*` を「必ず成功する」とはみなさない。
ラベルの送出は、`?` や `*` を素通りして選択肢を失敗させるからである。

そのため、必ず成功する選択肢の中にラベルを挿入すると、その選択肢は lint の上で必ず成功するものでなくなり、後ろの選択肢への警告が消える。
[ADR 0054](0054-automatic-label-insertion.md) のテスト設計は、挿入の前後で lint の結果が変わらないことを求めており、プロパティテストがこの反例を見つけた。
後ろの選択肢が決して試されないという問題は、ラベルを挿入しても残るので、警告が消えるのは誤りである。

### ラベルの挿入の ADR の例の文法を解析できない

[ADR 0054](0054-automatic-label-insertion.md) の「例」の節の文法は、`vs:(',' n:Num { n })*` のようにグループの中にアクションを書いている。
記法はグループの中のアクションを受け付けない（[ADR 0030](0030-unit-values-are-not-counted.md) の誤り）ので、この文法は解析できない。
例が示す挿入の結果（`^List_Num`、`^List_Num_2`、`^List_rbracket`）そのものは正しい。

### 雛形の本体が雛形の引数をそのまま渡すと、展開が終わらなかった

雛形の本体が、自分の雛形の引数を、そのまま別の雛形の呼び出しに渡すことがある（`Rec<p> <- Rec<p> ...` のように自分を呼ぶ場合を含む）。
これまでの展開は、値の使われない位置に置かれた引数を `EDiscard` で包んで渡していた（[ADR 0026](0026-discard-unused-values.md)）。
包むと引数の式が変わるので、展開の鍵（雛形の名前と引数の組）が呼び出しのたびに変わり、自分を呼ぶ雛形は同じ展開した規則に戻れず、「展開が終わらない」誤りになっていた。

[ADR 0055](0055-templates-and-parameterized-rules-in-stages.md) の段階 1 のテスト設計は、引数を取り込んだ展開した規則が左再帰に加わると、引数付き規則の左再帰の誤りになることを求める。
このテストを書くには、自分を呼ぶ雛形が展開できる必要があった。

## 実装すること

実装はすでに行った（[ADR 0054](0054-automatic-label-insertion.md) と [ADR 0055](0055-templates-and-parameterized-rules-in-stages.md) の pull request）。
本 ADR は、その振る舞いを仕様として定める。

### ラベルを除いて比べる

- ラベルの安全性の検査は、選択肢の共通の部分を数えるとき、要素の式からラベルを除いてから比べる。`'a' ^x` と `'a'` は同じ要素である
- これは [ADR 0029](0029-label-safety-implementation-deviations.md) の定義（ほかのラベルをすべて外した文法の上で判定する）に比べ方を合わせるものであり、定義は変えない
- リポジトリの文法と既存のテストの判定は変わらない

### lint が必ず成功するとみなす選択肢には挿入しない

- `peg-hs label` と言語サーバーのコードアクションは、lint が必ず成功するとみなす選択肢（後ろに選択肢があるもの）の中の位置を、候補にしない
- その選択肢から先読みの外で呼ぶ規則の中の位置も、候補にしない。そこにラベルを挿入しても、同じく lint の判定が変わるからである
- この除外を、[docs/syntax.md](../syntax.md) のラベルの挿入の説明と、`Peg.Grammar.LabelInsertion` の Haddock に書く

### ラベルの挿入の ADR の例の訂正

- 例の文法を、グループの中にアクションを書かない形（`vs:(',' Num)*` と `Num <- [0-9]+ { 1 }`）とする。挿入の結果は [ADR 0054](0054-automatic-label-insertion.md) の例と同じである
- テストと [docs/syntax.md](../syntax.md) の例は、この形で書く

### 雛形の引数をそのまま渡す

- 雛形の本体の中で、雛形の引数をそのまま別の雛形の呼び出しの引数に渡すときは、`EDiscard` で包まずに渡す。展開の鍵が呼び出しのたびに変わらず、自分を呼ぶ雛形も同じ展開した規則に戻れる
- 渡した引数の値を使うかどうかは、渡した先の雛形が決める。渡した先の本体で値が使われない位置に置かれれば、そこで [ADR 0026](0026-discard-unused-values.md) のとおり値を捨てる
- リポジトリの文法の生成物は変わらない

## 実装しないこと

- ラベルの安全性の検査の定義（[ADR 0029](0029-label-safety-implementation-deviations.md)）の変更
- lint の `unreachable-alternative` の判定の変更。ラベルを含む `e?` を必ず成功するとみなすと、ラベルの送出で選択肢が失敗する場合を見落とす
- コミット済みの [ADR 0054](0054-automatic-label-insertion.md) と [ADR 0055](0055-templates-and-parameterized-rules-in-stages.md) の書き換え。ステータスの行だけを本 ADR を指すように変える

## テスト設計

どれも、[ADR 0054](0054-automatic-label-insertion.md) と [ADR 0055](0055-templates-and-parameterized-rules-in-stages.md) の実装で加えたテストが確かめている。

- **ラベルを除いて比べる**：候補をまとめて挿入しても、既存のラベルへの警告と、挿入したラベルの判定が、一つずつ判定したときと変わらないこと（ラベルの挿入のプロパティテスト）。既存のラベルの検査のテストと golden が変わらないこと
- **lint の除外**：挿入の前後で lint の警告が変わらないこと（プロパティテスト）。必ず成功する選択肢の中と、そこから呼ぶ規則の中の位置が候補にならないこと（単体のテスト）
- **例の訂正**：訂正した例の文法で、挿入の結果が [ADR 0054](0054-automatic-label-insertion.md) の例と同じであること
- **雛形の引数**：自分を呼ぶ雛形が展開でき、引数を取り込んだ展開した規則が左再帰に加わると引数付き規則の左再帰の誤りになること。リポジトリのすべての生成物が変わらないこと

## トレードオフ

- lint の除外によって、必ず成功する選択肢の中にはラベルを挿入できない。この選択肢の後ろには決して試されない選択肢があり、lint が警告するので、文法を直した後にもう一度 `peg-hs label` を実行すれば候補になる
- 実装の後に ADR を追認する順になった。ADR を先に書く手順から外れるが、どれも ADR 自身のテスト設計を満たすための変更であり、テストが先に失敗して見つかったものである
