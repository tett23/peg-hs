# ADR 0065: 束縛した値をそのまま返すアクションを lint で知らせる

ステータス: 採択

## 文脈

アクションを省略した選択肢は、値を持つ要素がちょうど一つなら、その値をそのまま返す（[ADR 0004](0004-peg-notation.md)、[ADR 0030](0030-unit-values-are-not-counted.md)）。
そのため、要素を一つ束縛して、その名前だけをアクションで返す選択肢は、束縛とアクションを消しても値が変わらない。

```text
Inlines <- is:Inline* { is }        # Inlines <- Inline* と同じ
Paren <- '(' Sp e:Expr ')' Sp { e }  # Paren <- '(' Sp Expr ')' Sp と同じ
```

リポジトリの文法には、束縛した名前だけを返すアクションが約 196 か所ある（正規表現で数えた概算）。
[ADR 0063](0063-omit-unit-actions.md) は、省略できる `{ () }` を lint で知らせることにした（知らせの水準は [ADR 0067](0067-lint-info-with-verbose.md) で info とした）。
束縛した値をそのまま返すアクションも、同じ種類の、省略できる書き方である。

ただし、どれもが消せるわけではない。
束縛した名前を、同じ選択肢の意味述語や規則の引数でも使っている場合（`n:Num &{ n > 0 } { n }`）、束縛は消せない。
`%syntax` の文法では、束縛は構文木の取り出し関数の名前にもなる（[ADR 0019](0019-lossless-syntax-tree.md)）。
束縛を消すと、生成モジュールの公開する関数が減る。

## 実装すること

### lint の info

- [ADR 0063](0063-omit-unit-actions.md) の info の水準（[ADR 0067](0067-lint-info-with-verbose.md)）に、規則 `omittable-identity-action` を加える
- 対象は、次をすべて満たす選択肢である
  - アクションのコードが、空白を除いて、選択肢のある一つの束縛の名前だけである（`{ e }`）
  - その名前を、同じ選択肢の意味述語、規則の引数、雛形の引数のどれにも使っていない
  - 束縛とアクションを消した選択肢で、値を持つ要素として数えられるのが、その要素ちょうど一つである（[ADR 0004](0004-peg-notation.md)、[ADR 0030](0030-unit-values-are-not-counted.md)）。ほかに束縛した要素があれば対象にしない
  - 文法が `%syntax` を持たない
- 位置はアクションの始まりとし、文言は `the action can be omitted: it returns the value of the binding e, which the alternative returns without the action [omittable-identity-action]; remove e: and { e }` とする
- info なので、`peg-hs lint` の終了状態を変えず、`--verbose` を付けたときだけ表示する。言語サーバーは重大度 Hint で報告する（[ADR 0067](0067-lint-info-with-verbose.md)）

### リポジトリの文法の書き直し

- リポジトリのすべての文法から、この info が出る束縛とアクションを機械的に除く
- 書き直した後に、`peg-hs lint --verbose` の出力が空であること、すべてのテスト（適合性テストを含む）が通ること、適合性テストの結果が変わらないことを確かめる

### 文書

- [docs/syntax.md](../syntax.md) の「アクションの省略」と lint の節に、この info を書く。冒頭の「反映している ADR」にこの ADR を加える
- README の lint の説明と docs/specifications.md の lint の説明に、規則を加える

## 実装しないこと

- 記法の変更。省略はいまの記法でできる
- `%syntax` の文法での info。束縛が取り出し関数の名前になるので、消すと公開する関数が変わる
- アクションの式を解析した判定（`{ (e) }` や `{ id e }` を同じとみなすこと）。コードが束縛の名前だけの場合に限る
- 整形による自動の削除。整形は字句を変えない（[ADR 0032](0032-grammar-formatter.md)）

## テスト設計

先に書き、いまの実装で失敗させる。

- **info が出る場合**：`is:Inline* { is }`、単位の要素を挟む `'(' Sp e:Expr ')' Sp { e }`、キャプチャ `d:$[0-9]+ { d }`
- **info が出ない場合**：名前を意味述語で使う（`n:Num &{ n > 0 } { n }`）、規則の引数で使う、束縛が二つある、アクションが名前以外（`{ negate n }`、`{ (n) }`）、`%syntax` の文法、束縛を消すと値を持つ要素が二つになる選択肢
- **値が変わらないこと**：info に従って書き直した codegen の fixture が、書き直す前と同じ値と最遠の失敗の位置を返すこと（プロパティテスト）
- **出力**：lint の出力の golden に info を加えること。info だけの文法で、`--verbose` を付けると info を表示し、付けないと何も表示せず、どちらも終了状態が 0 であること
- **リポジトリの文法**：書き直した後に、`peg-hs lint --verbose` の出力が空で、すべてのテストが通ること

## トレードオフ

- 束縛の名前は、値の意味を読み手に伝える役目も持つ（`e:Expr` の `e`）。消すと短くなるが、その名前は消える。規則の名前（`Expr`）が同じ情報を持つことが多いので、消す形にそろえる
- `%syntax` の文法には info を出さないので、`%syntax` の有無で書き方がそろわない。構文木の取り出し関数を変えないことを優先する
- info の規則が一つ増え、lint の出力の読み手が見分ける規則が増える
