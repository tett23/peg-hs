# ADR 0009: Hackage 公開を前提とし、パッケージ名は peg-* で確定する

ステータス: 採択

## 文脈

Hackage では `peg` の名前は既に取られている（PEG とは無関係の concatenative 言語、2012 年から更新なし）。
一方 `peg-runtime` をはじめ `peg-*` の名前空間は空いており、既存の Haskell PEG 系（peggy、papillon、frisby）とも衝突しない。

公開を後回しにする案（git 参照で開発し、安定後に公開を判断する）も検討したが、最初から公開を前提とすることに決めた。
公開前提は PVP 準拠、Haddock、パッケージメタデータの整備を最初から義務にする。
このコストを初期から払うかわりに、公開直前の一括整備（往々にして手抜きになる）を避け、API の変更を PVP のバージョン番号として常に記録する。

## 実装すること

- パッケージ名を `peg-runtime` / `peg-grammar` / `peg-codegen` / `peg-cli` で確定し、この名前で Hackage に公開する
- ライセンスは MIT とする（Golem と同一。リポジトリの LICENSE に配置済み）
- 全パッケージで最初から次を整備する
  - PVP 準拠のバージョニング。1.0 到達までは 0.x とし、破壊的変更はメジャー相当の桁（0.x の x）を上げて明示する
  - 公開モジュール全体の Haddock
  - cabal メタデータ（synopsis、description、license、source-repository）
- 最初のアップロードは、非左再帰の生成器が end-to-end で実働した時点を目安とする。1.0 は自己記述化の完了と Golem での実利用を条件とする
- Golem からの参照は、Hackage 掲載までは `source-repository-package` の git ピン、掲載後は通常のバージョン境界に切り替える

## 実装しないこと

- 1.0 より前の API 安定保証はしない。安定性の約束（[ADR 0008](0008-source-positions.md) の位置型など）は「変更時に PVP で通知する」の意味であり、凍結ではない
- Stackage への登録は 1.0 後に検討する
- 固有名（happy / peggy のような命名）への改名は行わない。公開後の改名は事実上の新パッケージであり、選択肢から外す

## テスト設計

- CI で全パッケージの `cabal check` が警告なしに通ること
- CI で Haddock がエラーなしに生成できること
- `cabal sdist` から取り出した tarball 単体でビルドできること（公開物の自己完結性）

## トレードオフ

- 文書化とメタデータの整備コストを開発初期から払う。設計変更のたびに Haddock の追従が要る
- `peg-*` は汎用接頭辞であり、4 パッケージで押さえることになる。内容をそのまま言う名前である利点を優先した
- 公開後は名前の変更がきかない。この ADR の決定は他の ADR より不可逆性が高い
