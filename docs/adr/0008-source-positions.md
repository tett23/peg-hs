# ADR 0008: 暗黙束縛 _span による位置取得と、安定公開の位置型

ステータス: 採択

## 文脈

型付きアクション（[ADR 0003](0003-typed-semantic-actions.md)）は束縛した値しか参照できず、確定済みの記法（[ADR 0004](0004-peg-notation.md)）にはソーススパンを取る手段がなかった。
最初の利用者である Golem は AST のノードにスパンを持たせ、診断（golem-syntax）がそれを指す。
この用途は汎用的でもある（エラー位置を持つ AST は PEG の利用先の大半で要る）。

依存の向きは仕様書で確定している。
peg-hs は Golem に依存しないので、決めるのは「アクションがスパンをどう取るか」と「golem 側がどの型で受けるか」の二点である。

## 実装すること

### 暗黙の予約束縛 `_span`

- すべてのアクションで、予約識別子 `_span` が「その選択肢が消費した入力の範囲」に束縛される
- 範囲の開始は選択肢の評価開始位置、終了は最後に入力を消費した位置とする。述語（`&` `!`）は入力を消費しないため範囲に影響しない
- 名前を `_span` とするのは GHC の慣習を利用するためである。アンダースコア始まりの識別子は未使用でも警告されないので、生成コードは `_span` を無条件に束縛でき、アクションが使うかどうかを判定する必要がない
- アンダースコア始まりの束縛名はすべて生成器の予約とする。ユーザーが `名前:式` の束縛にアンダースコア始まりの名前を使ったら静的検査でエラーとし、将来の暗黙束縛の追加余地を確保する

### 安定公開の位置型

- peg-runtime は `Pos`（バイトオフセット、行、桁）と `Span`（開始と終了の `Pos`）を公開 API として安定させる。`_span` の型は この `Span` である
- ファイルの識別は peg-runtime の関知事項としない。パーサーは単一の `Text` を解析し、スパンはその入力内の範囲である。どのファイルかは呼び出し側が管理する
- golem-syntax への受け渡しは、golem-parser に置く変換アダプタで行う（実装は Golem リポジトリ側の作業であり、peg-hs は型の安定性だけを約束する）

## 実装しないこと

- 明示の位置マーカー（`p:@` のような構文）は導入しない。選択肢全体のスパンで足りない用途（途中の一点が欲しい場合）は規則の分割で表現できる。実需が示されたら新たな ADR で検討する。`^` と異なり予約もしない。新しい一次式トークンの追加は結合の強さの表に影響しないためである
- 位置型の多相化（生成コードを位置型でパラメトリックにする）はしない。生成コードの型の単純さを優先する

## テスト設計

- **範囲の正確さ**：`_span` が選択肢の消費範囲と一致すること。先頭・末尾の位置、述語が範囲を動かさないこと、複数行とマルチバイト文字を跨ぐ場合の行・桁とオフセットの整合
- **予約の検査**：アンダースコア始まりのユーザー束縛が静的エラーになること
- **左再帰との整合**：成長ループがアクションを再実行しても（[ADR 0001](0001-bounded-left-recursion.md)）、最終的に確定した結果の `_span` が最長一致の範囲を指すこと
- **コンパイルテスト**：`_span` を使う文法と使わない文法の両方で、生成コードが警告なしにコンパイルできること

## トレードオフ

- 暗黙束縛は「文法に書いていない名前がアクションで使える」というマジックであり、記法だけを読んだ利用者には見えない。記法のリファレンスに明記して補う
- 選択肢全体のスパンしか取れないため、粒度を細かくするには規則を分割する必要がある。分割はメモ化の単位を細かくする方向であり、[ADR 0004](0004-peg-notation.md) の束縛の制約と同じ性質のため許容する
