# ADR 0010: JSON パーサーを生成し、適合性テストとする

ステータス: 採択

## 文脈

[ADR 0001](0001-bounded-left-recursion.md)〜[0009](0009-hackage-publication.md) のテスト設計は、どれも機構単位の検証である。
生成器が実用的な文法を端から端まで処理できるかは、どの ADR も確かめていない。
文法、静的検査、コード生成、型付きアクション、メモ化、エラー報告が一度に噛み合う場面は、実在する言語の文法を書いて初めて現れる。

JSON はその最初の対象に向いている。
文法が小さく（RFC 8259 の ABNF は一画面に収まる）、仕様の解釈に揺れが少なく、正解の判定に使える公開のテストスイートがある。
nst/JSONTestSuite（MIT ライセンス）は、受理すべき入力（`y_`、95 件）、拒否すべき入力（`n_`、188 件）、受理と拒否のどちらも許される入力（`i_`、35 件）を分けて収録している。

また、JSON の文法は左再帰を必要としない。
[ADR 0009](0009-hackage-publication.md) は最初の Hackage アップロードを「非左再帰の生成器が end-to-end で実働した時点」としていたが、その時点の判定基準は定めていなかった。
本 ADR の合格をその判定基準とする。

## 前提

- peg-grammar、peg-codegen、peg-runtime の非左再帰部分が実装済みであること
- テストフレームワークとビルド構成が決まっていること（本 ADR では選ばない）

## 実装すること

### 配置

- リポジトリ直下の `conformance/` に、非公開の cabal パッケージ `peg-conformance` を置く。`packages/` の公開パッケージ群とは分け、[ADR 0009](0009-hackage-publication.md) の公開義務（PVP、Haddock、`cabal sdist` の自己完結性）の対象外とする
- 後続の適合性テスト（[ADR 0011](0011-commonmark-expressiveness-probe.md) など）も同じパッケージに追加する

### 文法と AST

- `conformance/json/Json.peg` に RFC 8259 の文法を書く
- AST は `peg-conformance` 内に定義する代数的データ型とする（null、真偽値、数、文字列、配列、オブジェクト）
- 数は字句をそのまま `Text` で保持する。数値への変換は行わず、精度や範囲の扱いを AST に持ち込まない
- 文字列はエスケープを復号して保持する。`\uXXXX` のサロゲートペアは一つのコードポイントに結合する
- オブジェクトはキーと値の組の列として出現順に保持し、重複キーを取り除かない

### 生成物の扱い

- 生成した Haskell モジュールを `conformance/json/` 以下にコミットする
- テストはその場で文法から再生成し、コミット済みの生成物とバイト単位で一致することを検査する（[ADR 0002](0002-standalone-code-generator.md) の決定性の、実用文法での確認）

### テストデータ

- JSONTestSuite の `test_parsing/` を `conformance/data/JSONTestSuite/` に取り込む。取り込んだコミットのハッシュと LICENSE を同じディレクトリに置く
- 入力ファイルはバイト列として読み、UTF-8 として厳格に復号してからパーサーに渡す。復号の失敗は拒否として数える

## 実装しないこと

- 数値の解釈（整数と浮動小数点の区別、範囲検査）
- JSON5、コメント、末尾のカンマなどの拡張構文
- 重複キーの検出や除去
- aeson など既存の JSON ライブラリとの互換性。依存にも入れない
- UTF-8 以外の文字符号化の受理（UTF-16 の入力は復号の段階で拒否される）

## テスト設計

- **受理**：`y_` の全件を受理すること
- **拒否**：`n_` の全件を拒否すること。拒否が復号の段階によるものか文法によるものかは区別せず記録する
- **処理系定義**：`i_` の各件について受理か拒否かの結果をファイルに記録し、結果が変わったらテストを失敗させる。どちらが正しいかは問わず、意図しない変化だけを検出する
- **深い入れ子**：`n_structure_100000_opening_arrays` が、スタック溢れやメモリ不足で異常終了せず、拒否として終わること
- **往復**：無作為に生成した AST を手書きの直列化関数で文字列にし、生成パーサーで読み戻した結果が元の AST と一致すること（プロパティテスト）
- **エラー位置**：`n_` のうち代表的な数件について、最遠位置と期待集合（[ADR 0005](0005-error-reporting.md)）が人間の目で妥当な位置を指すことを golden テストで固定する
- **決定性**：上記「生成物の扱い」の再生成一致

## トレードオフ

- JSON は左再帰を含まないため、本 ADR の合格は [ADR 0001](0001-bounded-left-recursion.md) の機構について何も保証しない。左再帰の実用文法での検証は別に要る
- 数を字句のまま保持するため、AST は利用者向けの JSON 型としては不便である。目的が生成器の検証であり、JSON ライブラリの提供ではないための割り切りである
- 本 ADR の文法と入力は、[ADR 0007](0007-performance-discipline.md) のベンチマークの入力としても使える。巨大な JSON 文書はメモ表の常駐量の計測に向く
