## 対象と前提

CLI のプロセス起動、ファイル探索・入出力・コンパイルキャッシュ、文法のテンプレート展開、生成器、runtime の反復と文字列照合、LSP の通信処理、VS Code 拡張、tree-sitter の外部 scanner、CI / リリース workflow を重点的に読んだ。生成済みの巨大なパーサー全体や適合性データを全行精査した監査ではない。

想定する入力境界は、第三者から取得した文法・リポジトリ、共有一時ディレクトリ、LSP クライアントからの標準入力、配布物を作成する外部依存関係である。LSP は標準入出力で動作し、ネットワーク待受けは実装していない。

文法の Haskell 埋め込みコードは実行可能なコードである。`parse` は GHC で生成コードをコンパイルして実行するため、信頼できない文法を安全なデータとして扱うことはできない。これは設計上の信頼境界として扱い、文法だけでコードを書けることを新規の任意コード実行脆弱性とは数えない。コンパイル自体も隔離対象になる。

## SEC-01: 自動探索がシンボリックリンクを辿る

根拠: `packages/peg-cli/app/Files.hs:24-35`、`packages/peg-cli/app/Command/Fmt.hs:35-53`、`packages/peg-cli/app/FileIO.hs` の `writeUtf8`。

`walk` は `doesDirectoryExist` で判定したディレクトリを再帰的に探索するが、シンボリックリンクの検査も探索ルート内への包含確認も行わない。列挙された `.hpeg` は `fmt` によって直接書き戻される。ファイルへのリンクも拡張子が `.hpeg` なら同じ問題を起こし得る。

攻撃者がリポジトリ内に対象外を指すリンクを置き、利用者がそこで `peg-hs fmt`、またはそのディレクトリを指定した `fmt` を実行すると、利用者が書き込める外部の文法ファイルも変更される。任意のバイト列を自由に書き込む攻撃ではなく、整形可能な文法への予期しない変更である。循環するディレクトリリンクにも訪問済み判定がないが、その停止条件・影響は今回測定していない。

一時領域に `repo/linked -> ../outside` と `outside/Victim.hpeg` を作り、`repo` を cwd として実行した。終了コードは0、外部ファイルは次のように変化した。

```text
変更前: %module M\nS :: ()\nS <-   'a'    { () }\n
変更後: %module M\n\nS :: ()\nS <- 'a' { () }\n
```

対処: 自動探索ではファイル・ディレクトリ双方のリンクを既定で除外する。リンクを許容する場合は、実体パスが探索ルート内にあることと訪問済みディレクトリを確認する。敵対的な同時変更まで想定する場合、事前の実体パス検査だけでは競合を防げないため、書込み時のリンク追従も制限する。明示的に指定したリンクの扱いは、自動探索とは分けて仕様化する。

修正後の確認: 外部ディレクトリリンク、外部ファイルリンク、循環リンクを一時領域で作り、外部ファイルが変わらず探索が有限時間で終わることを検証する。再現用スクリプトは [reproduce-symlink.sh](reproduce-symlink.sh)。

## SEC-02: minimatch の既知 DoS

根拠: `editors/vscode/package-lock.json:39-49,75-84`。依存経路は `vscode-languageclient@10.1.1 -> minimatch@10.2.6`。

2026-11-06 の `npm audit --package-lock-only --ignore-scripts --json` は [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) を検出した。アドバイザリは `>=7.0.0 <11.0.1` を対象とし、修正版を11.0.1としている。攻撃者が glob パターンを供給でき、`optimizationLevel >= 2` の処理に到達する場合の CPU・メモリ消費増幅である。

npm の moderate 2件は、この1件のアドバイザリを minimatch 本体と親の vscode-languageclient に報告したもの。独立した脆弱性2件とは数えない。この拡張から攻撃者制御のパターンが該当する最適化処理に到達するかは未確認であり、拡張を開くだけで悪用可能とは結論しない。

対処: 修正版 minimatch を利用する languageclient の互換更新を検討する。現行の依存制約 `^10.2.6` は11系を許容しない。override を使う場合は、Node / VS Code の実行環境と languageclient の glob 利用箇所の互換性を検証する。npm が提案した languageclient 9.0.1 へのメジャーダウングレードを、検証なしに適用しない。

修正後の確認: ロックファイルで修正版への解決を確認し、監査を再実行する。LSP の起動、診断、整形、ファイル監視の回帰も確認する。

## SEC-03: コンパイル用一時ディレクトリの保護不足

根拠: `packages/peg-cli/app/Command/Parse.hs:158-185`。

作業パスを `getTemporaryDirectory` と単調増加時刻から作り、`createDirectoryIfMissing True` で作成する。既存パスの拒否や所有者・権限の検証はなく、0700 の専用ディレクトリを原子的に確保する処理もない。ソースを書いた後、その場所のファイルを GHC に渡す。

共有 `/tmp` と umask 022 などの構成では、生成ソースを他ユーザーに読まれる可能性がある。また、別ユーザーが予測したパスを先に作成する、あるいはリンクを配置することに成功すると、ファイル書込みやコンパイル対象を誘導する可能性がある。ナノ秒時刻の予測と競合勝利が必要な攻撃経路は未再現であり、任意コード実行成功を確認したわけではない。ユーザー専用の非公開 TMPDIR では他ユーザーからの経路は大きく制限される。

対処: `withSystemTempDirectory` 等で衝突時に既存ディレクトリを再利用しない、所有者専用の一時領域を確保する。例外時も後始末する。キャッシュも所有者のみが書き込めることを運用上の前提とする。

修正後の確認: 共有一時ルートと umask 022 の環境で、生成ディレクトリの権限が0700であること、事前作成したリンク・既存パスを再利用しないこと、コンパイル失敗時に後始末されることを検証する。

## SEC-04: LSP フレームのサイズ制限がない

根拠: `packages/peg-lsp/src/Peg/Lsp/Rpc.hs:29-50`、`packages/peg-lsp/src/Peg/Lsp.hs:43-62`。

ヘッダー終端が未到着の場合や宣言した本文長に達しない場合、`decodeFrames` は入力全体を未処理バッファとして返す。`runServer` は次の最大65536バイトのチャンクと連結して再解析する。ヘッダー長・本文長・保留バイト数の上限はない。長い未完了ヘッダーは繰り返し走査・コピーも引き起こす。

悪意ある、または故障したクライアントは長い未完了メッセージを送り続け、メモリ・CPUを消費させられる。巨大な Content-Length の数値を送るだけでその全量が即座に確保される、と主張するものではない。標準入力へアクセスできるクライアントが必要で、通常のローカル LSP 接続では影響範囲が小さいため低リスクとした。

対処: ヘッダー長、本文長、未完了バッファ長に上限を設け、超過時は診断して接続を終了する。数値は通常の大きな文書を扱える範囲で決める。修正後はヘッダー分割・本文分割の正常ケースと上限境界、上限超過をテストする。

## 防御として確認できた点と追加改善

- CLI は `proc cmd args` で子プロセスを起動しており、利用者の文字列をシェルコマンドへ直接連結していない。
- runtime の `many` は入力位置の前進を確認する。テンプレート展開には深さ64、引数サイズ10000の制限がある。ただし、総インスタンス数や全体の時間・メモリを保証する制限ではない。
- UTF-8 の妥当性確認と LSP の負の Content-Length 拒否がある。手書き tree-sitter scanner は外部入力を独自の固定長配列へコピーしていない。
- CI の既定権限は `contents: read`、checkout は `persist-credentials: false`。release の公開ジョブだけが `contents: write` を持つ。
- Actions はタグ参照で、リリースの ghcup bootstrap は取得したスクリプトを実行する。供給元侵害時の影響を減らすため、Actions のコミット SHA 固定と bootstrap の検証・固定を検討する。侵害が発生しているという指摘ではない。
- `parse` のヘルプ・利用案内に、文法が利用者の権限で動くコードであることを明記する。信頼できない文法を扱う用途では、コンパイル・実行双方をファイル権限、ネットワーク、時間・メモリ制限のある環境に隔離する。
- VS Code 拡張は `peg-hs.path` を実行コマンドとして使用する。Workspace Trust と設定スコープの方針を明記する改善余地がある。今回、Restricted Mode を迂回した実行は検証しておらず、確定した脆弱性には数えない。
