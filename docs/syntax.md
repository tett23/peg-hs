# .peg 記法

peg-hs の文法定義ファイル（`.peg`）の書き方を、例を中心に解説する。
規範は各 ADR にあり、この文書はそれを利用者の側から読める形にまとめたものである。
記述が ADR と食い違う場合は ADR が優先する。

この文書は、採択済みの ADR の内容だけを反映する。
反映している ADR は [0001](adr/0001-bounded-left-recursion.md)、[0003](adr/0003-typed-semantic-actions.md)、[0004](adr/0004-peg-notation.md)、[0005](adr/0005-error-reporting.md)、[0006](adr/0006-memoization-control.md)、[0008](adr/0008-source-positions.md)、[0012](adr/0012-context-sensitive-extensions.md)、[0014](adr/0014-generated-module-api.md)、[0015](adr/0015-implementation-deviations.md)、[0016](adr/0016-language-extensions.md)、[0017](adr/0017-nomemo-implementation.md)、[0019](adr/0019-lossless-syntax-tree.md)、[0020](adr/0020-unicode-identifiers-self-hosted.md)、[0021](adr/0021-error-recovery.md)、[0026](adr/0026-discard-unused-values.md)、[0028](adr/0028-label-safety-check.md)、[0030](adr/0030-unit-values-are-not-counted.md)、[0031](adr/0031-rule-templates.md)、[0038](adr/0038-label-check-precision-and-strip-labels-entries.md) である。

## 最小の例

加算だけを持つ式の文法から始める。

```
%module Example.Sum

%{
import Data.Text (unpack)
}%

# 左結合の加算
Sum :: Int
Sum <- l:Sum '+' r:Num { l + r }
     / Num

Num :: Int
Num <- ds:$[0-9]+ { read (unpack ds) }
```

この文法から生成されるモジュール `Example.Sum` は、入口 `parse :: Text -> Either ParseError Int` を公開する。
`parse "1+2+3"` は `Right 6` を返す。
`Sum` は左再帰の規則であり、`1+2+3` は `(1+2)+3` の順に組み立てられる。

## ファイルの構造

ファイルは、ディレクティブと verbatim ブロックの並びに、規則の並びが続く形をとる。

### ディレクティブ

| ディレクティブ | 意味 | ADR |
|---|---|---|
| `%module A.B.C` | 生成するモジュールの名前。必須 | 0004 |
| `%start Name` | 開始規則。省略すると、最初に定義した規則が開始規則になる | 0004 |
| `%entry Name` | 開始規則以外の規則にも入口 `parseName` を生成する。同じ規則を二度書くとエラー | 0014、0038 |
| `%export 項目, ...` | verbatim ブロックで定義した名前を生成モジュールから公開する | 0014 |
| `%env 型` | 解析全体で不変な環境の型を宣言する | 0012 |
| `%tabstop N` | `_col` の計算で、タブを N の倍数の桁まで進める | 0012 |
| `%language 拡張, ...` | 生成モジュールで言語拡張を有効にする | 0016 |
| `%nomemo Name` | 規則のメモ化を外す。左再帰に関与する規則には指定できない | 0006、0017 |
| `%syntax` | ロスレスな構文木を返す入口も生成する | 0019 |
| `%token Name` | 構文木で、規則の一致を一つのトークンにする | 0019 |
| `%trivia Name` | `%token` の規則を、空白やコメントのようなトリビアとして扱う | 0019 |
| `%inline Name` | 構文木で、規則の呼び出しをノードにせず子を呼び出し元に並べる | 0019 |
| `%recover label Name` | ラベル `label` の回復の規則を `Name` とする | 0021 |
| `%safe label` | ラベル `label` の安全性の検査の警告を止める | 0028 |

### verbatim ブロック

`%{` と `}%` で囲んだ部分は、生成モジュールに Haskell のコードとして丸写しされる。
import、構文木の型、アクションから呼ぶ補助関数をここに書く。
複数のブロックを書いた場合は、出現順に連結される。

```
%{
import qualified Data.Text as T

digitValue :: Char -> Int
digitValue c = fromEnum c - fromEnum '0'
}%
```

verbatim ブロックでは、`peg'` と `Peg'` で始まる名前の定義と、`PegRt` と `PegPrelude` を import の別名に使うことが禁じられている。
どれも生成器が内部で使う名前である。

生成モジュールは Prelude を `PegPrelude` として qualified に import する。
verbatim ブロックが Prelude を import していなければ、生成器は通常の `import Prelude` も補うので、アクションからは普段どおり Prelude の名前を使える。
verbatim ブロックで `import Prelude ()` のように Prelude を隠しても、生成コードは影響を受けない。

verbatim ブロックはモジュールの先頭より後ろに置かれるため、`{-# LANGUAGE OverloadedStrings #-}` のような言語拡張のプラグマを書いても効かない。
言語拡張は `%language` ディレクティブで有効にする（[ADR 0016](adr/0016-language-extensions.md)）。

```
%module Example.Words
%language OverloadedStrings, LambdaCase
```

生成器は、書いた順のままプラグマを生成モジュールの先頭に置く。
生成コードの `do` 記法の意味を変える `RebindableSyntax` は指定できない。
`NoImplicitPrelude` を指定した文法では、生成器は `import Prelude` を補わない。

### コメント

`#` から行末までがコメントになる。
リテラル、文字クラス、アクションの内側の `#` はコメントにならない。

```
# この行はコメント
Hash :: ()
Hash <- '#' { () }    # リテラルの '#' はコメントではない
```

## 規則

規則は、型注釈と定義の組で書く。
型注釈のない規則はエラーになる。

```
Name :: 型
Name <- 選択肢 / 選択肢 / ...
```

規則名と束縛名には Unicode の文字を使える（[ADR 0020](adr/0020-unicode-identifiers-self-hosted.md)）。
先頭は英字か `_`、二文字目以降は英数字、`_`、`'` である。
英字の判定は Haskell の `Data.Char.isAlpha` に従うので、漢字や仮名も英字として扱われる。

```
数式 :: Int
数式 <- 左:数式 '＋' 右:数 { 左 + 右 }
      / 数
```

型注釈の `::` の右側は、行末までを Haskell の型として扱う。
`[Int]` や `Maybe (Text, Int)` のような型もそのまま書ける。

## 式

### 終端

- **リテラル**：`'abc'` と `"abc"` のどちらでも書ける
- **文字クラス**：`[a-z0-9_]` の形。否定の文字クラス `[^...]` は使えないので、`![a-z] .` のように否定先読みと `.` で書く
- **任意の一文字**：`.` は Unicode のコードポイント一つに一致する

リテラルと文字クラスでは、次のエスケープを使える。

```
\n \t \r \\ \' \" \] \[ \- \u{XXXX}
```

### 演算子

結合の強い順に並べる。

| 種類 | 記法 | 意味 |
|---|---|---|
| 接尾辞 | `e*` `e+` `e?` | 0 回以上、1 回以上、省略可能 |
| 失敗ラベル | `e ^label` | `e` が失敗したらラベルを送出する（[ADR 0021](adr/0021-error-recovery.md)） |
| 接頭辞 | `&e` `!e` `$e` | 肯定先読み、否定先読み、テキストキャプチャ |
| 逐次 | `e1 e2` | 左から順に照合する |
| 選択 | `e1 / e2` | 左の選択肢から順に試し、最初に成功したものを採る |

接尾辞は接頭辞より強く結合する。
`$[0-9]+` は `$([0-9]+)` と読む。

## 値と束縛

### 値を持つ式

アクションから参照できるのは、値を持つ式だけである。

| 式 | 値の型 |
|---|---|
| 非終端 `Name`、規則の呼び出し `Name(引数)` | その規則の型 |
| テキストキャプチャ `$e` | 消費した入力の `Text` |
| `e*` `e+` | `e` の値の型のリスト |
| `e?` | `e` の値の型の `Maybe` |

リテラル、文字クラス、`.`、先読み、意味述語は値を持たない。
文字クラスに一致した文字が欲しいときは、`$` で取る。

```
Ident :: Text
Ident <- s:$([a-z] [a-z0-9]*) { s }
```

括弧で囲んだグループは、内側の逐次が値をちょうど一つ持つときにその値を持ち、それ以外は値を持たない。

値を数えるとき、束縛しない `()` の値は数えない（[ADR 0030](adr/0030-unit-values-are-not-counted.md)）。
空白を読む規則のように型注釈が `()` の規則と、それに `*`、`+`、`?` を付けたものがこれにあたる。
そのため、空白の規則を挟んでもグループの値は一つのままである。

```
Sp :: ()
Sp <- [ \t]* { () }

ExpList :: [Exp]
ExpList <- e:Exp es:(',' Sp Exp)* { e : es }   # グループの値は Exp の値
```

`()` 以外の値を持つ要素が一つもない場合は、`()` の値も数える。
`Spaces <- Ws` のように `()` の規則をそのまま返す選択肢は書ける。
束縛した要素（`u:Sp`）は、`()` でも常に数える。
型注釈の判定は文字列で行うので、`type Unit = ()` のような別名は `()` とみなされない。

アクションを省略した選択肢の値の数え方も同じである。
グループの値が使われる位置（束縛した要素や、アクションを省略した選択肢の値になる要素）では、どの選択肢の値も同じ型でなければならない。

グループの値が使われない位置では、選択肢の値の型が違ってもよい（[ADR 0026](adr/0026-discard-unused-values.md)）。
値が使われない位置は、テキストキャプチャ `$e` の中、先読み `&e` と `!e` の中、アクションを書いた選択肢の束縛しない要素である。

```
# Num は Int、Name は Text だが、キャプチャの中なのでグループの値は使われない
Word :: Text
Word <- w:$(Num / Name) { w }
```

### 束縛

`名前:式` の形で、式の値に名前を付ける。
名前は Haskell の小文字の識別子である。

```
Pair :: (Int, Int)
Pair <- '(' a:Num ',' b:Num ')' { (a, b) }
```

束縛には次の制約がある。

- 選択肢の逐次の直下にだけ書ける。括弧の内側の束縛は外から見えない
- 値を持たない式には付けられない（`c:[a-z]` はエラー。`c:$[a-z]` と書く）
- 一つの選択肢の中で同じ名前を二度使えない
- アンダースコアで始まる名前は使えない。生成器の予約である

深い位置の値が欲しい場合は、規則を分けて束縛する。

### 予約束縛

生成器は、次の名前を自動で束縛する。

| 名前 | 値 | 使える場所 | ADR |
|---|---|---|---|
| `_span` | その選択肢が消費した入力の範囲（`Span`） | アクション | 0008 |
| `_env` | `%env` で宣言した環境の値 | アクション、意味述語、規則の引数 | 0012 |
| `_col` | 評価している位置の桁（0 始まり） | 意味述語、規則の引数 | 0012 |

## アクション

選択肢の末尾に `{ Haskell の式 }` を書くと、その選択肢の値になる。
式の型は規則の型注釈と一致しなければならない。
アクションは純粋な式でなければならない。左再帰の解析では、同じアクションが複数回評価されることがある。

```
Signed :: Int
Signed <- '-' n:Num { negate n }
        / n:Num     { n }
```

アクションに型の誤りがあると、GHC はそのエラーを生成されたファイルではなく `.peg` ファイルの行と桁で報告する（[ADR 0014](adr/0014-generated-module-api.md)）。

### アクションの省略

値を持つ要素がちょうど一つの選択肢は、アクションを省略できる。
その要素の値がそのまま選択肢の値になる。
上の `Signed` の二つめの選択肢は、次のように書いてもよい。

```
Signed :: Int
Signed <- '-' n:Num { negate n }
        / Num
```

値を持つ要素が 0 個、または 2 個以上の選択肢でアクションを省略すると、エラーになる。

```
# エラー：値を持つ要素が 0 個
Unit :: ()
Unit <- 'unit'
```

```
# 正しい
Unit :: ()
Unit <- 'unit' { () }
```

### 位置を持つ構文木

アクションの中では、`_span` で選択肢が消費した入力の範囲を参照できる。
`Span` は開始と終了の位置を持ち、位置はバイトオフセット、行、桁からなる。
構文木のノードに位置を持たせるときに使う。

```
%module Example.Located
%export Expr(..)

%{
import Peg.Runtime (Span)  -- モジュール名は peg-runtime の実装時に確定する

data Expr = Lit Span Int | Add Span Expr Expr
}%

Expr :: Expr
Expr <- l:Expr '+' r:Lit { Add _span l r }
      / Lit

Lit :: Expr
Lit <- n:Num { Lit _span n }
```

構文木の型 `Expr` を利用者のコードから使うため、`%export` で公開している。
先読みは入力を消費しないので、`_span` の範囲を動かさない。

## 規則の雛形

規則名の直後の山括弧に式の引数を書くと、規則の雛形になる（[ADR 0031](adr/0031-rule-templates.md)）。
雛形の本体では、引数を非終端のように書く。

```
# 予約語：リテラルの後に識別子の文字が続かず、空白を読む
K<w> :: ()
K<w> <- w ![a-zA-Z0-9_] Sp { () }

# 区切りのある一つ以上の列
List<p :: a, sep> :: [a]
List<p, sep> <- x:p xs:(sep Sp p)* { x : xs }
```

呼び出しは、規則名の直後の山括弧に引数の式を書く。

```
While :: Stat
While <- K<'while'> c:Exp K<'do'> b:Block K<'end'> { SWhile c b }

ExpList :: [Exp]
ExpList <- List<Exp, ','>
```

- 規則名と `<` の間に空白を置かない。`<-` はこれまでどおり定義の矢印である
- 引数には選択や逐次を含む任意の式を書ける。カンマや `>` を含む式は括弧で囲む
- 値を使う引数は、型注釈で `p :: a` の形の型変数を宣言する。呼び出しごとに、型変数は引数の型に置き換わる。型を宣言した引数には、規則の呼び出し、テキストキャプチャ、雛形の呼び出しのように型の分かる式だけを渡せる
- 型を宣言しない引数は、本体の中で値を持たないものとして扱う
- 生成器は、雛形の呼び出しを引数の組ごとの規則に展開する。展開した規則は、それぞれがメモ表を持ち、左再帰の解析も展開した後の規則に対して行う
- 雛形は引数付き規則の引数を取れない。`%entry`、`%start`、`%recover` の規則にはできない
- `%syntax` の文法では、雛形の呼び出しはノードを作らず、子を呼び出し元に並べる

## 左再帰

規則は自分自身を左端で呼べる（[ADR 0001](adr/0001-bounded-left-recursion.md)）。
直接の左再帰は左結合の構文木を作る。

```
Sub :: Int
Sub <- l:Sub '-' r:Num { l - r }
     / Num
```

`10-3-2` は `(10-3)-2` すなわち `5` になる。
右結合にしたい場合は、右再帰で書く。

```
Pow :: Int
Pow <- b:Num '^' e:Pow { b ^ e }
     / Num
```

複数の規則を経由する間接の左再帰も書ける。
演算子の優先順位は、規則の階層で表す。

```
Expr :: Int
Expr <- l:Expr '+' r:Term { l + r }
      / l:Expr '-' r:Term { l - r }
      / Term

Term :: Int
Term <- l:Term '*' r:Factor { l * r }
      / Factor

Factor :: Int
Factor <- '(' e:Expr ')' { e }
        / Num
```

## 文脈に依存する構文

標準の PEG は、いまの位置から先の入力だけを見て照合を決める。
字下げで構造が決まる言語や、文書の別の場所の定義で解釈が変わる言語は、それだけでは書けない。
次の四つの拡張は、そうした構文のためにある（[ADR 0012](adr/0012-context-sensitive-extensions.md)）。

どの拡張も、規則の結果が「規則、引数、位置の組と、解析環境」だけで決まるように設計されている。
そのため、メモ化と左再帰の解析の正しさを損なわない。
解析中に書き換えられる状態は用意していない。

### 意味述語

`&{ 式 }` は、Haskell の真偽式が真のときに、入力を消費せずに成功する。
`!{ 式 }` は偽のときに成功する。

```
Byte :: Int
Byte <- n:Num &{ n < 256 } { n }
```

式が参照できるのは、同じ選択肢の中で述語より左にある束縛、規則の引数、`_env`、`_col` である。
意味述語の失敗は、エラーの期待一覧に項目を加えない。

### 引数付き規則

規則は引数を取れる。
型注釈で引数の名前と型を宣言し、呼び出しでは Haskell の式を渡す。

```
Indent(w :: Int) :: ()
Indent <- &{ _col >= w } { () }
        / ' ' Indent(w)
```

この規則は、桁が `w` に達するまで空白を読む。

- 規則名と `(` の間に空白を置かない。`A(x)` は呼び出し、`A (x)` は非終端 `A` と括弧グループの逐次である
- 引数を取らない規則を `A(x)` の形で呼ぶと、引数の個数の不一致としてエラーになる
- 引数の型は `Ord` のインスタンスでなければならない
- 引数付き規則は左再帰に使えない

### 解析環境

`%env` で、解析全体を通じて変わらない値の型を宣言できる。
宣言した文法の入口は、最初の引数に環境を取る。
規則の中からは `_env` で参照する。

```
%module Example.Link
%env Set Text

%{
import Data.Set (Set, member)
import Data.Text (Text)
}%

Link :: Text
Link <- '[' l:$[a-z]+ ']' &{ member l _env } { l }
```

この文法の入口は `parse :: Set Text -> Text -> Either ParseError Text` である。
`[foo]` は、環境の集合に `foo` が含まれるときだけ解析に成功する。

文書の後方にある定義を参照するような構文は、二回の解析で扱う。
一回目の解析で定義を集め、それを環境として二回目の解析に渡す。

### 桁の参照

`_col` は、評価している位置の桁を 0 から数えた値である。
コードポイント一つを 1 桁と数える。
`%tabstop 4` を宣言すると、タブは次の 4 の倍数の桁まで進むものとして数える。
宣言しなければ、タブも 1 桁である。

`_col` は照合の判断に使う値であり、エラーの位置の表示に使う桁（1 から数え、`%tabstop` の影響を受けない）とは別物である。

## 生成されるモジュール

### 入口

生成モジュールは、開始規則の入口 `parse` を公開する（[ADR 0014](adr/0014-generated-module-api.md)）。
`%entry` で指定した規則には、規則名を後ろに連結した入口が加わる。

```
%module Example.Calc
%entry Term

Expr :: Int
# ...

Term :: Int
# ...
```

この文法から生成されるモジュールは、次の二つを公開する。

```haskell
parse     :: Text -> Either ParseError Int   -- 開始規則 Expr
parseTerm :: Text -> Either ParseError Int
```

入口は入力の全体の消費を要求する。
規則が成功しても入力が残っていれば、解析は失敗する。

生成モジュールが公開するのは、入口と、`%export` に挙げた名前だけである。
規則の内部の実装は公開されない。

### 解析の失敗

解析に失敗すると、入口は `ParseError` を返す。
`ParseError` は、入力の中で最も遠くまで進んだ位置と、その位置で期待していた終端の一覧を持つ（[ADR 0005](adr/0005-error-reporting.md)）。
期待の一覧に入るのは、リテラル、文字クラス、任意の一文字、入力の終端である。
否定先読みと意味述語による失敗は、一覧に項目を加えない。

`renderParseError` は、失敗を人間向けの文字列にする。
上の `Expr` の文法に `1+*2` を与えると、3 桁目の `*` で失敗し、次のように表示される。

```
1:3: expected '(' or [0-9]
```

### 位置の数え方

エラーの位置と `_span` の位置は、次の規約で数える。

| 欄 | 数え方 |
|---|---|
| バイトオフセット | 入力の先頭を 0 とする UTF-8 のバイト数 |
| 行 | 1 から数える。LF で改行する。CRLF の CR は行末の一文字、単独の CR は改行にならない |
| 桁 | 1 から数える。コードポイント一つを 1 桁とし、タブも 1 桁 |

## メモ化を外す

既定では、すべての規則の結果は位置ごとにメモ表に記録され、同じ規則が同じ位置で二度評価されることはない。
空白や一文字の字句のように、同じ位置で二度呼ばれることがほとんどない規則は、`%nomemo` でメモ化を外すとメモリを減らせる（[ADR 0017](adr/0017-nomemo-implementation.md)）。

```
%nomemo Ws
%nomemo Hex
```

メモ化を外しても解析の結果と失敗の報告は変わらない。
ただし、深い後戻りの中で何度も呼ばれる規則のメモ化を外すと、解析時間が入力の長さに比例しなくなる。
外す前と後で、ベンチマークを比べること。
左再帰に関与する規則には指定できない。

## ロスレスな構文木

`%syntax` を書いた文法からは、型付きの値を返す入口に加えて、入力の文字列を一文字も失わない構文木を返す入口が生成される（[ADR 0019](adr/0019-lossless-syntax-tree.md)）。
空白やコメントを扱う lint や formatter のためのものである。

```
%module Example.Calc
%syntax
%token Num
%token Ws
%trivia Ws
%inline Sp

Expr :: Int
Expr <- l:Expr Sp '+' Sp r:Num { l + r }
      / Num

Num :: Int
Num <- ds:$[0-9]+ { read (unpack ds) }

Sp :: ()
Sp <- Ws? { () }

Ws :: ()
Ws <- [ \t]+ { () }
```

この文法から生成されるモジュールは、`parse` に加えて次の入口を公開する。

```haskell
parseSyntax :: Text -> Either ParseError SyntaxNode
```

構文木は次のように作られる。

- 規則の呼び出しは、規則名を種類とするノードになる。`%inline` の規則は、ノードを作らずに子を呼び出し元に並べる
- `%token` の規則の一致は、内部の構造を持たない一つのトークンになる
- それ以外の終端の一致は、同じノードの直下で連続するものが一つの無名のトークンにまとまる。`'<' '/'` は `</` という一つのトークンになるので、区別したい記号は `%token` の規則として書く
- 先読みと意味述語は木に何も加えない
- 構文木のテキストは、入力の文字列と常に一致する

構文木の入口では、アクションは評価されない。
ただし、意味述語や規則の引数が束縛の値を参照する場合は、その値を計算するためにアクションが評価される。

### 型付きの取り出し関数

`%token` と `%inline` 以外の規則ごとに、ノードを包む型と、束縛ごとの取り出し関数が生成される。
上の文法では次のようになる。

```haskell
newtype ExprSyntax = ExprSyntax SyntaxNode
castExprSyntax :: SyntaxNode -> Maybe ExprSyntax
exprL :: ExprSyntax -> Maybe ExprSyntax
exprR :: ExprSyntax -> Maybe SyntaxToken
```

取り出し関数の名前は、規則名の先頭を小文字にして束縛の名前の先頭を大文字にしてつないだものになる。
型の名前は規則名の先頭を大文字にしたものに `Syntax` を付けるので、漢字のように大文字と小文字の区別のない文字で始まる規則名は、`%syntax` の文法では Haskell の型名にならず、GHC のエラーになる。
束縛の名前の変更は公開 API の変更になる。
取り出し関数は、`%trivia` の種類のトークンを読み飛ばす。

このほか、規則ごとの種類の定数（`syntaxKindExpr` など）、種類の名前を返す `nameOfSyntaxKind`、トリビアの種類かどうかを返す `isTriviaSyntaxKind` が生成される。
構文木の移動と表示の関数は `Peg.Runtime.Syntax` にある。
`debugTree nameOfSyntaxKind` は、木を一要素一行の字下げで表した文字列にする。

## 構文エラーからの回復

`e ^label` は、`e` が失敗したときにラベル `label` を送出する（[ADR 0021](adr/0021-error-recovery.md)）。
送出は普通の失敗と違い、順序付き選択 `/` は次の選択肢を試さずに、そのまま外に伝える。
先読み（`&e`、`!e`）の中の送出だけは、普通の失敗として扱われる。

ラベルは、そこで失敗したらどの選択肢でも成功しえない位置にだけ付ける。
そうでない位置に付けると、後戻りすれば受理できた入力まで受理されなくなる。

```
%recover close CloseAtParagraphEnd

Command :: Inline
Command <- '[' name:Ident body:CommandBody (']' ^close) { Command name body }

# 何も読まない。段落の終わりで閉じたとみなす
CloseAtParagraphEnd :: ()
CloseAtParagraphEnd <- &(BlankLine / !.) { () }
```

### ラベルの安全性の検査

ラベルの位置が安全か（そこで送出しても、受理される入力が変わらないか）を、生成器が検査する（[ADR 0028](adr/0028-label-safety-check.md)）。
危険かもしれないラベルは警告として報告し、生成は続ける。

```
peg-hs gen Grammar.peg
Grammar.peg:3:11: warning: the label l may reject valid input: where it fails, the alternative at 3:28 can match
```

この例は、`S <- 'a' ('b' ^l) { () } / 'a' 'c' { () }` の `l` への警告である。
`ac` は二つめの選択肢で受理できるが、ラベルがあると一つめの選択肢の `'b'` で送出して止まる。

検査は入力の次の一文字を基本に判定する近似であり、安全なラベルに警告することがある。
次の三つは、一文字より先まで見て判定する（[ADR 0038](adr/0038-label-check-precision-and-strip-labels-entries.md)）。

- **規則の呼び出しを越えた共通の接頭辞**：失敗した選択肢がそれまでに読んだ要素と、後の選択肢が同じ要素で始まるなら、その部分を除いて比べる。後の選択肢の先頭の規則の呼び出し、グループ、繰り返しは、その中身に置き換えて比べる。引数のある規則は、仮引数を実引数に置き換えたうえで、引数の字句が一致する呼び出しを同じものとみなす（`B(n) <- Bad(n) / Orphan(n)` の `Bad` と `Orphan` がどちらも `Ind(n)` で始まる場合など）
- **定数の意味述語**：`&{ False }` と `!{ True }` は決して成功せず、`&{ True }` と `!{ False }` は必ず成功するものとして扱う
- **既知の接頭辞**：失敗した選択肢がリテラル（またはリテラルだけの選択肢からなる規則）で始まるなら、入力がその文字列で始まることを使い、後の選択肢がその入力で必ず失敗するかを確かめる（`'%%'` の後の `!'%%'`、`'[='` の後の `'[' Ident` など）

それでも、意味述語で文字を判定する規則（`c:$. &{ isAlpha c }` など）は、どの文字でも成功しうるものとして扱われるので、その規則で始まる選択肢が近くにあると警告が出やすい。
引数の値の大小（`Ind(n)` と `Ind(n + 2)` が読む空白の数の違いなど）も判定しない。
安全なことを確かめたラベルは、`%safe` で警告を止める。
理由はコメントに書く。

```
# [[ と [ は二文字目まで見れば区別できる
%safe table
```

`%safe` に書いたラベルが文法に現れなければ、エラーになる。
`peg-hs gen --Werror` は、警告があれば生成せずに失敗する。

### 二つのモード

ラベルを含む文法からは、回復しない入口と回復する入口の両方が生成される。

```haskell
parse        :: Text -> Either ParseError Inline            -- 回復しない
parseRecover :: Text -> (Maybe Inline, [SyntaxError])        -- 回復する
parseSyntaxRecover :: Text -> (SyntaxNode, [SyntaxError])    -- %syntax の文法だけ
```

回復しない入口は、最初の失敗で止まる。
送出されたラベルは `ParseError` の `parseErrorLabel` に入る。

回復する入口では、ラベルが送出されて `%recover` の回復の規則があれば、送出の位置から回復の規則を評価する。
回復の規則が成功すれば、ラベルを付けた式はその値で成功したものとして解析が続き、構文エラーが一つ記録される。
回復の規則がない、または回復の規則が失敗すれば、送出はさらに外に伝わる。

- 回復の規則は引数を取れない。型は、ラベルを付けた式の値の型と同じでなければならない。値を持たない式に付けたラベルでは、回復の規則の値は捨てられる
- 回復の規則が入力を消費しない場合（閉じ括弧を補うような挿入の回復）、構文エラーの範囲は空になる
- 後戻りで捨てた試行の中の構文エラーは報告されない
- 開始規則の後に入力が残れば、残りの全体が一つの構文エラーになる。開始規則が回復できなければ、入力の全体が一つの構文エラーになる

`parseSyntaxRecover` は、どの入力に対しても構文木を返す。
回復した範囲は種類が `ERROR` のノードになり、構文木のテキストは常に入力と一致する。

構文エラーは `SyntaxError` の列で返る。
ラベル、範囲（バイトオフセット）、範囲の始まりの位置、送出の時点の期待集合を持つ。
ラベルから利用者向けのメッセージへの対応は、利用者が持つ。
