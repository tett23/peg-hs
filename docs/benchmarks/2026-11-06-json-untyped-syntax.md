# 型注釈とアクションを書かない %syntax の JSON の文法の費用（2026-11-06）

[ADR 0068](../adr/0068-untyped-rules-in-syntax-grammars.md) の実装の後に、JSON の文法の四つの変種で、時間と最大の常駐メモリを測った。
型注釈もアクションも書かずに構文木を使う書き方は、`%syntax` のない型付きの文法に比べて、時間が約 1.60 倍、最大の常駐メモリが約 1.12 倍だった。
[ADR 0068](../adr/0068-untyped-rules-in-syntax-grammars.md) を書いたときの計測（時間が約 1.47 倍、メモリが約 1.12 倍）と比べると、メモリの比は同じで、時間の比はやや大きい。
`%syntax` の変種は時間のばらつきが大きく（後述）、この差はその幅に収まる。

この値は下記の環境での計測であり、他の環境の値とは比べられない。
退行の判定には使わない（[ADR 0007](../adr/0007-performance-discipline.md)）。

## 計測の環境

- 機械：Apple M1 Max、メモリ 64GB
- OS：macOS 27.0
- コンパイラ：GHC 9.10.3（`-O1`、cabal の既定）
- 入力：ベンチマークが生成する合成の JSON 文書（`conformance/bench-main/BenchMain.hs` の `syntheticJson`）、801,683 文字
- 文法：`conformance/json/Json.hpeg`、それに `%syntax`、`%token Ws`、`%trivia Ws` を加えた `conformance/bench/JsonSyntax.hpeg`、`JsonSyntax.hpeg` から型注釈、アクション、束縛を除いた `conformance/bench/JsonUntyped.hpeg`

## 解析時間

criterion の計測（`peg-bench --time-limit 15 json`、`conformance` のディレクトリで実行）。
表の「前回」の列は、[ADR 0068](../adr/0068-untyped-rules-in-syntax-grammars.md) を書いたときに同じ機械で測った値である。

| 文法と入口 | 時間 | 型付きの文法との比 | 前回 |
|---|---:|---:|---:|
| `%syntax` なし、型付きの値 | 646.0 ms | 1.00 | 636.5 ms |
| `%syntax` あり、型付きの値 | 1,180 ms | 1.83 | 1,229 ms |
| `%syntax` あり、構文木（アクションは評価しない） | 1,145 ms | 1.77 | 1,085 ms |
| `%syntax` あり、型注釈とアクションなし、構文木 | 1,032 ms | 1.60 | 936.6 ms |

型注釈とアクションを書かない変種は、構文木を作る三つの変種の中で最も速い。
`%syntax` を付けて型付きの値を返す変種より約 13%、型注釈とアクションを書いた文法の構文木の入口より約 10% 速い。
前回の計測では、前者との差は約 24% だった。

`%syntax` の変種の時間は、ガベージコレクションのためにばらつく。
criterion の信頼区間は、型付きの値の入口で 735.3 ms から 1.462 s、型注釈とアクションを書いた構文木の入口で 817.2 ms から 1.354 s、型注釈とアクションのない構文木の入口で 932.6 ms から 1.154 s だった。
`%syntax` のない文法の信頼区間は 633.2 ms から 669.3 ms で、狭い。

## 最大の常駐メモリ

変種ごとに別のプロセスで計測した（`peg-bench --memory VARIANT 10000`、VARIANT は `typed`、`syntax`、`syntax-tree`、`untyped-tree`）。

| 文法と入口 | 最大の常駐メモリ | 型付きの文法との比 | 前回 |
|---|---:|---:|---:|
| `%syntax` なし、型付きの値 | 264,740,432 バイト | 1.00 | 264,740,432 バイト |
| `%syntax` あり、型付きの値 | 297,103,608 バイト | 1.12 | 297,103,608 バイト |
| `%syntax` あり、構文木 | 297,102,872 バイト | 1.12 | 297,102,872 バイト |
| `%syntax` あり、型注釈とアクションなし、構文木 | 296,625,104 バイト | 1.12 | 296,789,336 バイト |

型注釈とアクションのない変種は、前回の計測より 164,232 バイト少ない。
計測のときの文法はキャプチャを書かず、いまの `JsonUntyped.hpeg` は `Number`、`Unit`、`Escape` でキャプチャを書く。
差の原因は文法の違いにあると考えられるが、どの規則の生成コードが割り当てを変えたかは確かめていない。

## 判断

時間の比は前回の計測（約 1.47 倍）より大きい約 1.60 倍になったが、`%syntax` の変種のばらつきの幅に収まり、[ADR 0068](../adr/0068-untyped-rules-in-syntax-grammars.md) の判断を変えるほどではない。
構文木を作るかどうかで費用が決まり、型注釈とアクションを書かない分はその中で最も安い、という順位も変わらなかった。
速さが要る利用者は、`%syntax` を付けず、型注釈とアクションを書く。
