# CI の時間（2026-10-13）

[ADR 0039](../adr/0039-faster-ci.md) のテスト設計に従い、CI を速くする変更の前後で、GitHub Actions の段ごとの時間を比べた。

すべてのキャッシュが当たる実行で、ワークフロー全体は約 8 分半から約 3 分 45 秒になった。
haskell のジョブは 507 秒から 220 秒になった。
内訳では、GHC の導入（105 秒から 11 秒）とビルド（88 秒から 6 秒）がほぼ消え、残りの大半はテストである。

テストの段は 233 秒から 133〜177 秒に縮んだが、ADR が目安にした「peg-grammar-test が最も長いスイートでなくなるか、100 秒以内に終わること」は満たさなかった。
peg-grammar-test は今も最も長く、111 秒と 150 秒だった。

この値は GitHub のホストするランナー（`ubuntu-latest`、x86-64、4 コア）での計測であり、実行ごとのばらつきが大きい。
同じ内容の二回の実行で、テストの段は 133 秒と 177 秒だった。
退行の判定には使わない（[ADR 0007](../adr/0007-performance-discipline.md)）。

## 計測した実行

| 列 | 実行 | コミット | キャッシュ |
|---|---|---|---|
| 変更前 | run 38316473868 | 7e0eb31（main） | 依存のストアだけ |
| キャッシュなし | run 38323063209 | a8167b0 | なし（依存のストアの場所が変わり、すべて外れた） |
| GHC 以外 | run 38330942328、一回目 | 60b9472 | 依存のストアとビルドの成果物 |

「キャッシュなし」の実行は、テストの段の後の修正（60b9472）より前のコミットである。
その修正はテストの補助のスクリプトの書き方だけを変えたので、段の時間の比較には影響しない。

この外れは、この変更のときに一度だけ起きる。

「GHC 以外」で GHC のキャッシュが当たらなかったのは、その前の実行が GHC のキャッシュを正しく保存できていなかったためである（次の節）。

## テストスイートの時間

テストの段の中で、各スイートが報告した時間である。
cabal はスイートを並列に動かすので、段の時間は最も長いスイートで決まる。

| スイート | 変更前 | GHC 以外 | すべて |
|---|---:|---:|---:|
| peg-grammar-test | 198 秒 | 111 秒 | 150 秒 |
| lua-conformance | 61 秒 | 64 秒 | 85 秒 |
| toml-conformance | 34 秒 | 36 秒 | 54 秒 |
| json-conformance | 35 秒 | 41 秒 | 49 秒 |
| peg-cli-test | 32 秒 | 19 秒 | 23 秒 |
| peg-lsp-test | 4 秒 | 5 秒 | 7 秒 |
| peg-codegen-test | 2 秒 | 2 秒 | 2 秒 |

peg-grammar-test は、手元（10 コア）では 147 秒（一つずつ）から 66 秒（並列）に縮んだ。
ランナーの 4 コアでは、ほかのスイートも同時に動き、それぞれが全コアを使おうとするので、手元ほどは縮まない。
並列にした分、ほかのスイート（Lua、TOML、JSON の適合性）はかえって遅くなった。

## ADR のテスト設計の結果

| 項目 | 結果 |
|---|---|
| 並列のテストの安定 | 手元で全スイートを 3 回続けて実行し、すべて通った。peg-grammar-test は `-j1` と並列の両方で通った。CI で一度、peg-cli-test が並列の実行の競合で失敗した（下の節）。直した後は通っている |
| テストを分けた後の網羅 | 分けた二つのテストは、どちらも文法ファイル 36 個に一つずつのテストになり、分ける前と同じ文法ファイルと変異を調べている |
| キャッシュのない実行 | 成功した。依存のストアのキャッシュが外れたため、変更前より遅かった（770 秒） |
| キャッシュのある実行 | GHC の導入は 11 秒で、目安の 30 秒以内だった。ビルドは 6 秒だった |
| テストの段の時間 | 233 秒から 133〜177 秒に縮んだ。peg-grammar-test は最も長いスイートのままで、100 秒以内にも収まらず、目安を満たさなかった |
| 文書だけの変更 | `docs/syntax.md` だけを変えた使い捨ての pull request（#3）で、ADR のワークフローだけが動いた |
| 古い実行を止める | 使い捨ての pull request（#2）に続けて push し、前の push の実行が取り消された。取り消しの完了までに 1 分ほどかかる |

## 実装の途中でわかったこと

GitHub のランナーの `~/.ghcup` は、root の持つ `/usr/local/.ghcup` へのリンクだった。
`~/.ghcup` をキャッシュすると、リンクそのもの（212 バイト）しか保存されなかった。
ghcup が入れる場所（`GHCUP_INSTALL_BASE_PREFIX`）を、ランナーのユーザーが持つ `/home/runner/toolchain` に変えた。
ADR は haskell-actions/setup を使い続けるとしていたが、入れる場所を確実に決めるため、ghcup を直接呼んでいる。

`cabal path --store-dir` は、設定ファイルがないとき、パスの前に注記の行を出力する。
そのまま段の出力に書くと形式の誤りになったので、最後の行だけを使っている。

テストを並列に動かしたことで、peg-cli-test の `peg-hs parse` のテストが、Linux でだけ `Text file busy` で失敗した。
各テストが ghc のラッパーのスクリプトを実行中に書き直しており、別のテストの子プロセスがそのファイルを書き込みのために開いたまま持っていたためである。
ラッパーはテストの開始前に一度だけ書くようにした。

## 残った課題

peg-grammar-test が、今もテストの段の時間を決めている。
最も長いテストは、文法ファイルごとに分けた後の記法の文法の変異のテストと、無作為な文法のプロパティテストである。
さらに縮めるには、スイートごとに使うコアの数を分けるか、テストスイートを別のジョブに分ける必要がある。
どちらも別の ADR で検討する。
