# JSON の文法の %syntax の費用（2026-10-11）

ADR 0019 のテスト設計に従い、`%syntax` を付けた文法と付けない文法で、型付きの値の入口の時間とメモリを比べた。
80 万文字の文書で、`%syntax` を付けると型付きの値の入口の時間は約 65% 増え、最大の常駐メモリは約 15% 増えた。
規則の評価が値と構文木の子の組を返すため、構文木を使わない場合にも組と子の記録の割り当てが生じる（ADR 0019 のトレードオフ）。

この値は下記の環境での計測であり、他の環境の値とは比べられない。
退行の判定には使わない（ADR 0007）。

## 計測の環境

- 機械：Apple M1 Max、メモリ 64GB
- OS：macOS 27.0
- コンパイラ：GHC 9.10.3（`-O1`、cabal の既定）
- 入力：ベンチマークが生成する合成の JSON 文書（`conformance/bench-main/BenchMain.hs` の `syntheticJson`）、801,683 文字
- 文法：`conformance/json/Json.peg` と、それに `%syntax`、`%token Ws`、`%trivia Ws` を加えた `conformance/bench/JsonSyntax.peg`

## 解析時間

criterion の計測（`cabal bench peg-conformance --benchmark-options='--time-limit 3 json'`）。

| 文法と入口 | 時間 |
|---|---:|
| `%syntax` なし、型付きの値 | 723.9 ms |
| `%syntax` あり、型付きの値 | 1,196 ms |
| `%syntax` あり、構文木 | 1,074 ms |

構文木の入口が型付きの値の入口より速いのは、構文木の入口ではアクションが評価されないためである。

## 最大の常駐メモリ

変種ごとに別のプロセスで計測した（`--memory VARIANT 10000`）。

| 文法と入口 | 最大の常駐メモリ |
|---|---:|
| `%syntax` なし、型付きの値 | 248,736,872 バイト |
| `%syntax` あり、型付きの値 | 285,183,440 バイト |
| `%syntax` あり、構文木 | 285,183,680 バイト |

## 判断

`%syntax` を付けない文法の生成コードは変わらないので、構文木を使わない利用者は費用を負わない。
構文木を使う文法でも型付きの値だけが要る場合は、`%syntax` を付けない文法を別に生成するほうが速い。
メモリの大半はメモ表が占めており、構文木の追加は 15% にとどまる。
メモ表の削減には `%nomemo`（ADR 0017）が効く。
