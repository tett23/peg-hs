# package のジョブを分けた後の CI の時間（2026-10-13）

[ADR 0046](../adr/0046-docs-cli-and-ci-before-v0-1-0.md) のテスト設計に従い、package のジョブを haddock と sdist の二つに分けた後の、GitHub Actions のジョブごとの時間を計測した。
比べる相手は、[ADR 0042](../adr/0042-shard-peg-grammar-test.md) の後の計測（[2026-10-13-ci-shard-grammar.md](2026-10-13-ci-shard-grammar.md)）である。

すべてのキャッシュが当たる実行で、ワークフロー全体は 2 分 4 秒から 2 分 58 秒に延びた。
haddock と sdist は並列に動き、どちらも通った。
延びたのは、sdist のジョブが、ソースのアーカイブからのビルドに加えてテストも動かすようになったためである。
このジョブは 174 秒かかり、ワークフローの時間を決めるジョブになった。
[ADR 0046](../adr/0046-docs-cli-and-ci-before-v0-1-0.md) のトレードオフは「並列のジョブなので、ワークフローの時間への影響は小さいと見込む」としていたが、この見込みは外れた。

この値は GitHub のホストするランナー（`ubuntu-latest`、x86-64、4 コア）での一回の計測であり、ばらつきがある。
退行の判定には使わない（[ADR 0007](../adr/0007-performance-discipline.md)）。

## haddock と sdist の内訳

各ジョブのテストの前の準備（キャッシュの復元、GHC の導入、依存の解決）は、約 35 秒だった。

| ジョブ | 段 | 時間 |
|---|---|---:|
| package（分ける前） | Haddock | 43 秒 |
| package（分ける前） | ソースのアーカイブからのビルド | 41 秒 |
| haddock | Haddock | 40 秒 |
| sdist | ソースのアーカイブからのビルドとテスト | 138 秒 |

sdist の段の 138 秒のうち、テストのスイートが報告した時間の合計は約 79 秒である。
このうち 65 秒は peg-grammar-test だった。
ソースのアーカイブでは、peg-grammar-test を分けずに一つのジョブで動かしている（[ADR 0042](../adr/0042-shard-peg-grammar-test.md) のシャーディングは、リポジトリのテストのジョブだけに掛けている）。
リポジトリの外のファイルを読む 29 件のテストは、`skipped:` と報告して飛ばした。

## ADR のテスト設計の結果

| 項目 | 結果 |
|---|---|
| haddock と sdist のジョブが並列に動き、どちらも通ること | 満たした |
| アーカイブから展開したパッケージのテストが通ること | 五つのスイートがすべて通った |
| 飛ばしたテストが報告されること | 29 件を報告した |

## 残った課題

ワークフローの時間は、sdist のジョブで決まっている。
縮めるには、ソースのアーカイブでの peg-grammar-test の重いプロパティテストの扱いを変える必要がある。
たとえば、アーカイブでも `--shard` で分けて複数のジョブで動かす、アーカイブでは事例の数を減らす、といった方法がある。
どちらも、アーカイブから何を確かめるかの決定を伴うので、別の ADR で検討する。
