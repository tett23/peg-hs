# 文法のインタプリタの解析時間（2026-11-09）

[ADR 0090](../adr/0090-grammar-interpreter-without-ghc.md) の実装の後に、JSON の文法で、インタプリタと生成したパーサーの解析の時間を測った。
同じ文法では、インタプリタは生成したパーサーの約 1.3 倍（平均の比）から 2.2 倍（時間の推定値の比）の時間がかかった。
この ADR は速さの目標を置かないので、この記録は今後の判断の材料である。

この値は下記の環境での計測であり、他の環境の値とは比べられない。
退行の判定には使わない（[ADR 0007](../adr/0007-performance-discipline.md)）。

## 計測の環境

- 機械：Apple M1 Max、メモリ 64GB
- OS：macOS 27.0
- コンパイラ：GHC 9.10.3（`-O1`、cabal の既定）
- 入力：ベンチマークが生成する合成の JSON 文書（`conformance/bench-main/BenchMain.hs` の `syntheticJson`）、801,683 文字
- 文法：`conformance/json/Json.hpeg` と、それに `%syntax`、`%token Ws`、`%trivia Ws` を加えた `conformance/bench/JsonSyntax.hpeg`

## 解析時間

criterion の計測（`peg-bench --time-limit 15 json`、`conformance` のディレクトリで実行）。
インタプリタは、文法に `%syntax` がなくても構文木を作る。
そのため、比べる相手は、生成したパーサーの構文木の入口（`parseSyntax`）である。

| 文法と道 | 時間 | 平均 | 信頼区間（時間） |
|---|---:|---:|---|
| `JsonSyntax.hpeg`、生成したパーサーの `parseSyntax` | 897.2 ms | 1.193 s | 754.8 ms から 1.121 s |
| `JsonSyntax.hpeg`、インタプリタ | 1.974 s | 1.564 s | 1.139 s から求まらず |
| `Json.hpeg`、インタプリタ（`%syntax` を加えた扱い） | 1.422 s | 1.474 s | 1.295 s から 1.499 s |
| `Json.hpeg`、生成したパーサーの `parse`（参考、値を作る） | 723.1 ms | 837.1 ms | 630.0 ms から 852.7 ms |

同じ文法 `JsonSyntax.hpeg` で比べると、インタプリタは生成したパーサーの約 2.2 倍（時間の推定値の比）、平均の比では約 1.3 倍だった。
二つとも、構文木を作る計測に共通するガベージコレクションのばらつきが大きく、インタプリタの信頼区間の上端は criterion が求められなかった。
`Json.hpeg` のインタプリタは、値を作る生成したパーサーの約 2.0 倍（時間の推定値の比）だった。
`Json.hpeg` には `%token` がないので、空白も規則のノードになり、`JsonSyntax.hpeg` とは木が異なる。

## コンパイルの待ち時間との比べ

[ADR 0090](../adr/0090-grammar-interpreter-without-ghc.md) の文脈の節の例（`E <- l:E '+' r:T / T`、`T <- [0-9]+`、入力 `1+2+3`）を、同じ機械の `peg-hs parse` で測った。
`PATH` の `ghc` は 9.14.1 で、キャッシュのディレクトリは空から始めた。
時間は、シェルからコマンドの開始と終了までを測った壁時計の時間である。

| 道 | 時間 |
|---|---:|
| `--format cst`、初回（コンパイルする） | 5.201 s |
| `--format cst`、二回目（キャッシュの実行ファイル） | 0.183 s |
| `--interpret`（3 回） | 0.033 s、0.038 s、0.035 s |

小さな文法と入力では、インタプリタはキャッシュの効いたコンパイルの道より速く、文法を書きかえた後の初回の待ち時間がない。

## 判断

大きな入力では、インタプリタは生成したパーサーより遅い。
文法を書きながら入力を試す用途では、コンパイルの待ち時間がなくなる利点のほうが大きい。
速さが要る利用者は、これまでどおり生成したモジュールを使う。
