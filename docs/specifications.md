# peg-hs 仕様書

peg-hs は、PEG（Parsing Expression Grammar）の定義から Haskell のパーサーを生成するツールチェーンである。
標準的な PEG の全構文に加えて左再帰を受理し、文法定義ファイルから Haskell ソースコードを生成する。
最初の利用者は組版システム Golem だが、peg-hs 自体は Golem に依存しない汎用ライブラリとして開発する。

この文書は peg-hs の能力、意図的に採用しなかったもの、設計原則、モジュール構成、開発順序を定める。
この文書には実装の詳細を書かない。
設計決定と実装ステップは `docs/adr/` に連番の ADR として置く。

## 目的

PEG は文法の合成性と無曖昧性という利点を持つ一方、素朴な実装では左再帰の文法が無限再帰に陥る。
左結合の演算子や左結合の後置構文（メソッド呼び出し、添字、フィールド参照）は左再帰で書くのが自然であり、この制限は文法を書く側に不自然な書き換えと結果の再結合を強いてきた。
peg-hs は左再帰を意味論のレベルでサポートし、文法を自然な形のまま書けるようにする。

パーサーは実行時にコンビネータで組み立てるのではなく、文法定義ファイルからソースコードとして生成する。
生成されたコードはリポジトリにコミットでき、レビューと版管理の対象になる。

パッケージは Hackage への公開を前提とし、PVP に従って版を刻む（ADR 0009）。
ライセンスは MIT とする。

## 能力

### 受理する文法

Ford が定義した標準 PEG の全構文を受理する。

- 逐次、順序付き選択 `/`
- 繰り返し `*` `+`、省略 `?`
- 先読み述語 `&` `!`
- 任意の一文字 `.`、リテラル、文字クラス
- 直接と間接の左再帰を含む規則

左再帰の意味論は Medeiros らの bounded left recursion に従う（ADR 0001）。
`E <- E '+' n / n` のような直接左再帰は左結合の構文木を生じ、複数の規則にまたがる間接左再帰も同じ機構で扱う。
nullable な式を前置した左再帰（隠れ左再帰）も同じ意味論の下で動作することを目標とし、テストで確認する。
成長ループの反復の終わりには、成長中の種に依存したメモ表の項目だけを捨てる。左再帰の規則が何段入れ子になっても、評価の回数は段の数と入力の長さに比例する範囲に収まる（ADR 0024）。

標準 PEG の外側の拡張として、次の四つを受理する（ADR 0012）。
どれも「規則の結果は、規則、引数、位置の組と、解析環境だけの関数である」という不変条件を保ち、メモ化と左再帰の成長ループの前提を壊さない。

- **意味述語** `&{ 式 }` `!{ 式 }`：左にある束縛などを参照する純粋な真偽式
- **引数付き規則** `Name(式)`：引数はメモ表の鍵に含まれる。左再帰への関与は禁止
- **解析環境** `%env 型`：解析全体で不変な値を入口から渡し、`_env` で参照する
- **桁の参照** `_col`：評価位置の桁。`%tabstop N` でタブの扱いを指定する

### 生成するコード

生成器は文法定義ファイル（`.peg`）を読み、単一の Haskell モジュールを出力する。

- 各規則はユーザーが指定した結果型を持ち、パーサーは中間表現を経由せずユーザーの AST を直接返す（ADR 0003）
- 生成コードは実行時ライブラリ peg-runtime の上で動く薄いコードとし、メモ表と左再帰の機構は実行時ライブラリが担う
- 同一の入力からバイト単位で同一の出力を生成する
- 生成モジュールは、開始規則の入口 `parse :: Text -> Either ParseError a` を公開する。入口は入力の全体の消費を要求する。エクスポート、名前の衛生、位置の規約、`.peg` の行番号への写像は ADR 0014 に定める
- `%language` で、生成モジュールの言語拡張を有効にできる。生成コードの意味を変える `RebindableSyntax` は拒否する（ADR 0016）
- `%nomemo` で、規則ごとにメモ化を外せる。左再帰に関与する規則には指定できない（ADR 0006、ADR 0017）

### ロスレスな構文木

`%syntax` を書いた文法では、型付きの値の入口に加えて、元の文字列を一文字も失わない構文木を返す入口を生成する（ADR 0019）。
構文木は rust-analyzer の rowan に倣い、共有可能な不変の木（green tree）と、親と絶対位置を計算する層（red tree）と、文法から生成する型付きの取り出し関数からなる。
規則の呼び出しがノードに、終端の一致がトークンになり、空白やコメントの規則も木に残る。
lint や formatter のように、空白とコメントを扱う用途のためのものである。

### 静的検査

生成器は文法を検査し、次の問題をコード生成前に報告する。

- 未定義の非終端の参照
- 開始規則から到達不能な規則
- nullable な式の繰り返し（`e*` で `e` が空文字列を受理する形。実行時の無限ループになるため拒否する）
- 左再帰規則の検出（該当規則にメモ化と成長ループを配線するために使う。ユーザーへの警告ではない）

ラベル（ADR 0021）の位置が安全か（送出しても受理される言語が変わらないか）も検査し、危険かもしれないラベルを警告する（ADR 0028）。
検査は入力の次の一文字による近似であり、安全と判定したラベルは安全だが、安全なラベルに警告することがある。
作者が確かめたラベルは `%safe` で警告を止める。

### エラー報告

失敗の表現はラベル付き失敗（labeled failures）の型を持つ。
失敗は最遠到達位置（farthest failure）とその位置の期待集合（失敗した終端の集合）を報告する（ADR 0005）。
位置情報はバイトオフセットと行と桁の両方を保持する。

### 構文エラーからの回復

文法の作者は、そこで失敗したら構文エラーである位置に `e ^label` を書き、ラベルごとに回復の規則を `%recover` で与える（ADR 0021）。
送出されたラベルは順序付き選択の後戻りを止める。
回復するモードの入口は、回復の規則で入力を同期の位置まで読み飛ばして解析を続け、構文エラーの列を返す。
`%syntax` の文法では、回復した範囲を誤りのノードとして含む構文木を、どの入力に対しても返す。
構文木のロスレス性は、エラーを含む入力でも成り立つ。
回復しないモードの入口は、これまでどおり最初の失敗で停止し、送出されたラベルを失敗に含める。

## 文法定義の記法

記法は Ford の PEG 表記を基礎に、型注釈とセマンティックアクションを加える。
確定した記法は ADR 0004 に定める。

```
%module Example.Parser

%{
import Data.Text (unpack)
}%

# 加算式
Expr :: Int
Expr <- l:Expr '+' r:Term { l + r }
      / Term

Term :: Int
Term <- ds:$[0-9]+ { read (unpack ds) }
```

規則は型注釈（`::`）と定義（`<-`）の組で書き、選択肢ごとにアクションをブレース内の Haskell 式として与える。
部分式の結果は `名前:` の束縛で参照し、消費した入力そのものは `$` キャプチャで `Text` として取る。
アクションでは暗黙の予約束縛 `_span` で選択肢の消費範囲を参照できる（ADR 0008）。
アクションを省略した選択肢は、値を持つ要素がちょうど一つのときその値をそのまま返す。
モジュール名は `%module` ディレクティブで宣言し、import と補助関数は `%{ ... }%` の verbatim ブロックに書く。
コメントは `#` から行末までとする。

## 意図的に採用しなかったもの

以下は検討の上で落とした。
それぞれの根拠は対応する ADR に記録する。

- **Warth らの seed-growing（OMeta 系）**：間接左再帰で結合性が壊れる既知の反例があり、正当性の根拠が弱い。形式意味論を持つ bounded left recursion を採る（ADR 0001）。
- **静的な左再帰除去**：文法変換で左再帰を消す方式は、構文木の形が変わるため再結合アクションの合成が必要になり、型付きアクションと両立しない（ADR 0001）。
- **Template Haskell quasiquoter**：v1 はスタンドアロン生成器のみ。生成コアを純関数として設計するため、TH フロントエンドは後から追加できる（ADR 0002）。
- **構文木だけを返すパーサー**：生成パーサーは型付きの AST を直接返す（ADR 0003）。ロスレスな構文木は、`%syntax` を書いた文法でだけ、もう一つの入口として加わる（ADR 0019）。
- **構文木の書き換え**：構文木は読むためのものとし、書き換えの API は作らない。formatter は構文木を読んで新しい文字列を作る（ADR 0019）。
- **可変な利用者状態**：Parsec 型の状態は、同じ規則と位置の評価が同じ結果を返すというメモ化の前提を壊す。解析中に変わらない解析環境と引数付き規則で代える（ADR 0012）。
- **アクション内の副作用**：セマンティックアクションは純粋な Haskell 式に限る。左再帰の成長ループはアクションを複数回実行しうるため、副作用があると意味論が壊れる。
- **インクリメンタルパースとストリーミングパース**：入力は全体をメモリに載せた `Text` とする。
- **自動のエラー回復**：同期の位置を生成器が自動で探す回復や、ラベルの自動挿入はしない。回復の位置は文法の作者がラベルと回復の規則で決める（ADR 0021）。
- **結合性と優先順位のアノテーション**：yacc 系の `%left` `%prec` は導入しない。左再帰が書けるため、結合性は文法の形で表現できる。

## 設計原則

**決定性**。
生成器は同一の入力からバイト単位で同一の出力を生成する。
生成コードにタイムスタンプや環境依存の情報を含めない。
利用者が生成物をコミットしたとき、差分は文法の変更とだけ対応する。

**広い型、狭い実装**。
将来の拡張が予見される箇所（失敗のラベル、メモ化の制御）は型を先に広く取り、v1 の実装は当面の用途に絞る。
未実装の機能に遭遇したらエラーで停止し、黙って無視しない。

**生成コアの純粋性**。
文法から Haskell ソースへの変換は純関数として実装し、CLI はその薄いラッパーとする。
この分離が TH フロントエンドの後付けとテストの容易さの両方を支える。

**自己記述**。
`.peg` 記法のパーサーは、記法を peg-hs 自身で書いた文法（`packages/peg-grammar/grammar/Peg.peg`）から生成したものである。
最初は手書きのパーサーで実装し、両者が同一の結果を返すことを確かめてから置き換えた（ADR 0027）。
誤りの文言は、自己記述の文法のラベル（ADR 0021）から作る。

## モジュール構成

```
packages/
  peg-runtime   -- 生成コードが依存する実行時ライブラリ
                --   入力表現、位置、失敗（ラベル付き）、メモ表、bounded LR の成長ループ
  peg-grammar   -- .peg 記法のパーサー（自己記述）、文法 AST、静的検査
  peg-codegen   -- 文法 AST から Haskell ソースへの純関数変換
  peg-cli       -- CLI ドライバ（ファイル入出力と診断表示のみ）
```

依存は `peg-cli → peg-codegen → peg-grammar → peg-runtime` の一方向とし、peg-runtime は他のどのパッケージにも依存しない。
peg-grammar が peg-runtime に依存するのは、自己記述の記法のパーサー（peg-hs 自身で生成したもの）を含むためである（ADR 0015）。
生成されたコードが依存するのは peg-runtime だけである。構文木の実行時の部分も peg-runtime に置く（ADR 0019）。

```
conformance/
  peg-conformance  -- 実在する言語の文法による適合性テスト（非公開）
```

peg-conformance は公開パッケージ群とは分けて置き、Hackage には公開しない。

## 適合性テスト

機構単位のテストに加えて、実在する言語の文法を peg-hs で書き、公開のテストスイートで検証する。
四つの言語は役割が異なる。

- **JSON**：生成器が実用文法を端から端まで処理できることの確認。全件の合格を要求し、その合格を非左再帰の生成器の完成の判定基準とする（ADR 0010）
- **CommonMark**：PEG の表現力の限界の測定。適合率と失敗の原因分類を記録して、記法の拡張を検討する根拠資料とする（ADR 0011）。拡張（ADR 0012）と論理桁の受け渡し（ADR 0018）によって全件の適合を目指す
- **Lua 5.5**：左再帰の実用の規模での検証。`prefixexp`、`var`、`functioncall` の間接の左再帰と 12 段の演算子の優先順位を、マニュアルの構文のまま書く。公式のテストスイートの全ファイルの受理に加え、参照実装から作った正解で構造（優先順位と結合性）と拒否を検査する（ADR 0022）
- **TOML 1.1.0**：構文の後の検査との分担と、エラーからの回復の検証。キーの重複や表の再定義は文法の後の組み立てで拒否し、拒否した段階を記録する。toml-test の全件で回復の全域性とロスレス性を検査する（ADR 0023）

CommonMark の適合率と失敗分類、Lua の文法の書き換えの記録と計測、TOML の拒否の段階の集計のスナップショットは `docs/conformance/` に置く。

## 開発順序

peg-runtime → peg-grammar → peg-codegen（左再帰なし）→ JSON の適合性テスト → ベンチマーク → 左再帰対応 → CommonMark の表現力測定 → 文脈依存の拡張と再測定 → 自己記述化、の順に進める。
段階と ADR の対応は ADR 0013 に定める。
その後に、言語拡張の指定（ADR 0016）、メモ化の選択（ADR 0017）、タブの部分消費（ADR 0018）、ロスレスな構文木（ADR 0019）を実装する。
エラーからの回復（ADR 0021）の後に、Lua（ADR 0022）と TOML（ADR 0023）の適合性テストを行う。二つは互いに独立である。Lua の前に、入れ子の左再帰の評価の回数の修正（ADR 0024）を行う。
自己記述のパーサーへの切り替えは、CommonMark の全件適合を含むすべての検査に合格した後に行った（ADR 0015、ADR 0027）。
ADR の連番は決定の順であり、実装の順ではない。

記法の利用者向けの解説は `docs/syntax.md` に置く。

左再帰を後置するのは、非左再帰のパックラットパーサーが先に実働していれば、成長ループの追加が「メモ表の初期値と更新規則の変更」として局所化できるためである。
最初から左再帰を組み込むと、バグが基礎機構のものか成長ループのものかを切り分けられない。
