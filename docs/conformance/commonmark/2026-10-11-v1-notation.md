# CommonMark の適合率：v1 の記法（2026-10-11）

[ADR 0011](../../adr/0011-commonmark-expressiveness-probe.md) の初回のスナップショットである。
[ADR 0012](../../adr/0012-context-sensitive-extensions.md) の拡張（意味述語、引数付き規則、解析環境、桁の参照）を使わずに書いた文法で、CommonMark 0.31.2 の 652 件の例を判定した。
結果は 652 件中 500 件の適合（76.7%）だった。

## 測定の条件

- 仕様：CommonMark 0.31.2（`conformance/data/commonmark-spec-0.31.2/spec.txt`）
- 文法：`conformance/commonmark/v1/Block.peg` と `conformance/commonmark/v1/Inline.peg`
- 判定：仕様の例の HTML との完全一致（`→` はタブに戻す）。手順は `conformance/test/CommonMarkMain.hs` の `--report-v1` で再現できる

v1 の記法で書ける技法（固定回数の列挙、アクションの中での判断）は使った。
たとえばコードスパンの区切りは長さ 1 から 3 までを列挙し、文字参照が既知かどうかはアクションで判断している。
書けない構文は、ファイルの冒頭に書いた近似で置き換えた。
引用とリスト項目は入れ子にできず、参照リンクは解決できない。

この測定は [ADR 0013](../../adr/0013-roadmap-toolchain-memo.md) の実装順序から外れている。
[ADR 0012](../../adr/0012-context-sensitive-extensions.md) の拡張は生成器の実装と同じ段階で実装したため、v1 の記法での測定は、拡張を使わない文法を別に書いて行った。

## 原因の割り当て

失敗の原因は、例ごとの調査ではなく次の規則で割り当てた。

1. 拡張を使った文法でも失敗する例は、`conformance/commonmark/failures.txt` に記録した原因とする
2. リンク参照定義を含む例は前方参照とする
3. 引用かリスト項目の記号で始まる行を含む例は字下げの状態とする
4. タブを含む例はタブの桁とする
5. それ以外は「その他」とする。v1 の近似（フェンスの長さの比較、字下げの幅の比較、自動リンクの長さの制限など）による失敗である

規則による割り当てなので、複数の原因を持つ例は最初に当てはまった原因にだけ数えている。
