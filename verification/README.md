# Lean による peg-hs の検証

[ADR 0097](../docs/adr/0097-verify-hpeg-and-generated-haskell-in-lean.md) の証明を、実装と照合できた範囲から追加している。
次の表で「モデル」とした性質については、Lean が検査した定理のほかに、Haskell の公開入口からそのモデルまでを結ぶ証明が必要になる。

| 不変条件 | Lean が検査する性質 | 実装との対応と残る課題 |
| --- | --- | --- |
| 1 | [Parsing.lean](Parsing.lean) の有限の式について、実行結果と帰納的な判定関係が同値。順序付き選択、先読み、ラベルの伝搬、真偽の述語、入力末尾を扱う。深さを一つずつ増やす前置演算子では 256 個まで深さ検査を通る。 | 非回復時のランタイムと制御演算の結果を比較する。意味述語の Haskell 式はモデルに真偽値を渡す前に評価されると仮定する。規則呼び出し、繰り返し、左再帰、メタ文法全体の導出、任意のテキストでの `parseTops` との同値は未証明。 |
| 2 | [Guard.lean](Guard.lean) のファイル名検査は、二つの名前のいずれかに U+0000 から U+001F または U+007F があるとき、かつそのときだけ検査の診断を返す。 | [check-guard.sh](check-guard.sh) が生成器の先頭の分岐と文字比較を読み取る。Haskell の `Char` の順序をコードポイント順に、有限リスト上の `any` を Lean のリスト探索に対応させる。この分岐を通過した後の宣言、import、テンプレート展開、規則検査の停止と拒否は未証明。 |
| 3 | [Header.lean](Header.lean) で、生成するモジュール名と `module` 行の構文を検査する。 | [check-header.sh](check-header.sh) が対応する Haskell の定義を照合する。対象はモジュール名を印字する行まで。エクスポート一覧、言語拡張、埋め込みコード、レイアウト、最終出力全体を GHC が構文解析できることは未証明。 |

ソースの照合スクリプトと、そこで使う Haskell の構文の読み取り方は信頼する前提である。
[Audit.lean](Audit.lean) は三つの証明モジュールの定理ごとに依存する公理を列挙し、Lean 標準の `propext`、`Classical.choice`、`Quot.sound` 以外の公理を使うと失敗する。

## 実行方法

リポジトリのルートで次のコマンドを実行する。
GHC と Cabal はプロジェクト指定の版を使う。
elan が [lean-toolchain](lean-toolchain) の Lean を選ぶ。

```sh
cabal build exe:peg-hs
verification/check.sh
```

対応テストでは、深さ 256 の前後で `parseTops` と Lean の結果を比較する。
空ファイル、末尾の余分な文字、未定義参照については実際の診断を確認する。
二つのメタ文法は実ファイルから再生成し、出力を GHC で検査する。
区切りが閉じたアクションに不完全な Haskell 式を入れたケースでは、GHC が構文エラーを返すことを確認する。
